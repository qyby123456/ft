# 故障机器人：充能球与技能联动

2026-09-17。沿用尖塔风格机器人的黄铜、旧铁和能量核心材质，不改掉落武器或其他 Boss 的资产。

## 模型

| 球种 | 轮廓 | 骨骼 / 方块 |
| --- | --- | --- |
| 玻璃 | 分片棱晶、黄铜支架、环形约束 | 9 / 43 |
| 雷电 | 六枚电极、折线闪电、外部电容环 | 11 / 50 |
| 冰霜 | 六向分叉冰晶、中心棱面、金属底环 | 11 / 46 |
| 离子 | 交叉双环、四枚磁极、粉色能量轴 | 9 / 44 |
| 黑暗 | 裂纹暗核、悬浮碎片、黄铜束缚环 | 11 / 45 |

每种球有 idle、summon、focus、dash、return、beam、drain、burst 八段动作。
贴图为 256×256 的逐面 UV 图集，另有 AutoGlowingGeoLayer 使用的 glowmask。
动画与模型使用新路径 `orb_link_<type>`；旧路径资产保留但不再被 ChargedOrbGeoModel 引用。
旋转遵循现有模型工具的 Bedrock X/Z 反号约定；预览只使用共享 `cube_space.cjs` 的完整骨骼链。

## 运行联动

- 成球：从施法位置沿弧线进入环绕槽，0.5 秒成形。
- 激发：服务器保留所选球实体，按球种时序移至施法位置；胸口核心变色，连线跟随真实手部骨骼。
- 结算时序：玻璃 11t、雷电 9t、冰霜 / 离子 6t、黑暗 16t。黑暗本体动作的推出帧校正到 0.8 秒。
- 玻璃 / 雷电保持原技能结算；冰霜 / 离子有回流环；非黑暗球吸收后用 6t 收拢动画结束。
- 黑暗球直接发射原实体，保留积累伤害；核心随同步蓄力值最多扩大 22%，不扩大碰撞箱。
- 光束：8 秒蓄力、3 秒引导数值不变；非冲刺球切换到输能队形，发射时环绕半径收紧；双手与胸口有能量桥。
- 被动供能、阶段突破、回想与集中碎片也有核心脉冲和输能连线；黑球不参与普通被动供能。
- 玩家拆掉已选球会取消该次激发；拆掉排队球则从队列移除；未成功释放的雷电球不计入电流相生。
- 队列最多 11 项，单颗成熟球只入队一次；黑暗发射体不再循环激发。消散球退出槽位统计后保留 6t 播完动画。
- 球种、主人、蓄力、状态通过实体同步；存档保留归属、槽位、寿命与伤害倍率，未完成的施法预约不跨存档恢复。
- 客户端距离上限 64 格，每帧最多 48 条球连线、12 个本体脉冲；按 UUID 区分多 Boss，卸载世界清除骨骼缓存。

## 工具流程

从源码工程根目录运行，OUTPUT 必须是源码资源目录之外的任务目录：

```text
node tools/model3d/defect_orbs_v2/build.cjs OUTPUT
node tools/model3d/defect_orbs_v2/install.cjs OUTPUT
node tools/model3d/defect_orbs_v2/verify.cjs OUTPUT
node tools/model3d/defect_orbs_v2/preview.cjs OUTPUT --frames
```

install 只复制 20 个球资源，并单独替换本体的 cast_dark 动画，不覆盖其他 16 段动作。
preview 生成实际 UV 模型图、机制分镜和八种动作的逐帧 PNG；分镜中球位与连线是机制示意，不是游戏截图。
测试覆盖 UV 不越界且不透明、发光层、骨骼引用、正缩放、循环首尾、几何尺寸和资源确定性。
Java 测试编译真正的 OrbLinkMath；队列测试从 DefectOrbs 提取生产方法，在轻量适配器中验证重复请求、容量、归属、已发射状态和拆球取消。
完整 Forge 构建还需通过 verifyResources、reobfJar 和 verifyJar；以上测试不替代游戏内实机验收。

## 实机检查

1. 召唤故障机器人，观察五种模型、第一次补球、槽位环绕及核心颜色。
2. 选球后拆掉发亮的球：该次技能不应继续，其他球应保持正常。
3. 黑球蓄力后应由同一颗球飞出，不应在胸口凭空生成第二颗。
4. 光束开始时检查球向核心输能、双手连线；结束后应进入原有虚弱流程。
5. 第二、三阶段确认 8 / 11 槽与回想、集中碎片的连线；多人及多 Boss 时不应串线。
6. 切换世界和重载存档确认无残留连线、无无主球永久悬浮。

部署必须用 `tools/deploy_jar.ps1 -NoBuild -ArtifactPath <已校验的 JAR>`。
检测到游戏正在运行时只保留成品，不覆盖正在使用的模组，不关闭用户游戏。
