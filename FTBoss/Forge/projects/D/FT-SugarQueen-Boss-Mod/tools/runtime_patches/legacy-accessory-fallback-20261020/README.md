# 旧版配件插入界面回退

## 范围

只调整石像中心两个界面入口，不扩大武器改装资格，不修改材料数值、物品注册 ID、网络包、配件账本或存档格式。

- 未接入新版构成的可改装物品：进入现有的三部件材料页，刷新旧版确认按钮，不发送新版开屏请求。
- 已接入新版构成的物品：继续走原有剑腔或四类基础结构容器。
- 正在等待事务响应时：两个入口均不改变当前页面，也不重复发送开屏请求。
- 新版开屏暂时失败不代表该武器应降级旧版；保持既有失败边界，避免向错误账本写入材料。
- 配件排除规则和服务端旧材料入口的拒绝规则不变。

openBuildAdjustment 统一委托 openSwordCavity。运行基线中此前定向加入的调整回调仍调用 Hub 本地的 usesCavity，但 JAR 中实际只有共享呈现类上的对应方法。本次委托同时移除这一不可解析引用，不重新编译或覆盖整个 Hub。

## 构建和保真

build.cjs 从冻结的真实 Hub 方法提取捐赠体，仅移植 openSwordCavity 和 openBuildAdjustment。枚举、字段、匿名回调、其他方法与其他 JAR 条目不得来自捐赠体。LegacyAccessoryPatch 比较全部条目和全部 Hub 方法，拒绝越界变化。

工作目录：D:/ft工程文件/FT-SugarQueen-Boss-Mod/_work/legacy-accessory-fallback-20261020。

初始基线为 baseline.jar。并行任务更新正式实例后，先在 predeploy-baseline.jar 上生成 deploy-candidate.jar；最终采用持锁流程冻结 locked-baseline.jar、生成 locked-candidate.jar，并在同一锁保护下运行精确成品客户端回归和部署。不使用旧基线整体覆盖新版本。最终成品只改变一个类中的两个方法，最新基线的其余全部条目内容完全一致。

## 验证入口

- node tools/verification/check_legacy_accessory_entry.cjs：执行真实源码提取的两个入口，72 种组合、432 项断言；覆盖新旧分流、等待状态、开屏成功/失败和选中材料保留。
- node tools/verification/check_accessory_ui_routing.cjs <输出目录>：既有资格分流与旧服务端入口回归。
- node tools/runtime_patches/legacy-accessory-fallback-20261020/prepare-probe.cjs final <最终成品路径>：生成私有测试实例，不改正式实例配置或存档。
- 私有客户端通过旧材料页普通左键处理器、正式网络包和服务端装配入口检查三部件装配；覆盖铁镐、铁锹、剪刀、铁剑、弓、弩及主副手。服务端检查材料消耗、同材和非法请求拒绝、无关 NBT 保留及重载后的部件。
- 新版物品继续打开新容器，旧材料入口拒绝改装且不消耗材料；两个入口的等待状态均有回归。
- deploy.ps1 仅在最终成品 12 项客户端场景全部通过、游戏退出、目标哈希一致并获得三个共享锁后调用公共部署脚本，随后读回 SHA256。

测试存档副本、玩家无敌/飞行与禁用 SDM Shop JEI 刷新监听器只用于隔离测试，不进入正式 JAR。第一次探针在两项旧版装配通过后因测试玩家在水中死亡而中断，记录保留；最终场景改到安全高空并保持生存模式的材料消耗规则。没有修改相关模组或正式玩家数据。
