# 庄园仪式演出重做

## 范围

开场、Boss 轮换与胜利使用统一的苹果红、深石蓝、香槟金、翠绿叶饰模型语言。所有部件均为代码定义的真实三维网格，不把平面贴花称作实体模型。不修改 Boss 数值、出场顺序、战斗判胜、道具掉落、成就及奖励内容；保留其他线程的法术模型与特效。

- 开场：46 秒，见 `MANOR_INTRO_FX.md`。
- Boss 轮换：在现有 60 tick 等待内凝聚拱门与下一位成员彩色徽章，最后 8 tick 开门，实际 Boss 生成时开始 30 tick 退场。替换原出场爆炸粒子和图腾粒子，保留原出场音效，不增加出场等待时间或无敌阶段。
- 胜利：120 tick，十一枚主战成员徽章（包含祁崽、不包含支援位麻雀）绕行汇聚，实体桂冠、苹果徽记与宝匣显现，之后由原账本发放真实战利品箱。模型宝匣只是演出，不承担库存或提前发奖；见 `MANOR_VICTORY.md`。

## 轮换链路

`ManorFight` 的死亡等待阶段调用 `ManorTransition.prepare`，仅窥视既有随机池、不提前消耗下一位；实际 `spawnVariant` 成功后调用 `arrive`，以真实变体及出生点校准。新 S2C `ManorTransitionPacket`（编号 6，协议 8）包含战斗 UUID、维度、坐标、变体、已过 tick 与取消标志。

服务端每秒补发当前状态，客户端补包不重播；存档恢复后的等待阶段按剩余时间加入，快速连杀可重启下一次换人演出。中止、失败、投降或胜利都通过真实 `endFight` 取消轮换；到时、登出、换维度、世界卸载本地清理。演出无伤害、不放方块、不生成 Boss 替身；不恢复已被删除的合体终章。

自然死亡轮换测试发现：仅依赖嵌套 `Ticker` 的自动订阅时，最后一个存活实体死亡后不再调用 `pumpAll`（连续 110 tick 的 `phase=0`、`lastPump=-1`），导致等待和演出均不开始。模组入口现显式注册 `ManorFight.Ticker.class`；保留原有每游戏 tick 去重，仍严格使用 60 tick 间隔。测试从真实实体死亡到下一实体生成进行观测，不在测试里手动推进战场。GameTest 采样在该帧 END 事件之前，故以真实下一实体出现为基准校验揭幕时刻，允许一个采样 tick 的相位差。
