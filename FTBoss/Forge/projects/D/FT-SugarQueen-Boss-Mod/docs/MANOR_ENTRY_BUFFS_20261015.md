# 庄园 Boss 进场前复制 Buff

已将增益复制提前到进场流程，复用运行版原有 `syncPlayerBuffs`，没有重写或替换复制策略。

## 执行顺序

1. 入场演出：设置 Boss 身份、难度、召唤者、坐标及演出状态 → 复制附近玩家 Buff → 加入世界。
2. 演出结束：46 秒演出完成 → 再复制一次最新玩家 Buff → 解除无敌和 AI 冻结 → 接入庄园战斗/麻雀支援。再次复制是为了避免 30 秒 Buff 在 46 秒演出期间过期。
3. 后续主战 Boss：设置身份与召唤者 → 绑定本场阶段与难度 → 复制 Buff → 启用 AI → 加入世界 → 公告、红圈和阶段演出。

没有符合条件的玩家或没有可复制 Buff 时，正常进场，不阻塞、不延后。战斗内每 15 秒复制仍然保留。

## 原样保留

- 原 48 格内最近存活玩家的选择方式，不扩大到整场所有玩家，也不引入额外过滤。
- 原正面效果复制、等级与显示标志，复制持续 30 秒，不消耗或修改玩家效果。
- 吸收、生命提升、修改最大生命的效果、`herbalbrews:renewal` 的原排除规则。
- 原 MaqueSupportHooks、连锁增益和麻雀特殊逻辑；没有静默替换成普通 `addEffect`。
- 原进场时长、模型、动画、柔光、伤害规则及之前的 Boss 红圈领域强化。

## 工程与部署

- 三个运行源码与变更日志已经同步主工程 `D:\ft工程文件\FT-SugarQueen-Boss-Mod`，修改前备份在 `source-before`。
- `PatchManorEntryBuffs.java` 是方法级增量工具，按写入当刻 JAR 合并，遇到本次相关方法被并发修改会停止；不会以旧整包覆盖其他任务成果。
- `build-test.ps1` 构建、生成候选并执行进场回归；`deploy.ps1` 使用三道协调锁、目标独占保护、完整备份、写入前后 SHA256 校验和异常回滚。
- 默认只部署当前 `FarmingTales_ForgeⅡ v1.5.2\mods\qys-bosses.jar`，不写桌面、fix2 或 NeoForge。运行中的客户端需要重启。
- 备份、安装哈希和时间以 `deployment.json` 为准；不可拿工具/fixtures 中的 class 整类覆盖运行 JAR。
