# 柠檬猫继承多重铁魔法

2026-09-19：继承期间单轮最多 `min(5, 2 + inheritedBossCount)` 个铁魔法。

| 实际继承 Boss 个数 | 单轮上限 |
|---|---|
| 0 | 2 |
| 1 | 3 |
| 2 | 4 |
| 3 及以上 | 5 |

## 计数与存档

- 计数来自本次成功献祭的 Boss 实体：女皇、屠夫、沙耶、酒桶王、鼠王。同种 Boss 的不同实体分别计数。
- 茶树小怪、小酒桶、迷你老鼠等随从不献祭，也不增加施法数量；之后新召唤的 Boss 不追加本次计数。当前先召两只不同助战 Boss，达标后优先一次性献祭，沿用公式得到单轮最多四个法术。
- `ftboss:lemon_sacrifice.bosses` 随实体 NBT 保存。旧存档没有实际实体数量，按已记录的有效 Boss 能力种类保守恢复，绝不拿含小怪的 sacrificed 总数冒充 Boss 数。
- 继承持续直到柠檬死亡/移除；失效后施法恢复原先的双施法，不重置献祭机会与后续单只召唤数量。

## 统一施法

- `LemonSpellBarrage` 统一选择自身三门法术、已继承 Boss 的专属法术和符合继承来源的原生铁魔法。
- 每轮选取不重复、启用、冷却完成且预检查通过的法术，最多占满当前上限；可用法术不足时按实际可用数量施法，不复制同一招凑数、不绕过冷却。
- 每个槽位持有独立 MagicData，批次采用本轮最长的有效咏唱；非持续法术同一 tick 释放，持续法术保留原生持续回调。
- 自身技能与继承专属的原有独立冷却、原生铁魔法的低频选择限制保留；统一批次结束后使用柠檬猫原有施法间隔。
- 旧继承专属单发调度与独立原生铁魔法调度不再额外启动，替换技能入口也进入同一批次，防止五重之外再叠第六、第七个法术。
- 目标丢失、换目标、距离/视线无效、无 AI、死亡、继承到期及世界卸载取消未释放的批次，所有已初始化法术执行结束回调。
- 保留本体近战、武器技能与继承的非施法能力，不新增法术/卷轴 ID，不修改其他 Boss 或柚子分身的施法规则。

运行 `gradle -I tools/verification/lemon_barrage_gametest.gradle build runGameTestServer`。
