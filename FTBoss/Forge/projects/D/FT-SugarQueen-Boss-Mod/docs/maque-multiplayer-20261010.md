# 麻雀：多人战斗登场次数与支援概率

## 行为

这里的“其他 Boss 的出现可能性增加”指麻雀在其他 Boss 场次出现的可能性增加，不增加敌方 Boss 的数量。

| 有效参战人数 | 每位 Boss / 场次的登场上限 | 独立 Boss 每轮判定概率 | 庄园原未选中场次的追加支援概率 |
| --- | --- | --- | --- |
| 1 | 1 次 | 50% | 0%，保持原计划 |
| 2 | 2 次 | 75% | 25% |
| 3 | 3 次 | 87.5% | 43.75% |
| 4 | 4 次 | 93.75% | 57.8125% |

- 每多一个有效参战者，每个 Boss 的登场额度增加一次。原庄园计划选中的场次仍然可以获得支援；原来未选中的场次有额外机会。
- 独立 Boss 每轮概率为 `1 - 0.5^人数`，继续沿用原 200 tick（10 秒）的检查入口。同一个 Boss 在同一轮只使用一个随机结果，遍历多个玩家不会反复抽签。
- 庄园额外场次概率为 `1 - 0.75^(人数 - 1)`。使用战斗 UUID 和 Boss 变体生成固定门槛；反复检查、读档或重复登记不会重新抽取，人数增加只会扩大可获支援的场次集合。
- 登场额度是上限，不保证在 Boss 被迅速击败前全部用完。额外额度用于上一只麻雀离场后的后续登场，不是同时召唤多只。
- 保留原有全局同时一只、登场保护、合法 Boss 与迷你体过滤、退休战斗过滤、实体生成与入世界成功检查。常规再次登场路径在成功生成后至少间隔 40 tick；已有麻雀仍在场时始终阻止第二只。
- IMPOSSIBLE 难度继续使用原来的专用常驻、预留席位和替换规则，不叠加本次普通模式的额度或概率。

## 有效参战人数

- 正式庄园从现有战斗存档的召唤者及参战者集合读取，不将围观玩家自动加进战斗。
- 独立 Boss 记录过去 1200 tick（60 秒）成功造成伤害的玩家，并纳入当前玩家攻击目标。每个 UUID 只算一次。
- 玩家必须在线、存活、未移除、处于同一维度，且不是创造或旁观模式。
- 玩家须在 Boss 48 格以内；正式庄园中，在战斗锚点 96 格以内的已登记参战者也可计入，避免 Boss 高速移动时人数反复跳变。
- 当前 Boss 场次记录有效参战人数的已观测峰值。离开、死亡或短暂掉线不收回本场已获得的额度，重新加入同一批玩家不再重复加次数；新场次单独统计。

## 存档与迁移

- 新服务端 SavedData 为 `ftboss_sparrow_multiplayer`，保存每个正式战斗与 Boss 场次的额度峰值、已用次数、已登记麻雀 UUID 和最近成功生成时间。
- 独立 Boss 使用 Boss UUID 隔离计数；不同 Boss、不同庄园战斗和不同场次不会共用额度。
- 原存档的已登场标记迁移为已使用 1 次，不清空原有历史。原来仍在场的那只麻雀再次被登记不会额外扣一次。
- 仅成功生成或首次确认在场的麻雀计数；工厂返回空、入世界取消、同一实体重复登记均不多扣额度。
- 正式战斗退休后定期清理其扩展记录；原 `ManorFightData` 的格式、单人随机计划和旧标记保持兼容。

- 正式目标只有当前 `FarmingTales_ForgeⅡ v1.5.2/mods/qys-bosses.jar`。使用统一部署锁、独占读取、当刻备份、JDK `jar --update`、部署前游戏检查与 SHA256 重核、同卷原子替换。
- 本次 5 个 class 增量保留了 2728 个无关条目，包括飞羽 8 秒冷却 / 5 秒禁疗与高速跑步。其他线程之后继续合并同一个包时，另行检查本次 5 个条目仍然一致，不用本次整包覆盖它们。
- 本次未改变模型、贴图、骨骼、人物动画、视觉特效或 renderer。部署时原有 1055 个非目录 `assets/` 条目全部逐项 SHA256 保持一致，四视图验收对本次纯服务端行为增量不适用。

- 1,202,189 条规则与计数断言；8,256 次原生 Minecraft NBT 保存 / 载入往返。
- 1–128 人额度、成功计数、重复 UUID 去重、旧存档迁移、场次隔离、重登不重置、退休清理、40 tick 间隔与固定概率的单调性通过。
- 32 种人数下隔离执行当前原始召唤方法的控制流，2,704 条断言、528 次顺序成功生成；覆盖全局唯一麻雀、生成失败、取消入世界、登场保护、额度耗尽与退休阻止。
- 直接执行编译后的参战人数方法，通过 144 条受控环境断言：两种战斗模式下 0–32 人、创造 / 旁观 / 死亡 / 移除 / 离线 / 围观过滤、攻击者与目标 UUID 去重、48 / 96 格边界、60 秒攻击记录保留及过期清理。
- 486 项当前运行包 API 引用及 JVM 字节码校验通过；移除本次限定钩子后完整共享类与原基线一致，15 个原方法与元数据保留。
- Forge ZIP 规则、本地头流式读取、CRC、部署前后条目范围和哈希校验通过。
- 以上是离线验收，控制流探针使用受控实体 / 世界替身，不等于启动了 Minecraft 或 Forge 世界。真实联机玩家登记、服务器加载、实际登场 / 离场时机、存档重进仍待实机验收。

## 实机验收建议

1. 关闭客户端后重启；联机时服务端和所有客户端都需使用合并后的模组包，不热替换运行中的 JAR。
2. 在普通庄园用 1 / 2 / 3 名生存玩家实际参与同一 Boss 战，等麻雀自然离场，确认分别不超过 1 / 2 / 3 次，且始终只在场一只。
3. 增加创造、旁观、场外围观与离线账号，确认不额外增加额度；中途加入新有效参战者时确认额度增加。
4. 麻雀登场后保存退出再进入，确认已用次数仍在；同一实体反复登记不会扣掉多次。
5. 原未选中的庄园 Boss 场次，在多人时可能获得支援但不是必定出现；独立 Boss 的频率提升也不是每轮强制生成。
6. 复查飞羽 5 秒禁疗、其他治疗 / 支援技能和 IMPOSSIBLE 常驻行为没有回退。
