# 模组架构总览

本页面向需要理解系统边界的新维护者。入口为 [文档总导航](README.md)，食物武器的详细协作关系见 [模块说明](architecture/FOOD_WEAPONS.md)。具体技能、数值和模型参数请按 [参考目录](REFERENCE_INDEX.md) 定位，再回到对应源码核对。部署材料与验证证据见 [交付与验证入口](REFERENCE_INDEX.md#正式交付与验证入口)。

## 模组解决什么问题

模组在 Minecraft Forge 1.20.1 中提供 Boss（首领敌人）战斗、庄园挑战、相关武器与石像交互。模组标识为 `ftboss`，交付物为 `qys-bosses.jar`。

战斗编排、实体行为、物品成长和客户端表现是相互协作的系统，不是同一个入口中的连续脚本。价格模组是独立工程，不属于这里的状态或权限范围；不能因为石像涉及交易就把价格系统并入本模组。

## 模块职责

下表中的目录均相对于 `src/main/java/net/farmingtales/ftboss/`。目录用来寻找职责入口，不承诺每个既有类都已完成理想分层。

| 模块 | 主要职责 | 协作边界与阅读入口 |
| --- | --- | --- |
| `FTBossMod.java` | 模组加载及公共注册接线 | 先理解注册关系，再核对事件类的实际订阅方式；不能假定所有功能都只从构造入口注册 |
| `boss/` | 战斗编排、庄园流程、入场与收尾、血条及全局事件 | 从 `BossHandler`、`ManorFight`、`BossBars` 开始，再进入相应首领脚本 |
| `boss/ai/` | 战术组件、战斗判定、效果约束、召唤物协作 | 与实体和编排层共同工作；伤害边界查 `BossDamageGate`，具体参数不在本文复制 |
| `entity/` | 实体本体、同步数据、保存与加载、移动和存活周期 | 类型登记查 `FTEntities`；再读具体实体以及它调用的战斗组件 |
| `item/`、`item/weapons/` | 物品登记、武器状态、成长规则和具体使用行为 | 食物武器从模块页进入；具体武器的命中与技能不要反向归入通用成长层 |
| `block/`、`menu/`、`network/`、`trade/` | 石像等方块、交互容器、网络请求及交易规则 | 容器和服务端逻辑确认实际操作，界面只负责交互；食物武器交互查 `StatueMenuNetwork` 与 `SwordCavityMenu` |
| `api/` | 剑体构筑与材料的扩展定义 | 阅读接口可理解接入边界，不能据此认定所有武器已发布适配 |
| `integ/`、`skill/`、`effect/` | 外部模组桥接、法术或技能执行、状态效果 | 铁魔法桥接可从 `WizardSummon` 进入；来源、目标与持续时间需沿实际执行路径核对 |
| `client/` | 客户端注册、界面、模型、渲染与表现状态 | 先查 `FTClientSetup`，再到 `client/model/` 和 `client/render/`；不能承担服务端结算权限 |
| `sound/` | 音效登记与战斗音乐协调 | `BossMusic` 接受战斗请求；`FTSounds` 和资源声明提供声音内容 |
| `balance/`、`butcherskills/`、`turret/`、`worldevent/`、`youzi/` | 平衡、屠夫技能、炮塔、世界事件和柚子相关领域模块 | 从调用它们的实体或玩法入口进入，不将这些目录视为统一战斗状态的所有者 |
| `mixin/` | 对游戏或依赖行为的定点注入 | Mixin 是在指定执行位置接入逻辑的机制；目录有源码不代表正式包已经应用，也不代表实际运行验证通过 |
| `util/` | 跨模块复用的规则、数学与几何辅助 | 不应成为新增事件监听器或战斗状态机的汇集点 |

## 状态与权限属于谁

服务端负责战斗推进、目标与伤害、奖励以及真实物品操作。客户端负责展示、输入和表现，不凭本地预览确认消耗、成长或掉落。

实体保存自身需要随实体存续的状态；战斗编排层另外维护挑战、入场、轮换与清理等运行状态。部分首领仍使用集中脚本维护战斗，不能假定全部状态都在实体对象里，也不能假定它们天然支持多实例。

武器自身的成长与构筑保存在物品的命名二进制标签中，简称 NBT，是 Minecraft 保存结构化状态的数据格式。原生磨损另有服务器世界中的权威记录，负责已结算阶段和修复任务的实际交付。界面中的临时选项和客户端镜像都不是最终权限来源。跨死亡、重登或服务器重启的数据应检查其实际持久化所有者，不能把临时玩家对象当作永久存储。

## 关键运行关系

### 战斗从入口到收尾

召唤物品、挑战确认或其他玩法入口先进入服务端规则，再由编排层创建或登记实体。实体更新与战术组件推进技能，公共事件处理伤害约束、死亡和奖励，血条与音乐分别由各自的协调模块跟随战斗。

庄园战的整体流程先读 `ManorFight`，单个角色的行为再查相关实体与战术模块。区块卸载、离开视野与实体死亡不是同一件事；失败处理必须回到战斗登记和实体标识核对，不仅依据某一刻能否查到实体。

收尾涉及实体、召唤物、血条和音乐，不只是删除一个对象。无奖励的清场与正常击杀必须区分，避免清理过程反向触发奖励。

### 物品交互从意图到提交

玩家在石像或容器中选择操作，网络层把意图交给服务端。服务端检查真实物品、玩家与交互位置等条件，交由领域规则计算并提交，再把结果同步给客户端。不同功能的状态归属和失败边界见 [食物武器架构](architecture/FOOD_WEAPONS.md)。

### 服务端结果如何变成画面与声音

实体的可见状态通过实体同步数据传达；粒子、声音和独立世界特效按各自同步路径到达客户端。客户端依照模型、动画、贴图和表现状态绘制结果，不能以本地动画是否播放判定服务端结算是否完成。

音乐由战斗请求驱动，不是资源目录里有音频就会播放。排查时同时检查请求与释放、服务端选曲、客户端播放和音效声明，而不是只替换声音文件。

## 资源与外部依赖

资源按 `src/main/resources/` 的相对布局打包；当前运行内容以交付中的生产资源导出为准。`assets/ftboss/` 提供模型、动画、贴图、语言与声音，材料目录还读取其中的食物属性资源；`data/` 提供配方、标签、掉落等数据。客户端模型和渲染入口决定资源是否被使用，资源文件存在不等于它已经接入；测试输入也必须与待验收包的生产资源对应。

铁魔法和 GeckoLib 等运行依赖由整合包提供，`libs/` 保存本地编译所需接口。是否允许某项集成缺失，由具体模块决定；不能把局部兜底扩大为“所有依赖都可移除”。GeckoLib 是模型与骨骼动画库，不负责决定战斗结算。

## 失败处理与维护顺序

- 行为没有生效：从实际调用入口、事件订阅与实体更新链查起，再查规则与目标，不以存在方法或枚举项作为生效证据。
- 实体或表现消失：分开检查服务端实体、同步状态、客户端注册和资源引用；客户端没有报错也不能排除资源未接入。
- 战斗残留：沿编排登记、卸载与重新加载、召唤物归属、血条与音乐释放查完整收尾，不混用卸载和击杀语义。
- 外部效果或法术失败：查实际集成模块的来源、目标和降级边界，避免把兼容失败扩散到整个服务端更新流程。
- 源码与正式运行包不一致：交由主代理核对实际构建输入与正式交付证据；不为让目录看起来统一而全量覆盖运行包。

## 源码、交付物与文档的边界

维护源码与共享主工程快照分别保存，二者存在分叉，不能互相覆盖。维护时先核对 [交付与验证入口](REFERENCE_INDEX.md#正式交付与验证入口) 中的源码角色，再沿本文的包路径阅读。共享快照不代表当前正式版已经完整回写到主工程。

生产资源从当前正式包导出。条目重放材料以固定只读基线加增量覆盖，恢复正式包的文件载荷；它不是全部遗留源码的独立干净构建，也不保证重新封装后压缩元数据及整包指纹完全相同。构建与依赖参考不能替代对应的构建证明。

构建与部署由获授权的主代理管理。本页不提供覆盖实例或清理工程的操作许可；正式包替换之外的存档、其他加载平台、脚本模组、资源包和配置不属于文档维护范围。工程整理仅确认对可恢复编译缓存的有限清理，不把历史目录视为已全面清理。

## 范围与验证边界

食物武器保留全部兼容清单及既有状态权威、最终伤害、结果消费、原生行为、铁魔法、三叉戟与首领接入。只有原生可损坏且已管理的武器进入磨损，原生不可损坏者自然排除，具体规则见 [食物武器架构](architecture/FOOD_WEAPONS.md)。

当前包专属的新鲜世界回归、生产环境武器检查、冷启动主菜单、真实石像满修和选定首领短程运行已有通过证据。自动化角色和选定场景不替代真人界面、全部招式与被动、长流程和多人体验；详见 [验证边界](architecture/FOOD_WEAPONS.md#验证边界)。

性能优化限于基础规则规范摘要的私有字符串编码，保留字节顺序、严格编码错误与预算约束，不缓存可变授权、不跳过来源检查，也不放宽石像支付条件。规则快照重算与受保护别名访问仍有开销，不能据单次配对样本推导首领整体或全服提速。

独立事件模组单独保留，未随本模组交付修改文件或启停状态，也不并入首领模组。本文讨论 Forge，不表示 NeoForge 或其他加载平台已同步适配。
