# 庄园 Boss 物理限伤与半血护甲

## 规则

- 正常体型的十一位庄园轮换 Boss，任意连续 20 个服务器 tick 中，物理攻击最终扣除的生命合计不超过 200。多人、武器和弹体共用每只 Boss 自己的额度；不是每位攻击者各有 200。
- 超额部分截断到剩余额度；额度耗尽后本次物理扣血为零。按滚动窗口过期，不按整秒重置，避免第 19/20 tick 连击越过上限。服务器低 TPS 时 20 tick 的实际时间会延长。
- 护甲、其他减伤、分摊预估、伤害吸收及最终伤害事件处理后，再对真正要扣生命的部分限伤；吸收黄心抵消的伤害不消耗额度。原有最终单次伤害大于 300 的屏蔽保持不变。
- 首次生命降到最大生命的 50% 或以下，进入护甲翻倍阶段。回血超过半血也保留；同一个 UUID 的修饰符不会逐 tick 叠加。新实体或变体更换重新计算。
- 限伤历史和半血阶段保存在实体 Forge persistent data；正常保存/重新加载不会清空一秒额度，护甲修饰符在服务器恢复。加载时先恢复生命、后恢复变体，不允许默认变体覆写已存阶段。
- 原版 ARMOR 属性有 30 的上限；本实现保留该全局限制，仅在这些 Boss 的 `getArmorValue` 计算翻倍后的有效护甲，避免 24→30 而不是 24→48。其他实体不受影响。部分属性查看工具仍会显示经原版上限截断后的属性值。
- 不改护甲韧性和原版护甲伤害公式；护甲翻倍不等于所有伤害减半，忽略护甲的伤害仍忽略护甲。

## 范围

仅支持当前轮换变体 0–8、10、11；麻雀支援位、迷你/巨大召唤形态、非庄园 Boss 和玩家不新增此防御。管理员 generic kill 不受限制。

物理来源用 `ftboss:physical_damage` 数据标签明确分类。默认包含近战、箭矢、三叉戟、投掷、普通实体弹体、爆炸，以及可选的 Bren 子弹和 armamentarium 暗杀。魔法、抗性/保护穿透攻击和真实伤害不因为“有攻击者”而误判为物理。新模组物理伤害可以在数据包里用 `replace:false` 追加其 DamageType ID；缺少可选模组不会导致标签加载失败。

## 实现与验证

纯滚动窗口规则为 `ManorPhysicalDefenseRules`；服务器状态、属性与事件辅助为 `ManorPhysicalDefense`。普通 Forge 最终伤害钩子通过 `FinalBossDamageGuard` 接入。庄园正式包现有 `ManorFinalDamage.settle` 需要在最终事件成功之后、分摊/吸收提交之前插入同一限伤调用；不能仅注册一个普通 `LivingDamageEvent` 监听器，否则其他低优先级监听器可以再增伤。

主源码保留着旧的 `manorHurt`，而正式包已经使用 `ManorFinalDamage`。本轮已给旧源码补入对应的护甲与限伤入口，并对正式包交付精确方法增量，不使用旧实体供体整类覆盖正式实体。未来全量源码构建仍必须遵守工程原有的运行时额外条目保全流程。

纯规则回归入口：`checkManorPhysicalDefense`，不依赖编译整个主源码；也可以直接用 Java 17 编译规则类与 `tools/verification/ManorPhysicalDefenseRulesCheck.java` 后运行。
