# ftboss 铁魔法模型全量补齐

## 审计口径

实际注册链：`BossIronSpells` → `BossSpellRules.Kind`，`ManorIronSpells` → `ManorSpellRules.Kind`，`QizaiPlayerSpells` → 四门玩家卷轴。共72门通用表现法术加4门玩家卷轴，合计76门；本轮不将 Iron 模组自己的其他命名空间法术算入 ftboss。

在已有实现中，13门庄园独立主体、27门专属射线模型、3门径向主体、绯星连奏专属模型均保留。另有4门已接入实际 Iron 实体模型：晶冠、果园盾、替身盾、羽步，保留而不重复叠加。光线/粒子映射不等于实体模型；因此剩余24门通用法术和4门玩家卷轴需要补齐。

每门至少有一个实际释放阶段或投射物实体的立体模型；并不声称每门所有阶段都重建模。已有法阵、警告及适当粒子可以保留作为辅助层。自动审计CSV逐门记录模型路径和阶段；运行时测试额外枚举 Iron 注册表所有 `ftboss` 键，不能仅靠已有列表自证没有遗漏。

## 渲染与安全

真源为 `RemainingSpellModels`。网格具有厚度、封闭端面与切面着色，非换色贴图。通用法术复用 `SpellVisualRenderer` 的可淡出写深度材质，每帧取/刷一次；主体全程保持设计尺寸，仅在最后最多 3 tick 透明消散，随后绘制透明法阵。新24门不再被 `IronNativeSpellBridge.accept` 提前消费为单纯原生粒子，原有4门原生模型入口不变。

删除新模型法术的重复通用主体几何，保留法阵、完整危险半径和阶段提示。玩家卷轴实体先写完模型，再切至法阵材质，绝不切换后继续写旧consumer。低粒子模式减小装饰数量，模型仍有主体；通用主体总数沿用12/8/4预算。最复杂当前模型824四边形，硬上限1100。

沿用距离/视锥剔除、施法者UUID匹配、死亡/离场/维度切换清理。反复充能用刷新后的年龄，避免超过首次充能时长后模型消失。碧潮莲华的大型实体莲花仅在本人第一人称隐藏，治疗粒子和法阵保留；第三人称及其他玩家仍可见完整模型。没有改变伤害、命中、冷却、回血、法力、AI、网络字段或法术注册。

## 验证与预览

- `checkRemainingSpellModels` 自动比较全部72门与模型覆盖并列出4卷轴，生成76行 `spell-model-audit.csv`。新增未建模法术会使构建失败。
- 每个新模型检查全部阶段、完整寿命半帧采样、低画质、无效输入、顶点/面面积、范围、面数、材质以及几何指纹，禁止简单换色冒充不同模型。
- 输出实际网格软件深度渲染的 `models-01.png`、`models-02.png`、`qizai-scrolls.png`；白夜碑双面纹样在预览检查中补齐。
- `RemainingSpellModelGameTests` 验证真实 Iron 注册表、包编解码到模型的接线、自然服务器tick下的全寿命和重复施放；保留玩家卷轴和万棱三连回归。
- 实机调试可使用已有 `/ftspellfx <id> <charge|release|pulse|beam>`（仅显示视觉）；玩家四卷轴通过原有实体渲染路径。
