## 优化点

| 热点 | 原实现 | 当前实现 |
|---|---|---|
| 隐藏 Boss 预警、核心连线、技能粒子 | 两个渲染器每帧分别扫描全部客户端实体，粒子每 tick 再扫一次 | `CombatVisualEntities` 按世界对象 + 游戏 tick 共用分类快照；只缓存实体引用，坐标/姿态/技能阶段仍实时读取 |
| 核心骨骼锚点回收 | 每帧创建 stream 遍历锚点表 | 每 20 tick 清理；换世界、卸载、断开时释放 |
| 玩家信标 | 每 10 tick 两次全生物范围查询 | 一次隐藏 Boss 类型查询；只有重新打开禁飞功能才补查常规 Boss |
| 麻雀附近候选 | 全生物查询后构造名单，再移除常规 Boss | 直接查询隐藏 Boss 类型，保持原范围、存活与变体筛选 |
| 狗群计数/维护/齐扑 | 计数按召唤次数重复扫描全维度实体；维护即使无狗也每秒全扫 | 由实体加入/离开事件维护已加载狗群表，空闲立即返回，召唤容量仅计算一次 |
| 狗群退场 | 先移除过期出生记录，随后查不到时间而无法执行 discard | 出生时间保存在 `ftboss_pack_born`，先退场再注销；不会因读档/区块重载获得无限续命 |

狗群保持原 `LIFE = 1200 tick`、`CAP = 12`、每 20 tick 维护及严格 `age > LIFE` 的边界。旧存档里只有 `ftboss_pack` 的狗在首次加载时补记出生时间，再获得一次正常寿命。普通野生狼不登记、不退场。没有修改攻击减益或狗种白名单。

登记表拒收客户端对象；移除事件用 UUID + 实例双重匹配，避免旧实体离开误删区块重载的新实例。维度卸载、服务器停止均清理引用和待执行动作。飞扑只作用于目标所在维度。

麻雀全局防重复扫描和屠夫遗骸兜底仍保留：它们是低频可靠性检查，不用可能遗漏重载实体的缓存冒险替换。BGM 调度、庄园战场状态机、反作弊与日志诊断本轮不动。

## 验证与收益边界

执行 `node tools/verification/check_performance.cjs`，也已纳入 `node tools/verify_project.cjs`。

- 使用真实缓存、客户端分类与狗群源码，配最小 Minecraft/Forge API 替身；不是重写一套逻辑来测试。
- 10,003 实体夹具、240 tick、模拟 120 FPS：三个使用方合计完整实体扫描从 260 次/秒降到 20 次/秒；测试按调用次数验证，不当作实际 FPS 提升。
- 检查世界切换、同 tick 复用、时间回退、旧世界迟到卸载、断开、不可变快照和加载异常重试。
- 狗群检查寿命边界、重载续期防护、取消生成、数量上限、齐扑时机、跨维度隔离、目标刷新、注销回调、客户端隔离与服务器停止。夹具的全世界扫描 API 直接抛错，避免测试中悄悄退回全扫。
- Forge 完整构建负责真实 API 类型兼容，资源校验与最终 jar 内容对比负责确认没有意外夹带旧资源。

尚未进行游戏内 FPS/TPS 或帧时间采样，不声称已消除整合包全部卡顿。建议重启 beta3 后对比同存档、同视距、同战场的帧时间/TPS，重点观察多人隐藏 Boss 战、故障核心多球和狗群 60 秒后退场。
