# 庄园开场：先清增益，再发场地增益

2026-10-17。实现已合入主工程；候选包、基线及验收记录位于 `D:/ft工程文件/FTBoss-开场净化后场地增益-20261017`。本记录不代表已部署。

- 成功生成开场演出后，首次同步附近玩家时，先一次性移除玩家当前全部正面状态，再立即发放庄园场地增益。负面与中性状态保留。
- 旧信标/环境增益也参与本次开场清除，随后由场地增益重建；此规则不同于麻雀战斗中每十秒随机驱散非信标增益，后者保持不变。
- 使用既有开场观看范围：与演出 Boss 同维度、96 格内的存活生存/冒险玩家。创造、旁观、死亡与已移除玩家不参与。
- 每场演出单独记录已处理玩家 UUID；重复同步、离场再回来、同一玩家断线重连都不会在本场重复清除。演出期间首次进入范围的有效玩家同样只处理一次；下一场新的开场演出会重新处理。
- 只在成功创建的开场演出中生效，失败召唤、普通 Boss、麻雀日常支援与庄园战斗换波不额外触发。
- 场地增益仍使用 `BossHandler.BEACON_EFFECTS` 的速度、急迫、抗性提升、跳跃提升、力量、生命恢复，均为 II 级、240 tick、ambient，不显示粒子和图标。原有十 tick 检查与低于 60 tick 时续期的逻辑保留。
- 演出开始后新获得的药水增益不会被反复清掉；常规场地增益补发仍保留原有“不覆盖更强/更长效果”的行为。
- 一次性状态保存在演出对象内；演出结束/取消后随对象释放，无全局玩家状态、存档键、网络协议或模型资源改动。

入口：`HiddenBossIntro.syncViewers` → `ManorIntroPlayerBuffs.begin`。常规场地增益入口 `BossHandler.applyBeaconBuffs` 共用同一个 `applyFieldBuffs` 实现，确保清除与发放顺序确定。
