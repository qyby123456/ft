# 非庄园 Boss：攻击、技能、被动与铁魔法并行

更新日期：2026-09-19。

## 通道分离

- 原有动作通道继续负责近战前摇、根刺、茶毒、炮弹、火球、召唤、冲撞和喷射。原有动作之间的互斥保留，不把两个主体动作挤进同一个状态机。
- 原生 Iron 法术继续使用 AbstractSpellCastingMob 的 MagicData，保留长施法、持续引导、取消与同步生命周期；正在施法时不会被另一原生 Iron 法术覆盖。
- FTBoss 专属法术统一由 BossSpellCombat 独立蓄力，释放时传入独立 MagicData，不调用 initiateCastSpell、不占原生 Iron 施法槽、不改原技能姿态或 LookControl。一个专属法术与一个原生 Iron 法术可以同时吟唱、释放。
- 专属法术保留原目标 UUID、前摇警示、范围/视线、安全目标、启用配置、死亡/无 AI 检查与超时取消。取消专属法术不会清除原生 Iron 数据。
- 原生 Iron 的 25% 抽取、成功 240 tick 冷却、失败 60 tick 重试，以及专属 60 tick 起手间隔、单招冷却与减半吟唱均不变。取消的是两类施法之间的互斥，不是所有冷却。

## 实体调整

| Boss | 并行行为 |
|---|---|
| 糖霜女皇 | 近战前摇不再检查 isCasting；本体冲刺及环绕移动不再暂停于吟唱；已有近战不会拒绝 Iron 起手。 |
| 沙耶 | 根刺、茶毒、近身攻击不再被 Iron 吟唱阻塞；Iron 调度移到原技能动作判定之前；光环、轮换增益、成长与汲取继续独立运行。 |
| 酒桶王 | 炮弹、火球、召唤起手及滚动、喷射不再等待 Iron 吟唱；Iron 调度在非待机动作时也能运行。主体动作动画排在 Iron 控制器之后，优先保留滚动/喷射等动作；纯施法时让原生控制器显示施法。 |
| 故障核心 | 独立专属法术不再等待充能球等动作锁；不删除原动作锁，也不改充能球、光束或回想逻辑。 |
| 堆肥、金苹果、潮汐鱼 | 延续独立专属蓄力通道；不改其原有技能/被动状态机。 |

屠夫、鼠群原本没有这套专属 Iron 调度，不新增法术或改动其行为。庄园 Boss、玩家卷轴、伤害、掉落、法力与冷却数值均不修改。

## 验证入口

隔离工程执行 `gradle -I tools/verification/manor_integration_gametest.gradle clean build runGameTestServer --rerun-tasks`。

`BossParallelCastingGameTests` 覆盖三类施法实体双通道正反顺序、MagicData 不被覆盖、近战与根刺/茶毒/炮弹/滚动/喷射起手、被动计时、故障核心动作锁兼容、七类专属调度与失效取消；原有法术与庄园测试一并回归。

2026-09-19 验证结果：9 项并行专项测试通过；合并其他线程当时已完成的更新后，完整 clean build 和 126 项服务端 GameTest 全部通过。最终混淆 jar 的字节码确认 BossSpellCombat 不再调用 initiateCastSpell 或检查故障核心动作锁，释放使用独立 MagicData。客户端动画叠加尚未进行实机目视验收。
