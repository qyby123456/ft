# Boss 仇恨机制

2026-09-18：由“最近攻击者锁定 10 秒”改为每个 Boss 独立维护累计仇恨表。

## 默认规则

| 来源 / 行为 | 规则 |
| --- | --- |
| 造成伤害 | 1 点有效伤害 = 1 点仇恨；读取 `LivingDamageEvent` 的护甲、抗性、吸收等结算后数值，并限制为 Boss 剩余生命值 |
| 食物 | 成功吃完一次 +5；兼容采用 Minecraft 食物属性的模组食品 |
| 药水 | 喝完有效药水，或成功抛出带效果的喷溅 / 滞留药水，一次 +8 |
| 时间衰减 | 连续指数衰减：`当前仇恨 = 原仇恨 × 0.5^(经过 tick / 600)`，30 秒减半、60 秒剩四分之一 |
| 遗忘 | 仇恨低于 0.1 时删除；死亡、下线、移除、换维度、离开 64 格范围也会丢弃 |
| 同分 | 保持当前目标，避免无意义地来回切换 |

伤害是主要来源；食物、药水仅给使用者同维度、64 格内**已经交战的已登记 Boss**增加仇恨，不会靠吃东西主动引来空闲 Boss。
取消进食 / 喝药不计数；水瓶、无效果药水、弓等非食品不计数。被取消、零伤害、无效数值不会记账。
不因药水持续生效或滞留云每次触发而重复增加“使用”仇恨；其造成的实际伤害仍按伤害事件单独计算。

## 目标选择

- 伤害或补给记账后立即选择当前最高仇恨目标；每 10 tick 清理无效条目并检查目标。
- 原版 AI 尝试切换目标时通过 `LivingChangeTargetEvent` 保留最高仇恨目标，避免最近玩家 / 最后受击目标抢锁。
- 女皇（含复制体）、屠夫、沙耶、酒桶王的手写索敌共用仇恨优先入口；庄园追击优先追仇恨目标，青衣三叉戟范围内落雷也优先仇恨目标；机器人玩家定向技能不再抢打较近的低仇恨玩家。
- 没有有效仇恨时回退原本的常规索敌；创造、旁观、已死、已移除对象不参与。
- 玩家与其他有效攻击生物共用排行榜；箭、法术、召唤物沿既有伤害来源归属规则追溯攻击者。
- ftboss 阵营不互相记仇；麻雀仍是支援位，冻结 / 入场状态不会被强制激活。
- 不改变技能伤害、冷却、动画前摇、预先锁定的技能落点、范围攻击或庄园场地规则。
- 仇恨不写入存档；服务端停止时清空，避免重开世界继承旧战斗。

## 调参与验证

参数集中在 `BossThreatTable` 的 `FOOD_THREAT`、`POTION_THREAT`、`HALF_LIFE_TICKS`、`MIN_THREAT`，最大追击距离在 `BossAggro.MAX_DIST`。

- `gradle build` 自动执行 `checkBossThreat`，覆盖累计、最高值、同分、衰减、无效条目、多 Boss 隔离及数值边界。
- 设置 `JAVA_HOME` 为 JDK 17 后执行 `node tools/verification/check_boss_aggro.cjs`，用简化世界替身执行真实 `BossAggro` / `BossTargets`，另检查事件和各索敌入口接线。
- 实机建议：两名生存玩家分别输出 100 / 10，低输出者最后补刀不应抢走目标；低输出者持续输出或补给超过衰减后的第一名时切换；切创造 / 旁观、死亡、跨维度后应丢失仇恨。
- 自动化检查不等同于 Minecraft 实机或多人联机验收。
