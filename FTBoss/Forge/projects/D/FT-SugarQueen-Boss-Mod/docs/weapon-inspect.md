# FTBoss 武器视检

## 使用

- 第一人称手持支持的武器，按 **N** 播放视检，再按一次用 0.3 秒收回。
- 可在「选项 → 控制 → 按键绑定 → FTBoss · 武器」改键；物品提示显示当前绑定。
- 主手优先；主手不是支持的物品时可视检副手。左利手自动镜像。
- 攻击、使用/施法、切槽、换物、冲刺、游泳、鞘翅、切第三人称、打开界面、死亡、离开世界都会结束视检。
- 动画仅作用于自己的第一人称持物画面，不影响第三人称、物品栏、掉落物、其他玩家或游戏数值。
- 视检不会装填、发射、消耗耐久、触发技能、写入物品 NBT 或发送技能包。

## 庄园创造栏

`item/ManorWeaponCatalog.java` 是庄园武器条目的唯一来源；`FTCreativeTabs` 在武器区调用它。雪黎原来的额外创造栏监听已合并，避免重复条目。本轮按用户要求新增两件有独立技能的朵拉武器，不改 Boss 原有装备/战斗逻辑或掉落概率。

| 庄园角色 | FTBoss 创造栏条目 |
|---|---|
| 柚子 / 蛋蛋 | 柚子小像 / 蛋蛋镰刀 |
| 朵拉 | FTBoss 地脉新星、鸣脉长枪（独立注册物品） |
| 工地 | 黑色切割者 |
| 柠檬猫 | 平底锅、锅铲 |
| 青衣 | stormseeker、the_desecrator、echo_of_the_deep、stellaris |
| 文玄蓝 | 绿月、白月两个独立初始形态条目 |
| 暗影 / 河豚 / 麻雀 | 暗影剑 / 河豚棒 / 赐福羽 |
| 雪黎 | 平底锅、擀面杖 |

共 18 个庄园物品堆条目（14 个 FTBoss 条目、4 个外部青衣武器条目），连同普通 Boss 武器和新增潮骨三叉戟，武器区共 31 个条目。未安装 Tridents N Stuff 时跳过青衣条目，不产生空气占位。朵拉两把玩家武器无需 Bren / TnS；玄蓝两种形态仍为同一把可切换武器，不锁死名称。

朵拉枪为 `ftboss:dora_nova_launcher` 鸣脉冲锋枪，使用独立短枪身、直弹匣三维模型；长枪为 `ftboss:dora_lance`，采用 40 方块模型与 128×128 逐面贴图。两者 GUI/落地/手持均为 FTBoss 模型，不再被 Bren 的图标拦截。冲锋枪机制与掉落见 `docs/dora-smg.md`。

旧存档中的 Bren 标记枪和 TnS 长矛不强行转换；原有 `ftboss:dora_nova_launcher` 自动使用冲锋枪模型与机制。符合条件的朵拉击杀掉落冲锋枪，创造栏也能取得。Boss 自己的武器与原模组物品保持不变。

### 朵拉独立技能

均仅主手。冲锋枪按住右键立即连射，30 发弹匣、600 发/分，空匣自动换弹 1.8 秒，潜行右键主动换弹。长枪仍按住右键蓄力后松开；0.6 秒起效、1.2 秒满蓄，松开时潜行决定副技能。未达到起效时间不扣耐久、不进冷却。实际伤害受目标护甲/原有伤害管线影响。

| 武器/技能 | 效果 | 冷却 | 耐久 |
|---|---|---|---|
| 鸣脉冲锋枪：全自动 | 单发 5 点伤害，14～28 格衰减至 2.5，遇墙/首个生物停止 | 每发 0.1 秒；换弹 1.8 秒 | 每发 1 |
| 鸣脉长枪：突刺 | 前方 6.5 格、半径 0.85 格，15 点伤害，减速 2.5 秒 | 2.5 秒 | 2 |
| 鸣脉长枪：潜行横扫 | 前方 4.5 格扇形，12 点伤害，减速 2.5 秒 | 4.5 秒 | 3 |

服务端执行技能与扣耐久；尊重冷却、PvP 开关、队伍友伤，跳过创造/旁观玩家、盔甲架与有主宠物。不清无敌帧、不直接写血量、不瞬移穿墙。特效通过服务端粒子/音效同步给周围玩家，不要求额外网络或外部弹药模组。右键会立即中断视检，N 视检不会释放技能。

## 实现

- `client/inspect/WeaponInspectClient.java`：N 键、客户端注册、状态过滤、第一人称渲染和物品提示。
- `client/inspect/WeaponInspectPlayback.java`：与帧率无关的时钟、提前平滑收回、即时中断。
- `client/inspect/WeaponInspectMotion.java`：资源校验、关键帧采样、左右手镜像。
- `assets/ftboss/inspect/weapon_inspect.json`：唯一动作参数源，可由资源包覆盖，F3+T 重新加载。
- `META-INF/accesstransformer.cfg`：只开放原版 `ItemInHandRenderer.renderArmWithItem`，保留原物品渲染器、模型覆盖、GeckoLib 骨骼和发光层。

RenderHandEvent 中先 pushPose，围绕持握位置应用视检变换，再调用原版单手渲染，finally popPose，然后取消该手默认重复绘制。不能调用 renderHandsWithItems，否则会再次进入 RenderHandEvent。输入事件只清空视检，不取消游戏攻击/使用。

每行参数顺序是 `[秒, 位移X, 位移Y, 位移Z, 旋转X, 旋转Y, 旋转Z]`；位移单位为格、旋转单位为度。时间必须严格递增，首尾必须回到零偏移，资源损坏时仅禁用视检并记日志。

可选 `variants` 数组按顺序匹配 `item`、`tag`、`value` 后选 `clip`；布尔、整数、字符串严格对应 NBT 类型，缺少/类型不符时回退 `items` 默认值。视检读取标签但不写标签；创造栏创建初始形态标签是单独的服务于物品目录的逻辑。

## 验证

运行 `node tools/verification/check_weapon_inspect.cjs <输出目录>`，覆盖：47 个物品、33 个庄园目录条目（20 个胜利箱条目与 13 个创造栏附加条目）、无重复创造栏接线、可选模组缺失保护、6 条严格类型 NBT 匹配/回退、按键/资源/事件接线、关键帧精确值、插值不超范围、左右镜像、重复采样不推进时钟、自然结束、提前收回、即时中断与坏资源拒绝。测试直接编译并调用实际 Java 采样器，不在 JavaScript 中重新实现动作曲线。

运行 `node tools/verification/check_dora_weapons.cjs <输出目录>`，调用实际 Java 技能规则，检查蓄力边界、模式、冷却/伤害、射程/扇形，以及服务端/PvP/视线保护接线、创造栏、双语提示、模型贴图、GUI 裁切范围和模型生成器可重现性。静态接线检查不等于实机命中测试。

运行 `node tools/model3d/preview_weapon_inspect.cjs <测试输出目录>/motion-samples.json <预览目录>`，生成七类基础武器的贴图序列图；追加 `--manor` 生成八类新增庄园动作。预览从实际 Java 导出的 60 fps 动作读取参数；几何使用项目已有 cube_space 工具，持物/视检旋转按 PoseStack 的 X/Y/Z 乘法顺序处理。

追加 `--new-weapons` 预览潮骨三叉戟、独立朵拉枪、鸣脉长枪；再加 `--gui` 输出三维图标预览。

离线图仅验证动作方向与大致取景，不是游戏截图：未复现玩家手臂、光影、动态骨骼和所有 BEWLR 变换。青衣三叉戟/旧 TnS 长矛用外部 Java BEWLR，未以虚构几何冒充预览。仍需在游戏中验证新技能的蓄力/冷却、墙体与 PvP、绯星祈愿杖及其他新增视检武器、玄蓝切换、普通/血怒黑切、暗影剑就绪/冷却、空载/装填酒桶弩、左利手、副手和资源重载。

## 构建与部署

`build.gradle` 必须保留 accessTransformer 配置，且最终 JAR 内必须包含 AT、三个运行类及 Registration 内部类、动作 JSON 和语言键。

使用 `tools/deploy_jar.ps1` 部署，正在运行 Minecraft 时脚本会拒绝替换。不要把构建输出直接覆盖到运行中的 mods。若存在其他会话正在修改 Boss 代码，应使用已验证快照保留独立产物，不覆盖其他构建目录；实际部署前应重新构建最新完整源码，避免回退并行改动。
