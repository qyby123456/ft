# 模组残留审计与清理

## 范围与处理原则

扫描整个运行时 Java、资源和注册关系，核对隐式事件订阅、Mixin、动态模型路径及声音事件。只移除能够证明没有运行入口的实现；未把“文本搜索不到引用”直接等同于无用内容。没有调整现行 Boss 的伤害、血量、技能时序、掉落规则或石像交易。

## 已清理

- 庄园旧巨人终章的生成入口、共享血池、编队数据、骨架粒子、追踪移动和重击；活动战斗不再保存旧终章状态或逐 tick 检查其分支。
- 实体侧的巨人血量、体型、判定箱、名字、践踏及对应渲染缩放。迷你分身缩放保留。
- `IronCast` 旧反射施法桥和 `SphereMesh` 备用球面网格：源码及运行时资源均无引用，也不属于事件/Mixin 自动入口，移至归档。现行铁魔法集成和法术独立模型保留。
- 三个无引用私有成员：屠夫旧 `facePlayer`、女王旧 `DESPAWN_RANGE`、庄园实体旧 `VOID_FALLS_TO_RELOCATE`。有效的屠夫距离检测、女王朝向逻辑和庄园虚空搬迁规则未动。
- 70 个停用卷轴模型和 70 张对应贴图；这些素材原本已被打包规则排除，本次从源资源目录归档，并不声称因此压缩了原有成品体积。
- 四个未接入声音事件且无运行时引用的苹果旧音效：attack / dash / death / seed。当前战斗音乐的原始字节不变。
- 按旧行号删源码的一次性 `cleanup_dead_code.cjs` 及三份历史日志。

总计归档 150 个文件、208011 字节，不作不可恢复的删除。目录及逐文件 SHA256 清单：

- `_dev_backup/organization-20260921-213157-676/manifest.json`：146 个文件。
- `_dev_backup/organization-20260921-214619-106/manifest.json`：4 个音效。

## 性能与兼容

- `isFinaleMember` / `onDamage` 保留常量 false 的旧接口，不再扫描活动战斗；实体受击路径移除多余的旧血池调用。
- 进度血条每场每 tick 只复制、清理一次观众集合，不再对每位在线玩家重复复制和扫描；无在线玩家时也能清理断线引用，且不会重新订阅已断线玩家。
- 保留旧 `DATA_GIANT` 同步槽和只读写标记的 `isGiant` / `setGiant`，避免改变后续实体同步字段的编号。标记不能恢复巨人属性或攻击。
- 不删除实体/物品注册 ID、玩家已有物品、存档、参考素材、发光图层、OBJ 材质或动态选取的模型。三叉戟内嵌包保留原始哈希。
- 构建新增退役内容守卫；已有备份后缀、旧卷轴目录的打包排除规则继续保留，以阻止旧生成器重新塞回资源。

## 审计边界

静态工具仍列出 207 个疑似无引用资源，其中有动态路径和框架约定加载内容；不能据此批量删除。77 个明确的约定加载资源另行识别。四条所谓缺失语言键是伤害消息 ID，实际 `death.attack.ftboss.*` 译文已存在。剩余 14 个未使用 import 只影响源码整洁，不是运行时性能问题，本轮不扩大修改范围。

## 验证

同一组 118 项 Forge GameTest，分别使用清理前和清理后的运行时代码对照：

- 清理前代码通过 109 项，清理后通过 111 项。
- 巨人标记不再恢复属性/判定箱，以及断线血条清理两个回归点由失败转为通过。
- 清理后 7 个失败与清理前完全重合，没有新增失败；其余测试覆盖入场保护、轮换、召回、直接胜利结算、跨维度停止、支援与实体兼容。
- 7 个旧失败：两条移动速度断言、青衣投戟频率、技能蓄力时长，以及三条奖励箱平铺/容量假设。奖励打包实际已有递归额外箱机制，旧测试需要适配它；不能把这些断言失败直接描述为本轮造成的丢奖励。
- 没有为了让旧测试变绿而恢复旧战斗数值或改动奖励结构。测试文件中的失效普通胜利入口名已对齐现行 `onManorNormalVictory`。
