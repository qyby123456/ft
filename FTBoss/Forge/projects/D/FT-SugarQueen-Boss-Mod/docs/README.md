# 文档总导航

这里帮助读者理解模组的现存架构、系统边界和维护入口。先读当前架构，再按需要进入机制参考；旧专题、交接和审计材料只是查找线索，不能单独证明正式运行状态。

## 当前能力与阅读范围

食物武器的原生磨损与石像满修已正式交付。当前包通过新鲜世界回归、生产环境武器检查、客户端冷启动主菜单、真实石像付费修复及选定首领的短程运行验证。具体用例、自然排除条件与未覆盖场景见 [食物武器验证边界](architecture/FOOD_WEAPONS.md#验证边界)，正式包与证据从 [交付与验证入口](REFERENCE_INDEX.md#正式交付与验证入口) 核对。

性能分析只支持受测磨损与石像流程的单次配对观察，不证明首领整体或全服提速。真人界面、全部技能与被动、长流程及多人体验仍需确认，详见 [性能与正确性边界](architecture/FOOD_WEAPONS.md#性能与正确性边界) 和 [未完成与待确认](architecture/FOOD_WEAPONS.md#未完成与待确认)。

## 保留资料与合并建议

旧文件保留原位，不默认删除、移动或继续补写发布流水。参考索引只解释它们用来查什么，不重新认可其中每一项实现结论。

- 建议将综合机制参考作为完整机制说明的优先检索入口，对照原机制参考逐项补缺；是否将后者归档，交由主代理确认。
- 两套精简速查建议只保留精简用途，不再各自维护一套架构解释；是否由统一机制内容派生，需要另行确认。
- 剑构筑、生命周期和剑腔专题有明显交叉，架构说明统一从食物武器页进入；旧交付收据继续留作证据，不并入正文。
- 多份暗影剑交接、工程整理、同步和审计资料建议在确认有效内容后归并；现阶段不改动其原文。

## 范围与阅读边界

- 全部武器兼容清单仍在维护范围内；只有原生可损坏且已纳入管理的食物武器参与磨损，原生不可损坏者自然排除，不靠删除兼容项缩小范围。
- 磨损阶段、非必要部件选择、非石像修复限制和石像任务满修统一见食物武器架构，不从旧阶段文档拼接规则。
- 正式交付包含维护源码、独立共享快照、生产资源和基线条目重放材料，不是已经证明可全量干净构建的完整源码工程。工程清理仅限可恢复编译缓存，不等于所有历史目录均已整理。
- 文档不把既有测试扩大为所有外部模组和多人场景的保证，也不提供覆盖运行包的操作授权。
