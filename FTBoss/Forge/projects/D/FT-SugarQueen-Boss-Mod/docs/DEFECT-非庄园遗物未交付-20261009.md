## 三、根因

三处实现共用同一条判定，**只认"致命一击归属"，不认"玩家是否参与"**：

```java
// skill/BossRelicDrops.java（线上在跑，打印中文"遗物跳过"）
if (!(source.getEntity() instanceof ServerPlayer) && !(boss.getKillCredit() instanceof ServerPlayer)) {
    FTBossMod.LOGGER.info("[FTBoss] 遗物跳过: {} —— 击杀者不是玩家（source={}, killCredit={}）", who, source.getEntity(), boss.getKillCredit());
    return;
}
```

被它误杀的三类正常情形：

1. **玩家打了，补刀是召唤物/傀儡/别的怪**（本例 焰魔、铁傀儡、监守者）；
2. **致命伤无实体来源**（`source=null`：火、坠落、DoT，或武器走 `damageSources().magic()`）——玩家击杀也会被判成"不是玩家"；
3. 玩家先被怪/Boss 打死，Boss 随后被怪打死。

**口径不一致**：同模组的连死怜悯用"参与度"（日志 `连死计数已清零(Boss「柚子」被击杀, 影响 1 名玩家)`），遗物系统用"致命一击归属"，同一场战斗两者结论相反。

## 五、修复规格（口径 A：参与即给）

### 5.1 `BossMercy`：开放一个可复用的"谁参与过"查询

威胁表已存在且已由玩家伤害路径写入（`BossHandler.java:370` 调 `BossMercy.noteThreat(p, attacker, gameTime)`；`THREAT_MEMORY = 200L` tick，`THREATS: Map<UUID, Map<keyOf(boss), gameTime>>`）。新增：

```java
/** 最近 THREAT_MEMORY tick 内对该实体造成过伤害的玩家（取最近一次）；无则 null。 */
public static ServerPlayer lastThreatPlayer(Entity target)
```
实现要点：以 `keyOf(target)` 为键遍历 `THREATS` 取 `now - t <= THREAT_MEMORY` 的最大 `gameTime` → 对应 UUID → `server.getPlayerList().getPlayer(uuid)`；顺手 `pruneThreats(now)`。
（若 `keyOf` 语义是"每实体实例"而非"每类型"，请在实现时按实际语义取键，并在交接里写明。）

### 5.2 `BossRelicDrops.reward`：判定改为"参与即给"，并调整判定顺序

```java
ServerPlayer credited =
        source.getEntity() instanceof ServerPlayer p ? p
      : ownerPlayer(source.getEntity())                                  // 召唤物/投射物归属（可复用 BossMercy.resolveOwner 的语义）
      : boss.getKillCredit() instanceof ServerPlayer c ? c
      : BossMercy.lastThreatPlayer(boss)                                 // ← 口径 A 的核心
      : null;
if (credited == null) { FTBossMod.LOGGER.info("[FTBoss] 遗物跳过: {} —— 本场无玩家参与", who); return; }
```

**同时把这道判定挪到"确认该实体确实是遗物持有者"之后**：现在 `normalDrops(event)` 对**任何**实体死亡都先跑这道判定，导致 448 条与奖励无关的 `遗物跳过` 噪声（骷髅、铁傀儡、玩家自己的死亡都在刷）。建议顺序：① `LemonSummonRewards.suppressed` → ② `doMobLoot` → ③ **是否遗物持有者（`BossRelicRules`）** → ④ `REWARDED` 标记 → ⑤ 玩家参与判定。

### 5.3 `NonManorLootCrateDrops` / `FoodBossInventoryRewards`

- 用同一套 `credited` 解析（把 5.2 的解析提成公共方法，例如 `boss/ai/RewardAttribution.java`，三处共用，避免再次口径分叉）；
- **把 `FoodBossInventoryRewards` 与改好的 `NonManorLootCrateDrops` 一起落进 jar**（当前前者完全缺失、后者是旧实现）；
- 保留 `FoodBossInventoryRewards` 的 voucher/claim 兜底：*背包满时不要静默丢*，按现有实现走凭证/二次领取。

### 5.4 交付后必须核对的

1. 条目级增量：新包相对 `47355CF5…` **只应新增** `FoodBossInventoryRewards*` 与归因工具类，外加被本次改写的 `BossMercy` / `BossRelicDrops` / `NonManorLootCrateDrops`；不得出现"A 锚点有条目、新包没有"的删除（现行硬底线：移除 0）；
