# FT Chunk Drops — 区块掉落物诊断

Minecraft **1.20.1** / Forge **47.4.10–47.x** / Java **17**，版本 **1.0.0**，模组 ID `ftchunkdrops`。

## 安装

停服后把 `release/ft-chunk-drops-forge-1.20.1-1.0.0.jar` 放进**服务器**的 `mods` 目录，再启动服务器。
客户端不需要安装。也支持 Forge 单人游戏 / 局域网内置服务器；使用指令需要开启作弊或具有 OP 2 级权限。
本工程不会自动向现有整合包安装 JAR，也不会修改现有世界、配置或其他模组。

## 指令

| 指令 | 用途 |
| --- | --- |
| `/chunkdrops` | 全服全部维度的掉落物区块排行，默认前 10 名 |
| `/chunkdrops top 30` | 查看前 30 名，允许 1–50 |
| `/chunkdrops here` | 查看当前执行位置所在区块的实体数、物品总数、每个实体的物品 ID / 数量 / XYZ |
| `/chunkdrops here 2` | 当前区块第 2 页，每页 10 个实体 |
| `/chunkdrops chunk -12 8` | 当前执行维度的区块 `[-12, 8]`，注意不是方块坐标 |
| `/chunkdrops chunk -12 8 2` | 指定区块第 2 页 |
| `/execute in minecraft:the_nether run chunkdrops chunk -12 8` | 查询下界指定区块 |
| `/chunkdrops report` | 全维度 CSV 导出，每个掉落物实体一行，不受聊天分页 / 排行条数限制 |
| `/chunkdrops help` | 游戏内帮助 |

服务器控制台输入指令时可省略开头的 `/`。`here` 使用指令执行位置：玩家执行时是玩家位置，控制台通常是主世界出生点；控制台推荐使用 `chunk`。

排行中的 `[查看]` 和明细中的 `[下一页]` 会把对应查询指令填入聊天框。点击明细坐标会填入对应维度的传送指令，**需要手动确认，不会自动传送**；悬停显示实体 UUID。

## 统计口径

- 一堆 64 个圆石 = **1 个掉落物实体、64 个物品**。排行优先按实体数量降序，同数量按物品总数降序。
- 只统计 `ItemEntity` 及其子类，不统计经验球、箭、容器内物品或模组自定义的非物品实体。
- 覆盖所有服务器维度，统计当前**已加载、实体可访问**的掉落物，包括不在玩家当前维度的区块；不读取卸载区块的存档，不触发区块加载。
- 按掉落物实际位置划分区块，正确处理负坐标和边界；例如方块 X=-1 属于区块 X=-1，而不是 0。统计覆盖区块全部高度。
- 排行显示区块坐标和一处掉落物位置；明细显示 XYZ，聊天显示三位小数，CSV 和传送建议保留完整 double 精度。
- 每次指令重新采集快照，期间不会等待或修改实体；各次查询间物品可能合并、移动、被拾取或自然消失。
- 只在执行指令时工作，没有常驻计时扫描、自动清理、实体上限或第三方模组依赖。全服扫描复杂度随已加载实体总数增加，繁忙服务器不宜高频执行；大报告的同步导出也会占用本次服务器线程时间。

## CSV 报告

报告保存到**服务器运行目录**的 `reports/chunkdrops/chunkdrops-<UTC时间>-<唯一后缀>.csv`，完整路径会通过指令反馈。
UTF-8（含 BOM），可用 Excel / 文本编辑器打开；每次生成新文件，不覆盖旧报告。无掉落物时仍生成列头。

字段：`dimension,chunk_x,chunk_z,entity_uuid,item_id,item_count,x,y,z`。

不导出物品 NBT 或玩家信息。物品名称可能受服务端语言环境影响，因此报告使用稳定的物品注册 ID；CSV 不包含可由玩家自定义的物品名称。

## 构建与测试

安装 Java 17 后，在本目录执行：

```powershell
.\gradlew.bat build
.\gradlew.bat runGameTestServer
```

产物：`build/libs/ft-chunk-drops-forge-1.20.1-1.0.0.jar`。`reobfJar` 会自动执行，正式 JAR 不包含测试类。
GameTest 在本工程的 `gametest-run` 中创建独立测试世界，不使用正式存档。
