# SDMShop 服务端审计 1.0.0

独立的 Minecraft 1.20.1 Forge 服务端 MOD，只监视 SDMShop 修改、购买和出售；不封禁、不阻止交易、不恢复商店，不依赖或修改 FTBoss。客户端不需要安装。

## 安装

1. 停止服务器，备份商店配置和存档。
2. 将 `sdmshop-server-audit-forge-1.20.1-1.0.0.jar` 放入**服务端**的 `mods` 文件夹，再启动服务器。保留原有 SDMShop 与其前置，不用替换商店 JAR。
3. 在控制台或 OP 账号执行 `/sdmaudit status`。正常应显示“仅监视”和日志目录，文件错误、钩子错误应为 0。启动日志中应有 `SDMShop audit active`、`14 hooked classes`。
4. `/sdmaudit snapshot` 手动记录当前商店取证快照，不会修改或恢复任何商品。

适用：Forge 1.20.1、SDMShop Rework `1.20.1-6.11-pre`。集成测试使用 Forge 47.4.10，以及本地 `[SDM商店修复版]sdmshoprework-forge-1.20.1-6.11-pre-max1024-fixed-ft-editor1.jar`、Architectury 9.2.14、FTB Library 2001.2.12、SDM Economy 1.7.2、SDM UI Lib 1.8.3。依赖由原商店提供；审计 JAR 不内嵌这些 MOD。不要把此 Forge JAR 用于 NeoForge、其他 Minecraft 版本或不同 SDMShop API。

## 固定原版商店基准

“原版”指用户指定的 fix2 整合包商店，不是仅允许 Minecraft 原生物品：

`C:\Users\YOUR_USERNAME\AppData\Roaming\.minecraft\versions\FarmingTales_ForgeⅡ v1.5.2fix2\config\SDMShop\sdmshop.snbt`

- 基准 SHA-256：`e4f5e1d25d41282b8868f1fab8757452e49c83677d25dbe260a6edc8b9490739`。
- 27 个分页，1050 个购买条目，1005 种去重后的商品身份，865 种物品注册 ID。
- 只把可购买条目的真实商品作为基准。出售条目、分页图标、商品图标不加入白名单。例如作为图标的 `minecraft:barrier` 不因此获得购买许可。
- 基准原文内嵌在审计 JAR 中，不从服务器启动时的现状自动学习，避免把已被玩家改过的商店误认为正常基准。安装后不依赖桌面路径，也不改写原配置。
- 普通物品比较注册 ID 与完整商品 NBT，保留 NBT 类型；同 ID 的额外附魔、属性、改名或其他 NBT 变体也可能不在基准内。忽略堆叠 `Count`，忽略价格、购买数量、分页、条目 UUID；空 `tag` 与空 `ForgeCaps` 视为缺省。
- 指令等非普通物品商品比较商品类型与完整 `entryType` 数据，不会把图标当作实际发放物品。
- 基准内已有的合法 NBT 变体允许购买。调整合法商品价格不会触发“非原商店物品”警告，但修改操作仍记录在修改日志中。
- 管理员故意增加新的商品/NBT 变体后，仍会被固定基准告警；需要审查新基准并重新构建，不会自动放行。

交付目录附有 `原版物品ID清单.txt`、`原版购买商品明细.json` 和 `原版商店摘要.json`，分别用于查看物品 ID、逐分页的商品类型/NBT/原价/数量、基准统计。ID 清单仅便于查看，不代替 JAR 内的 ID+NBT 校验。

## 非原商品购入警告

只有 BUY 请求经过原商店的购买执行方法、方法正常返回、且捕获到所有付款回调均接受时，才记 `SUCCESS`。随后检查购买前的商品定义；不在固定基准中的成功购入，每个请求写一条 `non_original_purchase_warning`。

警告同时写入服务器 WARN 日志、独立 `*-warnings.jsonl` 和每日人类可读日志。记录玩家名、UUID、OP/编辑模式、时间、维度/坐标、分页/条目 UUID、商品类型与 ID、购买批数/物品数量、价格、付款结果及余额变化、商品 NBT、基准哈希和原因。

例：

```text
[非原商店物品购入警告] 玩家=Example UUID="..." 商品=minecraft:dirt 数量=1 原因="ITEM_NOT_IN_OFFICIAL_SHOP" request=...
```

原因：

- `ITEM_NOT_IN_OFFICIAL_SHOP`：此物品 ID 不是 fix2 原商店的购买商品。
- `UNAPPROVED_ITEM_NBT`：ID 是原商店物品，但当前商品 NBT 不是任何原版允许的变体。
- `PRODUCT_TYPE_OR_PAYLOAD_NOT_IN_OFFICIAL_SHOP`：其他商品类型或其数据不在基准中。

余额不足、物品货币不足、无效数量、条件/限购拒绝以及出售都不会触发成功购入警告。它们仍写交易请求和结果。没有付款回调、付款拒绝、执行报错或执行中断分别使用未验证/拒绝/错误/中断状态，不冒充成功。

`SUCCESS` 依据 SDMShop 的执行完成与付款接受，不能替代对所有自定义指令/外部 MOD 最终效果的逐项验证。警告说明“此玩家买到了基准外的商品”，不单凭此判断该玩家就是修改者；应结合对应的修改记录追查。

## 独立日志

所有路径相对于**服务端根目录**，按配置时区的日期分文件；默认 `Asia/Shanghai`：

```text
logs/sdmshop-audit/
  YYYY-MM-DD-edits.jsonl          编辑请求、结果、变化和快照索引
  YYYY-MM-DD-transactions.jsonl   购买/出售请求、结果和付款信息
  YYYY-MM-DD-warnings.jsonl       成功购入非原商品的 WARN 记录
  YYYY-MM-DD-system.jsonl         启停、已应用钩子、固定基准摘要
  YYYY-MM-DD.log                  中文摘要，便于直接阅读
  snapshots/<SHA256>.snbt.gz      完整商店、编辑负载、交易商品前后的压缩取证快照
```

JSONL 每行是一个独立 JSON 对象，使用 `session`、`sequence` 和 `requestId` 关联同一服务器会话及请求。人类可读摘要转义换行、制表符和 ESC，避免玩家输入伪造日志行。中文文件为 UTF-8。

修改记录覆盖 9 种客户端编辑消息：创建分页/条目、整体商店变更、分页变更、分页条目批量变更、编辑分页/条目、移动分页/条目。记录请求玩家、权限/编辑模式、前后哈希、分页/条目新增删除移动与字段变化、原值与新值。非 OP 请求造成实际修改时，控制台额外发出 WARN。

定期扫描和商店保存后观察内存中的商店状态，补录其他途径的变化。无法关联玩家的变化标记 `UNKNOWN`，不猜测责任人。直接改磁盘但未加载进内存的配置变更不属于该扫描的检测范围。

快照按内容哈希去重；摘要限制差异数量和大字段长度，开启快照时完整数据保留在压缩文件。交易中的 `entryBeforeHash`、`entryAfterHash` 指向完整商品定义快照，可以查看未被摘要截断的 NBT。快照保存失败时仍尝试写操作记录，并在 JSON 中标记 `snapshotErrors`，同时控制台报错。磁盘/目录完全不可写时无法保证持久化，请监控状态命令中的文件错误。不要关闭快照后仍期望拥有完整大字段的历史版本。

写入使用有界单线程队列，满队列由调用线程写入，不静默丢弃；极端洪泛/慢磁盘可能拖慢服务器。正常停止等待写入队列，强制结束进程或掉电仍可能丢失尚未落盘的数据。日志和快照不自动删除，请留出磁盘空间并按需备份、归档。

## 配置

首次启动生成 `config/sdmshop-audit.toml`；修改后建议重启：

```toml
scanIntervalTicks = 200
maxInlineChanges = 200
saveSnapshots = true
timeZone = "Asia/Shanghai"
```

扫描默认每 200 tick（服务器正常 20 TPS 时约 10 秒）；直接编辑消息不是等到下一次扫描才记录。时区必须是有效的 Java 时区名称。

本工具只记录安装并成功启动之后的行为，不能恢复此前日志中没有记录的历史购买，也不是权限修复或防篡改补丁。备份服务器世界和商店配置仍然必要。

## 构建与测试

使用 Java 17 或 21、Gradle 8.8、ForgeGradle 6.0.54。主代码以 Java 17 字节码发布；主构建不需要私有 SDMShop 编译依赖。

```text
gradle --offline build
gradle --offline -PauditSmoke runGameTestServer
```

离线构建要求 Gradle/Forge 依赖已缓存。烟雾集成测试需要将原 MOD 复制到 `compat-libs` 并命名为 `sdmshoprework-6.11-pre.jar`、`architectury-9.2.14.jar`、`ftb-library-2001.2.12.jar`、`sdm-economy-1.7.2.jar`、`sdm-ui-lib-1.8.3.jar`。这些依赖不在发布 JAR 中。测试仅在 `run-audit-gametest` 的独立服务器运行，不使用真实存档；测试 MOD 也不进入发布 JAR。

`verifyAudit` 检查差异、64 位价格、交易状态、并发无丢行、UTF-8/日志注入、快照往返、快照失败保留操作记录。GameTest 调用真实 SDMShop 消息与付款代码，检查修改、金币购买/出售、物品货币、非法数量、余额不足、异常处理、非原商品和 NBT 变体告警，并校验所有 1050 个基准购买条目均被允许。

发布实包测试：先构建，将生成的 JAR 复制到 `compat-libs`，再运行 `gradle --offline -PauditSmoke -PauditJarSmoke runGameTestServer`。这一步加载发布 JAR 而不是主代码输出目录，检查 manifest 自动加载 Mixin、真实交易记录与商品快照；开发环境由 ForgeGradle 对发布包做映射转换。它不等于在用户完整服务端整合包中完成稳定性验证。
