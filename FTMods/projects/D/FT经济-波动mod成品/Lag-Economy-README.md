# FarmingTales 独立卡顿经济与区块限产

成品：`qys-lag-economy.jar`，Mod ID：`ftlagcontrol`，版本 1.0.0。

适配 Minecraft 1.20.1 / Forge 47.4.10、当前整合包的 KubeJS 2001.6.5-build.16、农场物语原生调度 1.0.11-kubejs、Create 6.0.8、Observable 4.4.2。
这是独立服务端逻辑模组，不合并进 Boss 模组，不打包税收模组或任何依赖。客户端不需要另装本模组；边界使用原版粒子。

## 收入：三个独立乘区

单件结算价 = 整合包原始单价 × 原有堆量行情倍率 × 财富商品倍率 × 卡顿倍率。

单件结果小于 1 时直接记为 0，再乘数量。64 件单价 0.5 的商品也只结算 0，不能凑整规避。
单件结果大于等于 1 时保留小数，沿用原出货箱对总金额四舍五入，避免无关的逐件向下取整损失。
零价商品仍被正常售出、扣除并计入市场销量；在线所有者收到零收入提醒；同日不会重复结算。
没有有效所有者的出货箱暂停结算并保留商品，先按整合包原有方式绑定箱主，防止使用无主箱绕过财富分档。
不扣已有存款，不追缴既有库存。

卡顿评级取 `min(实际 TPS, 1000 / 实际 MSPT)`，每 200 tick 更新一次；恶化立即进入下一档，恢复要连续 3 个窗口。

| 有效 TPS | 最高财富档卡顿倍率 |
| --- | --- |
| 大于 15 | ×1.00 |
| 12 < TPS ≤ 15 | ×0.70 |
| 10 < TPS ≤ 12 | ×0.40 |
| TPS ≤ 10 | ×0.10 |

其他财富档按 `1 - 本档降幅 × 财富比例` 缩放，最贫档不受这一乘区影响。×0.10 是**卡顿乘区下限**，不是三个乘区相乘后的收入保底。

参考提供的 qys-progressive-taxation 1.0.0：

- 财富门槛：0 / 1万 / 10万 / 100万 / 1000万 / 1亿，对应财富比例 0 / 0.2 / 0.4 / 0.6 / 0.8 / 1。
- 财富依据取累计销售收入与 SDM 当前余额的较大值；在线读取 SDM API，离线读取 SDM 已载入的服务器余额表，并缓存自己的销售账本。
- 旧累计收入兼容 `ftEconTotal`、`ft_econ_total`、`ftEconIncome`、`fteconTotal`；离线玩家首次结算可从玩家存档读取这些字段。
- 商品原价分档 ≤10 / ≤30 / ≤80 / 高价，因子分别 0.30 / 0.65 / 0.80 / 1.30。
- 商品倍率为 `1 + (商品因子 - 1) × 财富比例`；低价商品沿用高财富档额外压价和 ×0.30 保底。
- 若存在有效 `config/ftecon-config.json`，读取其中的财富与商品分档；不调用旧模组把最终单价强制保底 1 的函数，也不重复追加旧税。
- 堆量行情沿用现有出货箱的 `(100 - discount + boost) / 100`；不擅自打开或重置整合包的市场开关和销量。
- 仅接管本整合包出货箱的金币入账、离线箱内金币、主动箱内金币三条路径；不改任务奖励、玩家转账、其他商店收入。

例如最富档在 TPS ≤10 时，原价 1000、堆量降价 60%、高价商品因子 1.3：单件收入为 `1000 × 0.4 × 1.3 × 0.1 = 52`。

## 区块产出限制与冻结

以**单个区块平均每服务器 tick 的耗时**为依据，不是全服 MSPT，更不是将 ns 误当 μs。

| 区块耗时 | 默认行为 |
| --- | --- |
| <500 μs/tick | 不限制 |
| 500 μs/tick | 黄色边界，随机没收约 25% 新产出 |
| 1000 μs/tick | 黄色边界，约 50% |
| 1500 μs/tick | 黄色边界，约 75% |
| 2000～不足2500 μs/tick | 黄色边界，没收全部新产出，但不冻结 |
| ≥2500 μs/tick，连续两次有效采样 | 红色边界，冻结机器工作 |

区间内线性变化，按每批产出做随机舍入，单个产物也有概率被没收。大量物品/流体不逐单位循环抽签。
冻结阈值可上调，但代码硬下限为 2500，配置不能将其降到 2500 以下。

- 自动计时固定机器的真实 tick、农场物语 NativeMachineScheduler 回调和魔法木桶收割任务，弥补 Observable 看不到整合包日常生产调度的部分。
- 安装 Observable 时自动接收每次完成的原始报告，合并实体和方块实体到对应维度区块。`rate(ns) × entryTicks / profileTicks / 1000` 换算为 μs/tick。少于100 tick的报告不用于处罚。
- Observable 分析在后台进行，处罚返回服务器主线程；不会自动开启 Observable 性能采样，也不需要上传报告或安装之前的报告器。可与独立 Observable 报告器并存。
- 外部报告的黄色限制最多保留2分钟，没有新的高耗时证据会解除；持续冻结不受这个期限影响。相同报告对象不会重复计为两次冻结证据。
- 每次首次限产、升级冻结或管理员解除，向全服广播维度、区块 X/Z 和实际方块坐标范围。
- 黄色限制可以随新采样恢复；**红色冻结写入世界存档，即使 TPS 恢复、区块卸载、服务器重启也不会自动解除**。

## 产出保护与兼容范围

- 农场物语树液采集器、鱼塘、蟹笼及其原生生产回调；Create 固定方块实体机器；原版熔炉/高炉/烟熏炉。
- 作物的玩家破坏和自动收割掉落；跨区块收割也检查作物所在区块，不能用隔壁的正常机器绕过。
- 物品处理检查加工前后的新增量，保留已有输入、燃料及旧库存；不会扫描删除玩家背包、普通箱子、物品仓库或储液罐。
- 流体处理检查新的流体增量；Create 搅拌盆另在配方输出阶段拦截物品和流体，模拟容量检查不扣产物，隔壁搅拌器不能加工冻结的盆。
- Create 机械臂在每次实际取到新物品后处理新增持有量，不会每 tick 重复扣除；机械手/传送带加工另拦截配方结果，冻结的加工器也不能被相邻传送带调用。
- 树液采集器在产出建立时处理没收。整批被没收后重新开始完整生产周期，堵住“成熟状态不断补发产物”的问题。
- 冻结时禁止右键操作受管控生产机器，防止交互路径继续触发加工；不禁用普通存储箱。
- 管理员解除后，已知日历型机器重置生产日计时，防止鱼塘/蟹笼/树液采集器将冻结期间积累成追补产出。旧库存不清空。
- 针对普通 Forge 能力库存最多检查512槽、32个流体槽，防止管控功能本身产生无界开销。

范围说明：这是生产机器管控，不是暂停整个区块的世界模拟；玩家、生物、普通容器和流体方块自然流动不会被冻结。
移动装配体（列车、轴承上的移动机械）及第三方模组私有/异步产出接口不在这一版固定工作方块适配范围，不能据此宣称所有附属模组都已覆盖。

## 管理员命令

需要 OP 等级2，或从控制台执行：

```text
/lagcontrol
/lagcontrol list
/lagcontrol release minecraft:overworld -1 -2
/lagcontrol release minecraft:the_nether 12 34
```

参数是**区块坐标**，不是方块坐标；方块坐标除以16并向负无穷取整。`-1,-2` 区块对应方块 X=-16..-1、Z=-32..-17。
解除同时清除该区块限制与处罚计数，并给予默认600秒保护期。保护期后仍严重卡顿可以再次触发，须真正减少机器负载。
`/lagcontrol list` 最多列50条。冻结存档位于世界的 `data/ftlagcontrol.dat`。

配置：`config/ftlagcontrol.toml`，包括限产起点、100%没收线、冻结线、采样窗口、冻结连续样本数、解除保护期和边界粒子开关。
`enabled=false` 停止新增经济/黄色处罚与新的自动冻结，但不会隐式解冻已经封锁的区块，既有红色冻结仍须管理员解除。

## 安装与验证

退出游戏/停止服务器后将成品放进服务端 mods，再重启。不要热替换。
无需额外安装原税收 jar；保留原税收/行情配置与原脚本文件。出货箱、树液脚本只在 KubeJS 加载时做内存适配，不改磁盘上的整合包脚本。
对当前脚本的关键结构做严格检查，遇到不兼容版本会明确报错而不是默默使用错误价格。升级整合包后先检查 `/lagcontrol` 的桥接状态和 KubeJS 启动日志。

构建使用 Java17 / Gradle8.8。`gradle build runGameTestServer` 包括纯规则检查和加载真实 Observable、Create、KubeJS、农场物语模组的专用服务器测试。
测试在独立临时世界执行，使用当前整合包出货箱/树液脚本的只读快照；不打开用户存档。
成品不包含测试、脚本快照或依赖 jar。部署工具比对源文件 SHA256、成功构建日志和实际模组测试结果，并拒绝在 Minecraft 运行时替换。
