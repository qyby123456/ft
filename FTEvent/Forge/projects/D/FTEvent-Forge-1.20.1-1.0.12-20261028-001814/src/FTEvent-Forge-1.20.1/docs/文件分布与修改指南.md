# 文件分布与修改指南

唯一维护工程：`D:\ft工程文件\QYS-Event-Forge-1.20.1`。不要在历史单次交付目录中继续修改，然后误装旧 JAR。

## 游戏里实际生效的文件

| 位置 | 用途 | 修改后生效方式 |
| --- | --- | --- |
| `mods/qys-event-forge-1.20.1-1.0.11.jar` | Java 抽奖逻辑、许愿井商店界面、契约成就、默认配置和内置手册 | 重启游戏/服务器 |
| `config/qys_event/wishing_well/gold_pot_coins.json` | 六档金币权重，最常用的调参文件 | 保存后下一批金币锅生效 |
| `kubejs/server_scripts/block_events/wishing_well.js` | 升级、结构、付款、奖励倍数与实际发奖 | 本次安装后重启 |
| `kubejs/client_scripts/tooltips/wishing_well.js` | JEI/物品提示 | 重启客户端 |
| `kubejs/WISHING_WELL.md` | 多方块结构与当前奖励阅读入口 | 文档，不执行 |
| `config/qys_event/README.md` | 配置目录中文入口 | 文档，不执行 |

只换 JAR 而不更新服务器脚本，旧脚本仍会把新金币乘三倍，期望就不再是 9000。正式更新必须一起替换这两类文件。

## 按需求找文件

- 改许愿井商店布局、文字与绘制：`client/WishingWellShopScreen.java`、`client/WishingWellShopLayout.java`、`assets/qys_event/lang/`。
- 改庄园购入门槛：服务器脚本 `ftwwManorShopUnlocked`、`ftwwQueuePurchase`、`ftwwPurchase`；获取记录与登录补发见 `wishingwell/ManorShopAccess.java`，成就定义见 `data/qys_event/advancements/crimson_contract.json`，可选物品标签见 `data/qys_event/tags/items/crimson_contract.json`。
- 重绘商店背景：`tools/draw-wishing-well-ui.py`，使用 Pillow 生成 `assets/qys_event/textures/gui/wishing_well_shop.png`；`--preview <PNG 路径> --instance <游戏目录>` 可生成布局示意图（非游戏截图）。
- 核心的五行简易提示：配套客户端 `tooltips/wishing_well.js`；潜行右键玩法简介：服务端 `ftwwShowGuide`。完整结构资料仍保留在阅读文档，不显示在核心提示中。
- 只改六档概率：游戏外置 `gold_pot_coins.json`。
- 改金币类别的 5% 或其他类别概率：`GoldPotWishRules.Category`，并更新期望计算、测试、手册和提示。
- 改矿物种类/稀有度：`GoldPotWishRules.Mineral`。
- 改一次性升级价格：配套服务器脚本顶部 `FTWW_UPGRADE_POTS`；目前为个人累计 100 锅，只有未升级/满级两档。`FTWW_LEGACY_UPGRADE_BLOCKS` 只兼容旧满级资格，不再收取绿宝石块。
- 查多人等级：`ftwwPlayerKey`、`ftwwProgress`、`ftwwSaveProgress`；存档 `kubejs_persistent_data.nbt` 中的 `ftww_progress_v1_<玩家UUID>` 为独立记录，同一玩家换井通用不等于不同玩家共享。
- 改绿宝石奖池：配套服务器脚本顶部 `FTWW_LEVEL_ODDS` 及对应奖励列表；当前仅使用索引 0/3，对应未升级/满级，中间概率行仅作历史保留。
- 改三倍、数量大奖、三菜保底：服务器脚本 `FTWW_REWARD_MULTIPLIER`、`FTWW_JACKPOT_CHANCE`、`FTWW_MIN_FOOD_VALUE`；金币锅金币是明确例外。
- 改天气与事件：现有天气 Java 文件与 `worldevent/`，与本轮金币调整无关。

当前手册以 `docs/` 为可编辑原件，`tools/build.ps1` 构建时同步到 `src/main/resources/docs/`。旧研究报告保留为参考，不代表当前许愿池。NeoForge 是独立工程，不在此次更新范围。
