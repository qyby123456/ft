# 许愿井：一组绿宝石块解锁

Event Forge 1.20.1 / 1.0.8。替代新玩家原先累计 100 个金币锅的升级方式。

## 正式规则

- 每名玩家累计投入 **64 个 `minecraft:emerald_block`**，直接升至 Lv.3，永久解锁许愿井商店和金币锅许愿。进度按 UUID 保存，可分次支付。
- 完整多方块许愿井中，手持绿宝石块右键核心投入 1 个；潜行右键投入整叠；也可把自己的绿宝石块丢入井水。只扣还差的数量，多余物品保留。
- 未解锁前金币锅不扣除，也不能靠金币锅升级。水中被拒绝的金币锅需解锁后重新投入，不会自动在稍后扣费。
- 解锁后从**第一个金币锅**开始，每锅独立抽奖一次；支持右键、潜行右键整叠和丢入井水。不再需要额外捐献 100 锅。
- 升级成功会尝试打开商店，也可空手右键核心打开。背包被商店界面临时捕获期间，不消费水中的金币锅；关闭界面、原生背包恢复后再处理。
- 普通绿宝石许愿保留，累计次数独立保存，不折算成升级块。绿宝石有用物品概率为未升级 31.1%、满级 80%。
- 旧存档中累计金币锅达到 100 的玩家保留原有商店及金币锅权限；旧 Lv.1、Lv.2 概率加成保留，仍可投入绿宝石块直接升满级。不会修改或清空旧记录。

## 不变内容

- 非庄园召唤物每件 1 个金币锅；随机庄园武器 5000 万 SDM，排除万味胚刃；随机庄园法术卷轴 500 万 SDM，不含常规铁魔法。
- 金币锅池：铁魔法 15%、食物 30%、金币 5%、晶球 15%、矿物块 25%、技能经验 9.965%、庄园战奖励（武器/唱片/法术合计）0.035%。矿物稀有度子池和灾变三种块不变。
- Event 仍独立于 Boss，未修改 Boss、天气配置、其他模组或 NeoForge 实例。三个核心的四向放置保持。

## 实现与验证

服务器脚本实际校验 `emeraldBlocks` 和解锁状态；原生 `GoldPotWishes.rollUnlockedRewards` 不再计算旧百锅门槛，委托原奖池生成每锅奖励。旧入口保留以兼容二进制引用，但新脚本不调用它。保存失败回退物品，不开放商店或发奖；奖励生成失败不扣锅。购买仍在关界面、原生背包恢复后才扣费和插入物品。

运行 `node project/docs/wishing_well.behavior.test.js` 验证正式右键、实体投放、持久化、首锅/整组抽奖、满包掉落和原有商店/背包恢复回归。夹具来自不可变 1.0.7 测试文件；最新套件保留非奖池范围的商店回归，原通用法术的购买断言由新的庄园专属范围、价格和 NBT 测试覆盖。新原生 API 用独立模拟器记录参数；实际 JAR 的纯 Java 签池验证和 `javap` 调用检查另行验证，不能代替进游戏测试。

最新套件的 `--baseline` 指向本轮庄园商店修正前的 1.0.8 脚本，用于证明通用法术池不符合庄园商品要求；升级规则仍由正常回归覆盖。64 次整组奖励携带不同 NBT，因此 36 槽背包只能容纳 36 件，其余明确掉落，测试同时核对两者总量。

构建与自动化验证不启动客户端，不打开或修改世界存档。实际游玩表现仍需重启游戏验证。
