# 三级金币锅许愿

个人累计投入 1、10、100 个金币锅解锁一级、二级、三级。第 100 个只用于升级，第 101 个起每锅独立抽奖一次；批量跨过门槛时只有超出的部分抽奖。沿用完整多方块许愿井，支持右键、潜行右键整组以及丢入内圈水中。

| 类别 | 概率 | 内容 |
| --- | --- | --- |
| 铁魔法 | 15% | 1 张已启用且允许战利品的 Iron 卷轴，合法等级最高 3 级，排除庄园法术 |
| 食物 | 30% | 1～3 个随机农夫乐事料理或南瓜派 |
| 钱 | 5% | 1～9 个金币袋，每袋 100 金币 |
| 晶球 | 15% | 1 个普通晶球 |
| 矿物块 | 25% | 按稀有度抽取下表中的矿物块，每次 1～2 个 |
| 技能经验 | 9.965% | 六种技能中随机 1 本经验书，使用后增加对应技能 250 经验 |
| 庄园战奖励 | **0.035%** | 从真实庄园战胜利奖励池中随机取 1 件武器、法术卷轴或唱片，保留 NBT |

全部庄园战奖励合计占 100000 个等概率整数签中的 35 个，而非每种或每件各占 0.035%。庄园奖励继续调用 Boss 的 ManorVictoryLoot.contents()，该目录同时包含武器、唱片、法术，目录中的每件有效物品等概率，不强行令三种类型各占三分之一。普通铁魔法限制在 Iron 命名空间，避免庄园法术通过普通奖池出现。

庄园战奖励从 0.01% 提高到 0.035%，增加的 0.025 个百分点全部从技能经验书扣除；其他一级类别概率不变。没有次数保底。

钱的直接返还期望为 5% × 5 袋 × 100 = **25 金币/锅**，即 10000 金币投入的 **0.25%**，不计其他物品出售价值。

## 实现与兼容

- Event 的 GoldPotWishRules 管理概率、升级门槛与期望值；GoldPotWishes 用服务器随机源生成奖励。
- KubeJS 的 wishing_well.js 仅接入已有升级存档、结构检查、金币锅消费及发奖。绿宝石许愿和三级商店不变。
- 奖励全部提前生成、校验，成功后才扣除金币锅；依赖或物品缺失时不扣费、不另抽类别。
- 普通金币返回金币袋；技能经验返回现有经验书，沿用经济与技能脚本，不绕过其规则。
- 基于 2026-10-14 独立最终源码完整构建 Event 1.0.7，保留该基线的四向模型、放置和旋转修复，不把 Event 合入 Boss。
- 跨级抽奖先发奖励，再自动打开三级商店，避免原生背包捕获/恢复覆盖升级奖励；背包放不下的奖励仍走 KubeJS 原生掉落。
- 本批只在新的 D 盘目录生成源码和候选包，不修改原封存导出、实例脚本、Boss、NeoForge 或存档；Event 保持禁用。
