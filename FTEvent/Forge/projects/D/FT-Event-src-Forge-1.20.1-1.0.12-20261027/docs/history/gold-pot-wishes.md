# 三级金币锅许愿

个人累计投入 1、10、100 个金币锅解锁一级、二级、三级。第 100 个只用于升级，第 101 个起每锅独立抽奖一次；批量跨过门槛时只有超出的部分抽奖。沿用完整多方块许愿井，支持右键、潜行右键整组以及丢入内圈水中。

| 类别 | 概率 | 内容 |
| --- | --- | --- |
| 铁魔法 | 15% | 1 张已启用且允许战利品的 Iron 卷轴，合法等级最高 3 级，排除庄园法术 |
| 食物 | 30% | 1～3 个随机农夫乐事料理或南瓜派 |
| 钱 | 5% | 1～9 个金币袋，每袋 100 金币 |
| 晶球 | 15% | 1 个普通晶球 |
| 矿物块 | 25% | 1～2 个煤、铜、铁、红石、青金石、金、钻石或绿宝石块 |
| 技能经验 | 9.99% | 六种技能中随机 1 本经验书，使用后增加对应技能 250 经验 |
| 庄园战奖励 | **0.01%** | 从真实庄园战胜利奖励池中随机取 1 件武器、法术卷轴或唱片，保留 NBT |

全部庄园战奖励合计占 10000 个等概率整数签中的 1 个，而非每件各占 0.01%。普通铁魔法限制在 Iron 命名空间，避免庄园法术通过普通奖池出现。

钱的直接返还期望为 5% × 5 袋 × 100 = **25 金币/锅**，即 10000 金币投入的 **0.25%**，不计其他物品出售价值。矿物类别内部权重按上表顺序为 25、25、20、12、8、6、3、1，总计 100。

## 实现与兼容

- Event 的 GoldPotWishRules 管理概率、升级门槛与期望值；GoldPotWishes 用服务器随机源生成奖励。
- KubeJS 的 wishing_well.js 仅接入已有升级存档、结构检查、金币锅消费及发奖。绿宝石许愿和三级商店不变。
- 奖励全部提前生成、校验，成功后才扣除金币锅；依赖或物品缺失时不扣费、不另抽类别。
- 普通金币返回金币袋；技能经验返回现有经验书，沿用经济与技能脚本，不绕过其规则。
- 仅追加新增的 wishingwell 包到当前已部署 Event JAR，保留其余类与资源，避免旧规范工程覆盖后续四向模型/放置修复。

## 验证

构建执行 build 与 verifyQysEvent，穷举全部 10000 个签、升级/批量边界及金币期望；docs/test-gold-pot-bridge.cjs 检查脚本消费、发奖和失败不扣费。未自动启动游戏或修改存档。
