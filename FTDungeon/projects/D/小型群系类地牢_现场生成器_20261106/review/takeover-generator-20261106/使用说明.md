# 小型群系类地牢生成器：隔离实验使用说明

本说明对应显式命令生成器。最终可复现版本由同目录的交付索引绑定；组件
ready 只表示组件可消费，完整世界验收以最终独立报告为准。所有操作在新的
独立 Forge 服务端目录进行，正式玩家实例不在本次交付的安装范围内。

## 环境与房间范围

- Minecraft Java 1.20.1，Forge 47.4.10，Java 17；服务端仅装本候选模组。
- 实际完整池为八间原字节房间，加一间有明确变更账本的派生入口，共九间。
- 派生入口保留原家具、方块实体、台阶和高差，中央改为三宽三高拱洞；原相邻
  双门完整移到侧通道。侧双门只能关闭侧通道，不能封闭中央主拱。
- `accepted=false`、`productionPromotion=false` 与隔离作业功能状态分开记录。
  正式实例接入、其他模组兼容和网络客户端 UI 不属于已自动放行的范围。

## 安装与启动

新建一个位于本工程内部、名称唯一的服务端目录。使用已核验的官方安装器
`review/forge-1.20.1-47.4.10-installer.jar`，SHA256 为
`1912760b4cb6b803d8a826de603c9076b1da71ec2765e9a1f8c1ca78f65278e3`。
在新服务端目录作为工作目录，以 Java 17 执行安装器的 `--installServer`。
将最终交付索引指定的精确候选 JAR 放入这个新服务端的 mods，核对其 SHA256。

首次创建世界前，在新服务端根目录保存下列 `server.properties`。这是本机控制台
隔离回归配置：端口 0 不提供固定客户端端口；若另行进行客户端测试，应记录
实际端口与认证配置。世界种子由此配置指定，`plan` 末参数只是 ordinal。

```properties
server-ip=127.0.0.1
server-port=0
online-mode=false
level-name=world
level-seed=267611119455246637
view-distance=2
simulation-distance=2
spawn-protection=0
```

首次启动前创建 `world` 目录，并写入文件
`world/ALLOW_CANDIDATE_EVIDENCE_WORLD_V5`，内容必须准确为：

```text
PARENT_AUTHORIZED_EIGHT_ORIGINALS_ONE_DERIVED_V5_EVIDENCE_ONLY
```

实际世界根目录及其父路径必须是规范真实路径，不能位于 `.minecraft` 内或经过
链接、目录重定向；`world.toRealPath()` 必须等于其规范绝对路径。
保留原生 `randomTickSpeed=3` 与 `doFireTick=true`。在核准 EULA 后，以 Java 17
启动 Forge 安装器生成的参数文件；始终以新服务端目录作为当前工作目录。
Windows 对应命令为（外部复现时替换为本机 Java 17 的绝对路径）：

```powershell
& 'C:\Users\YOUR_USERNAME\AppData\Roaming\.minecraft\runtime\java-runtime-gamma-snapshot\bin\java.exe' '-Xmx2G' '@libraries/net/minecraftforge/forge/1.20.1-47.4.10/win_args.txt' 'nogui'
```

## 生成与观察

服务器控制台使用以下命令；游戏内命令有 `/` 前缀，并要求权限等级至少 2。
完整测试请求使用种子 `267611119455246637`、锚点 `(1000,200,1000)`；ordinal
0、1、2、3 对应入口四朝向，分别在不同新世界测试，末参数相应替换。已生成
世界修改 `level-seed` 不会改写存档种子；应核对 `acceptance-context` 返回的
`worldSeed` 为 `267611119455246637`、`dimension` 为 `minecraft:overworld`。
不要在已占用区域施工。每个报告记录世界真实路径、实例、锚点、ordinal 和 context。

```text
ftbiomedungeon_candidate plan 1000 200 1000 s8 9 3
ftbiomedungeon_candidate inspect <instanceId>
ftbiomedungeon_candidate build <instanceId> CONFIRM_ISOLATED_AIRSPACE
ftbiomedungeon_candidate status <instanceId>
ftbiomedungeon_candidate evidence <instanceId>
```

`plan` 为 dry-run，返回实例 ID 和真实房间级布局；`build` 在完整预检通过后分批
施工。候选使用真实门口脚高、九房各一次规划、原生方块实体与保存区块，施工
日志按尝试范围、区块持久化和已确认完成前缀记录。自然刻观察保留熔岩及藤蔓。

施工完成后，预期先进入 `VERIFYING` 与
`PAYLOAD_VERIFIED_ROUTE_INTERACTION_ACCEPTANCE_PENDING`。这表示载荷验证完成，
尚未自动认定完整路线与交互验收通过。可用 `routeaudit <instanceId>` 获取实际
房间的原生路径诊断；诊断不取代独立完整矩阵与全图验收。

## 暂停、重启与故障

```text
ftbiomedungeon_candidate pause <instanceId>
ftbiomedungeon_candidate list
```

暂停及重启不自动续建。再次 `build` 需要原显式确认并重新预检。遇到未知物品、
已完成格被更改、坏日志或保护冲突时，会拒绝操作或进入 `ROLLBACK_REQUIRED`；
应保留原日志与存档供检查，不清空箱子、不删日志、不强制覆盖来凑通过。
进程强杀测试不等于断电耐久性证明。

## 独立证据与显式完成

```text
ftbiomedungeon_candidate acceptance-context <instanceId>
ftbiomedungeon_candidate commit <instanceId> <evidenceSha256> CONFIRM_INDEPENDENT_EVIDENCE_COMMIT
```

完成凭据绑定精确 JAR、manifest、规划与操作摘要、世界种子/维度/真实路径及
当前 challenge。独立执行者必须先完成门槛、封存报告，将凭据放在该世界的
`candidate-acceptance/<instanceId>.json`，报告放在 `candidate-acceptance/reports/`
目录，再由显式命令提交；缺门槛或绑定错误
应被拒绝。不能复制别的实例凭据、把模板改为 PASS，或使用制作方自测代签。

完整凭据通过后，仍会重新预检与读回，保存区块后才写入隔离作业 `COMMITTED`。
候选池 accepted 与生产放行状态不会随之自动提升。最终独立报告必须包含真实
提交、停止、再次 JVM 启动及保存区块回读结果。

## 完成凭据的精确格式

凭据使用 UTF-8，顶层键必须恰好为 `schema`、`binding`、`gates`、`reports`、
`unresolvedBlockers`、`independentExecutor`、`purpose`。`schema=1`，
`purpose=ISOLATED_EXPERIMENTAL_JOB_COMMIT_ONLY`，`independentExecutor` 非空，
`unresolvedBlockers` 为空数组。只有实际独立证据全部通过后才可以填写通过值。

`binding` 原样使用目标世界当前 `acceptance-context` 返回的十个字符串键：
`instanceId`、`worldIdentity`、`worldSeed`、`dimension`、`runtimeVersion`、
`jarSha256`、`manifestHash`、`operationHash`、`planSha256`、`commitChallenge`。
不得增加 `worldCanonicalPath` 等键。世界真实路径应另记在报告中；路径、种子和
维度参与 `worldIdentity`。同种子不同目录可能具有相同实例 ID，却不能混用凭据。
复制或搬移世界后，必须在目标路径重新取 context 并完成对应验收。

`gates` 和 `reports` 均必须恰好包含下列十项：

```text
ORIGINAL_HASH_METADATA
INSTALLED_EXACT_ARTIFACT
SAVED_NATIVE_READBACK_RESTART
ALL_ORIGINAL_TARGETS_FOUR_ROTATIONS_RETURN
ACTUAL_GLOBAL_ENTRANCE_RETURN
FULL_DECLARED_WIDTH_CLEARANCE
NATIVE_STEP_DOOR_CONTAINER_INTERACTIONS
EXACT_SOURCE_FLUID_TICKS_RESTART
RUNTIME_PROTECTION_CONFLICT_RECOVERY
NO_UNRESOLVED_BLOCKERS
```

`gates` 每项值为 `INDEPENDENT_PASS`。`reports` 每项为只包含 `path` 与 `sha256`
的对象，路径相对于世界根目录，以 `candidate-acceptance/reports/` 开头。
路径只使用 ASCII 字母、数字、下划线、点、斜杠、连字符，不含 `..`，不能经过
重定向。SHA256 对应所引用报告的实际文件字节。凭据最多 200000 字节，每个报告
最多 16000000 字节。跨四世界的汇总报告必须明确各世界来源与当前提交实例。

先封存报告并记录摘要，再保存凭据，最后以其原始字节计算命令中的小写 SHA256：

```powershell
(Get-FileHash -LiteralPath '<凭据绝对路径>' -Algorithm SHA256).Hash.ToLowerInvariant()
```

所有命令共用权限等级 2；文件操作者还需世界目录的系统写权限。实现验证字段与
摘要，并不验证执行者数字签名；独立性由审查流程及文件权限保证。提交时必须
无活动作业、处于 `VERIFYING` 和上述 pending stage。返回 admitted 仅表示开始
完整重读，应继续轮询至 `COMMITTED`，停止后再以另一个 JVM 启动验证。

提交后保留凭据及引用报告原字节和路径，重启仍会验证它们。外部保护事件可能
撤销旧 challenge，应重新核对状态和 context。0.5.1 的 pause/commit 日志 I/O
失败会释放票据、撤销内存提交意图并停用运行时；保留现场排查，不能反复提交
或修改证据强行继续。
