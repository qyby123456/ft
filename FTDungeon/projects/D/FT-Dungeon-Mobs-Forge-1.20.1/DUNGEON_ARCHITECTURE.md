# 地牢建筑方块套件 · 第一批 24 款

版本 0.18.0，Minecraft Java 1.20.1 / Forge 47.4.10。延续现有黑暗血祭风，使用暗黑石、冷灰锈铁、骨白与少量猩红/幽青，不覆盖 0.17.0 的房间模板、原有门、火盆、血池和骷髅素材。

2026-11-04 源资源修正：封缚方棺的棺盖按两条束铁分成三段，去掉左右共四处同向共面重叠；保留原轮廓、实体并集、图集和可见面的 UV 映射。该款由 5 体块/26 面变为 7 体块/34 面；本次未替换已安装 JAR，客户端可单独加载防闪烁资源包。已核对 0.20.0 与当前 0.20.1 的同名模型和贴图一致。离线结构和软件预览不等于游戏端实测。

## 三路并行制作

此批使用三条独立进程制作线并行输出，各负责八款，最后由主进程串行合并语言、标签与注册目录，避免共享文件写入冲突。不是创建三个新的 Codex 聊天，也没有冒称由三个独立 AI 完成。`preview/worker-masonry.json`、`worker-structure.json`、`worker-decoration.json` 保存不同 PID、起止时间与各自产物。

先为柱座完成小样并审核，再并行导出。每款预算最多 16 个体块/96 面；修正后 22 款自定义几何合计 **97 个长方体、508 个导出面**，另两款楼梯/台阶运行时复用原版父模型，不以预览几何冒充其所有运行状态成本。

## 拼装规则

- 每件实际几何与碰撞均限制在自身 0～16 单格内，全部端点/尺寸/Pivot 为整数、元素旋转为 0。模型只旋转方块状态的 0/90/180/270 度，不使用斜切楔面、透明卡、圆柱或曲面。
- 常规件放置时正面朝玩家；背板类的前侧是北向基准、背板靠南面。楼梯与台阶遵循原版朝向、上下/内外角/双层及含水规则，其它件不含水、不自动连接成原版墙/栅栏。
- 柱体推荐从下到上放阶座→一到多段束纹柱→柱冠。柱身外轮廓在 2～14，阶座顶部与柱冠底部均为 2～14，避免节间突然变细；柱冠最上层回到整格宽。
- 拱券左/中/右件保持同朝向，在同高度横向排列，连到两端柱或墙。只靠三格拱顶不会自动生成支柱，不会挖开玩家墙体；可省中件组成两格小拱。拱券正面与左右标签以北向基准定义，换朝向时整组同时转动。
- 血槽为有凹陷的装饰石砖，不储存、过滤或传输流体；本批未把它加入血池结构边界标签，不改变 44 血液源祭祀识别。需要真实液体仍使用 0.16.0 的祭祀血液桶。
- 囚栏是固定镂空建筑件，不是可开关大门；铁刺不伤人，封印不触发战斗，石棺不含库存，壁灯不控制入口难度。它们不恢复旧 DSH 火炬，也不添加实体、粒子循环或怪物波次。功能扩展应另行明确设计。
- 本批不自动替换已接入房间的原版材料，不扫描/改写现有世界，不创建额外房间或维度。

## 解包参考与原创边界

只读研究以下文件的层级、材质分区和父模型复用，未拷贝模型顶点、UV、PNG 或 Java 行为。原研究库及源 JAR 没有写入；不把本地研究授权扩张为公开再分发授权。

- Goety `braced_crag_tile_pillar.json` 通过 `template_double_block.json` 组织上下柱节；实际模板为两个长方体、12 面，第二节越过单格到 Y=32。本批改为三个可独立拼装的单格柱件，不照搬越界模型。
- Goety `blackstone_brazier_unlit.json` 继承 `template_brazier.json`；模板 13 体块/78 面，存在非整数 Pivot。只借鉴底座、支撑、容器的职责分层，本批不使用其 Pivot、几何或贴图。
- Ars Nouveau `arcane_pedestal.json` 为 16 体块/96 面、64×64 图集；借鉴“宽底、收腰、顶面功能区”，不引入其功能注册、渲染层或图集。
- 与现有血池/火盆/大门保持暗石、骨白、暗红视觉语言，但新图集完全独立。`reference-audit.json` 记录原文件的尺寸、体块数、哈希，参考贴图总览仅用于本地证据，不打入交付 JAR。

## 文件与运行成本

- 可编辑源：`model_sources/dungeon_architecture/`，24 个独立 bbmodel，均含根组→主体子组、一个内嵌图集、整数 Pivot。它们是编辑用 Generic 层级，不是运行时实体骨骼动画；运行使用 Java 方块 JSON。
- 运行资源：`assets/ftdungeonmobs/models/block/dungeon_*.json` 等；共用一张 128×64 不透明像素图集，楼梯/台阶使用一张 16×16 派生砖纹。库存物品继承方块模型，无重复几何。
- 自定义几何 97 体块/508 面；最复杂铁刺座 13 体块/66 面。完整覆盖的内部面已保守剔除，镂空/部分覆盖处不盲目删面。不逐像素挤出裂纹、骨纹和符文。
- 不增加方块实体、ticker、网络包、自定义渲染器、逐帧模型或动画纹理；碰撞四向在初始化时计算并缓存，不每帧重新旋转。
- 24 个注册块共有 174 个原生状态：22×4 朝向 + 80 楼梯 + 6 台阶。状态数量不是同时渲染模型数，体块/面数也不等于 draw calls；实际 FPS 和材质批次未测量。
- 生成器 `tools/build-dungeon-architecture.py` 先检查预算，再启动三进程并行导出。生成器并发不是游戏运行线程，不会在游戏内后台制作模型。

## 验证和使用前提

完整离线构建包含 `verifyDungeonArchitecture`：原生 BlockModel 解析、整数几何、面数预算、UV 对齐、父模型、物品、配方、掉落、语言与标签检查。Forge `runData` 验证真实注册、174 状态、24 份原生配方、四向视觉/碰撞精确并集、亮度和无方块实体。24 份编辑源均经原生 Blockbench 加载，代表件前后视角与软件四向图分开记录；原先未保存工程内容和 saved 标记均保留并恢复选中。

完整整合包中的实际放置、挖掘掉落、楼梯连接/含水、光照与库存 Display 尚需在备份世界验收；本轮不主动启动客户端或打开玩家世界。软件总览不是游戏截图，不宣称“零开销”或 FPS 提升。

两端均需更新 0.18.0 并完整重启。使用新方块后的世界直接回退 0.17.0 会缺失注册，须同时恢复升级前世界备份。原有返程门占用 P1 沿用，未混入本次建筑任务修复。
