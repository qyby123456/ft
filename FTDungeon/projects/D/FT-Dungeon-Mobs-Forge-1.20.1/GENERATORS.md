# 地牢门与可扩展生成器

适用 FT 地牢怪物 0.21.0，Minecraft Java 1.20.1 / Forge 47.4.10 / Java 17。
客户端与服务端应安装同版本主模组及既有前置。生成器将合并在主 JAR 中。

## 玩家操作

潜行右键入口门的任意完整部件，打开“地牢生成类型”菜单。选中后关闭菜单，
正常右键非壁灯门框或走入门洞进入。普通右键壁灯仍控制火盆难度。返程门不
提供生成器选择，继续返回每位玩家自己的原入口位置。

- 连接地牢 · 固定房间群：沿用已有大厅、房间群与各房进度。
- 连接地牢 · 紫晶群系：首次准备九间群系房间和入口短平台，在平台放置 FT
  返程门。准备完成前玩家留在原维度，窗口不计时，原返程记录不改写。

类型分别保存在各入口门的 `GeneratorType` 中。首人成功入场后，本轮把类型、
入口和难度一起固定；其余成员进入同一布局。原五分钟窗口及全员离开后的
解锁规则沿用。已开启的一轮不能切类型，菜单打开时也不会由碰撞自动入场。
旧门和旧轮次没有此字段时默认为固定房间群；未知类型会拒绝入场并提示重选，
不会静默改用另一生成器。

群系内容只创建一次，后续进入复用已有结构。施工中断、持久日志异常或检测到
冲突时关闭入场，保留现场供管理员检查，不自动覆盖、清空箱子或删除玩家改动。
当前群系入口固定在地牢维度独立空域 `(1000,200,1000)`，与旧大厅分开。
本次连接的是生成与出入流程；没有把旧固定房间的怪物点位表搬到新布局。

## 管理员

```text
/ftdungeon generator list
/ftdungeon generator status
/ftdungeon generator prepare amethyst_biome
```

这些命令要求权限等级 2。`prepare` 与入口门调用同一后端，用于提前准备地牢；
不会传送玩家或开启轮次。`status` 显示阶段、完成量、观察 ticks 和失败原因。
没有自动清空或强制重置命令。首次生成需分批施工和原生刻观察，不能把 BUILDING
或载荷刚放完视作 READY。只在完整预检、原生载荷/流体检查及保存后开放入口。

## 接入其他生成器

在公共初始化的 `FMLCommonSetupEvent.enqueueWork` 中调用
`DungeonGenerators.register(Provider)`，使用唯一命名空间 ID。不要在客户端界面
硬编码类型。菜单从服务端发送注册表中的 ID、名称和说明，自动分页；最多 256 项。

`Provider` 包含以下接口：

- `id()`：持久类型 ID，后续版本不得挪用给不同生成器。
- `name()` / `description()`：玩家可读的 Component。
- `prepare(ServerLevel destination)`：服务端主线程调用，返回 READY、BUILDING
  或 FAILED。READY 必须含有限、安全落点；主传送逻辑还会做原生安全落点检查。
- `tick(MinecraftServer server)`：可选，每个服务端 tick 调用，适合分批生成。
- `onEntered(ServerPlayer player, ServerLevel destination)`：可选，成功传送且
  轮次绑定后调用，用于该生成器自己的后续行为。

所有生成器当前使用 FT 地牢维度，自行管理不重叠的生成区、持久化和返程门。
不得在菜单点击中直接施工或传送；不得跳过世界边界、已有方块、原生 BE、流体、
中断处理和安全落点检查。异步工作只做纯数据计算，世界读写必须回服务端线程。
可选生成器被移除后，其旧 ID 保留为不可用状态，管理员可在未开轮的入口重选。

`D:/ft工程文件/FT地牢_生成器接入_20261106/`。没有将新主 JAR 自动部署到正式玩家实例。
