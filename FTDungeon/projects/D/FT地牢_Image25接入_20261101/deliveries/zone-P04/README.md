## 入口、路线与失败恢复

所有坐标均为模板原点相对 XYZ，连接点和安全点用玩家脚部坐标。

| 位置 | 坐标 | 说明 |
| --- | --- | --- |
| 北入口 | [11,5,0] | 三格宽、三格高，三个脚位均有完整地板 |
| 入口安全点 | [11,5,3] | 可步行往返入口 |
| 中段安全点 | [4,6,14] | 六格宽贴墙平台，有外缘护栏 |
| 末段安全点 | [4,6,22] | 加宽岩沿连接南侧横廊 |
| 南出口 | [11,5,26] | 三格宽、三格高，经短梯回到与入口相同高度 |

从入口平台向西走，到西墙两格以上净宽岩沿沿 +Z 前进。断口分别在 z=8、12、16、20，均为一格空隙；仅第二跳上升一格，其余平跳。无需疾跑、药水或装备。每段岩沿均与西侧双层石墙同高相接，并有墙脚托石；六盏吊灯经三节锁链和实体锚座连接屋顶，四支壁炬均有墙体支撑。

从任何断口或平台外缘跌落，落到 y=2 的完整石地板，脚部 y=3，最大落差三格。沿 x=7 的清空带走到 z=12，再向东走到 x=18，向北到 z=8，经 x=17..19、z=7/6 的三格宽回程石梯返回入口平台。中段与末段安全点是实体休息平台，不包含自动传送、复活点或持久检查点功能。

## 对照图的适配与偏差

1. 原图为剖切示意，成品补齐四墙与完整屋顶；仅渲染剖视裁掉近墙和屋顶，不修改 room.nbt。
2. 保留苔石/裂石、贴墙断续岩沿、柱梁、暖光吊灯、铁栏和木箱语汇。为可验证通关，岩沿加宽，补齐中段休息台、南横廊及可用出口。
3. 降低坑深并增加完整恢复地面和回程梯；跌落失败可自行返回入口。
4. “崩裂”由静态断口与裂石表达，不做计时坍塌、落沙、实体或运行时破坏。
5. 木箱使用剥皮云杉原木，红布使用嵌墙红羊毛；没有容器、库存、战利品、实体、执行方块和流体。

## 验证范围与复现

静态检查读取最终 NBT，检查所有坐标、方块数量、单一调色板、禁用方块、完整屋顶/地基/恢复地面、北南开口、岩沿净空、墙体支撑、吊灯支撑以及全部非空气构件的六邻接连通性。

隔离 Forge 1.20.1-47.4.10 GameTest 在本目录 qa/forge-run 中运行。四个旋转均用 StructureTemplate.placeInWorld 放置；对每个记录执行邻居更新，强制区块加载，启用随机刻及方块掉落，等待 240 游戏刻后逐记录复核状态、canSurvive、流体/方块实体和掉落实体。路线使用 Forge FakePlayer 的 0.6×1.8 玩家碰撞体与原生 Entity.move 验证步行、四次正常步行速度跳跃、四处跌落恢复、回程石梯双向行走和出口落地。另用缺入口地板、阻挡跳跃净空、堵住回程梯、断开吊灯锁链四种故障检验验收器。

路线探针提供固定水平速度 0.21、起跳速度 0.42、重力 0.08 和竖向阻尼 0.98，以原生碰撞体执行。它是可复现脚本验证，不是整合包客户端键盘操作、网络联机或完整手感验收。最终结果以 qa.json 和 qa/native.json 为准，不将编译通过等同于原生放置或路线通过。

重建：在 Minecraft Builder 技能目录运行 node scripts/run-build.mjs <本目录>/tools/recipe.mjs --out-dir <本目录> --name room --data-version 3465 --json；然后 node tools/audit.mjs。

原生复验：PowerShell 执行 tools/run-native.ps1。脚本仅在本目录运行测试，临时设置 JAVA_HOME 后恢复，不向正式 mods、配置或玩家存档写入。

渲染：node tools/preview-server.mjs，另一个终端执行 node tools/render.mjs，再用 Python 执行 tools/contact_sheet.py。仅在本地打开只读 NBT 预览。
