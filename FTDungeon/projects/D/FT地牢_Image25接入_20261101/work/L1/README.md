# L1 黑曜试炼大厅 · 紧凑接入版

只负责制作与质检。交付文件位于 ../../incoming/L1/：room.nbt、room.json、preview.png、qa.json。没有修改 FT-Dungeon-Mobs 核心或 JAR，没有部署，没有读取或写入玩家存档，没有向其它聊天发送消息，也没有发起新的收费生图请求。

## 接入契约

- NBT：Minecraft 1.20.1，DataVersion 3465，XYZ 尺寸 25×12×25。
- 北向接口：局部入口脚点 (12,2,0)，三格宽（X=11～13）、三格高（Y=2～4）；入口脚下 Y=1 是干燥实体方块。
- 安全内部脚点：(12,2,4)。北侧中轴三格宽干燥走道直达中央竞技台台阶，另有东、西、南跨桥。
- 四周实体墙，除北侧接口外没有其它开口；屋顶是双层封闭阶梯穹顶。预览剖去屋顶和近侧墙，不表示成品缺墙缺顶。
- 使用原版方块，四桥宽三格，真实熔岩五面封边，中央火盆为原版地狱岩火焰常燃装饰，不具备 FT 交互能力。
- 两个空木桶没有 Items 或 LootTable；无实体、刷怪笼、命令方块、奖励配置、关闭铁门或自动 tick 逻辑。

模板显式包含整个 25×12×25 体积的空气格，不能直接覆盖已有建筑。由总接入负责人负责接入点坐标变换、相邻房间碰撞、防覆盖、维度与服务器权限以及实机验证。

## 质检与复现

build_room.py 生成模板及接口 JSON，并验证坐标、墙壳、双层屋顶、北口三格净空、四桥全宽净空、熔岩封边、入口到四桥与竞技台的两格净高可达性。四周方块和空域均在尺寸范围内。

VerifyRoom.java 使用实际 Minecraft 1.20.1 注册表和方块属性，原生 NbtIo 解码并通过 StructureTemplate 读写往返，核对 7500 个唯一位置、实体及方块实体负载、显式空气和尺寸。只启动无世界的验证程序，不启动游戏世界。

render_room.py 复用 D:/ft工程文件/黑曜试炼地牢_20261101/tools/render_dungeon.py 的原版贴图投影方法；需要 Pillow 及本机 Minecraft 1.20.1 客户端 JAR。finalize_room.py 核对 NBT 与渲染源数据一致、SHA256、接口、图片解码、禁用功能及旧工程交付 ZIP 未变，输出 incoming/L1/qa.json。

原生验证临时使用的重映射游戏 JAR 仅用于本机格式验证，未包含在四件接入交付或 L1-handoff.zip 中；验证后删除。编译器日志留在 qa/。不把格式与静态检查冒充游戏流体、火焰、多人或整合包实机测试。
