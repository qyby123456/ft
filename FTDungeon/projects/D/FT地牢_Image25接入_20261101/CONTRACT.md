# image2.5 地牢房间接入契约

## 范围与职责

本批落实已经存在的 image2.5 设计图片，不重新调用生图接口。首批 L1、L2、M1、M2、S1、S2，以及第二批已落盘 L3、L4、S3，共九间。第二批 M3、M4、S4 和总布局图在本次清点时没有 PNG，不把提示词冒充设计成品，也不阻塞九间房验收。

- 核心、连接路线、构建和部署唯一负责人：聊天「整理新地牢房间导入参考」。保留原 31/30_1、入口、返程和五档难度逻辑。
- 独立制作负责人：L1「参考图片设计地牢」；L2「参考图片设计制作地牢」；M1「参考图片生成 FT 地牢」；M2「参考图片生成地牢」；S2「根据图片设计地牢」；L3/L4/S3「制作并拓展地牢建筑」。
- 本聊天「检查并接入 FT 地牢设计」补做 S1、汇总原图指纹、独立验收，不与核心负责人同时修改核心源码。
- 任何制作线程不得直接部署、写入玩家存档、修改其它制作线程的房间、修改连接密钥或图像生成配置。

## 每间交付

`incoming/<ID>/room.nbt` 是 gzip 压缩的 Minecraft Java 1.20.1 单一调色板结构模板。`room.json` 最少包含：

```json
{
  "id": "S1",
  "name": "墓狱档案囚室",
  "size": [9, 8, 11],
  "entrance": [4, 1, 0],
  "interior": [4, 1, 2],
  "facing": "north",
  "sha256": "room.nbt 的完整 SHA-256",
  "reference": "对应 PNG 的绝对路径"
}
```

坐标均为模板原点相对整数 XYZ。entrance、interior 是玩家脚部坐标，不是脚下地板。entrance.z 必须为 0，位于北侧中央。北开口至少三格宽、三格高，三个脚位下方须有完整地板，不能使用关闭的门或额外突出石饰。入口与内部安全点必须可步行往返。允许花园露天，其余房间必须有完整屋顶；剖切只用于预览，不修改最终结构。

另交付 `preview.png`（从实际 NBT 渲染，不使用 AI 图代替成品）、`qa.json`（检测项和真实结果）。生成脚本、材料和额外报告可保留在各自工程或此房间子目录，不能写入其他 ID。

## 建筑与安全

只用 1.20.1 已有原版方块。允许少量空容器点缀，不自动分发战利品、不新增刷怪笼或实体、不加入命令方块、结构方块、拼图方块。保留书架、石台、工具、植物等主题内容，不能交付空盒子。真实熔岩/水必须有底与边界，火不得接触可燃木构件。主路不穿熔岩、火、深水、粉雪或蛛网。灯、植物、雪、悬挂件要有支撑。

NBT 稀疏坐标不代表清空命令。核心在第一次施工前验证整个体积，包括未记录坐标，以及世界边界、液体和实体；占用就拒绝该房间，不能无条件清空。每个房间有独立持久生成标记；再次入场不覆盖玩家修改，已生成房间不因新增模板而重建。安全失败必须可诊断，不能把失败写为成功。

## 接入验收

必须有从现有 FT 大厅实际可走到新房间北入口的连接路线，不能只把 NBT 打进 JAR。保持已有传送门返程、入场窗口和个人记录。无需伪造新的战斗、波次或奖励系统。构建、Minecraft 方块状态和模板加载、连接布局/幂等/占用拒绝的隔离验证完成后再部署。游戏运行中不热替换，备份旧 JAR，保留回滚资料。不得打开或代执行玩家世界施工命令。

核心交付记录放 `integration/`，包括版本、模板 ID、固定位置、连接说明、验证结果、JAR SHA-256 和部署状态。软件渲染、隔离验证与整合包实机游玩是不同级别的证据，交付时必须区分。
