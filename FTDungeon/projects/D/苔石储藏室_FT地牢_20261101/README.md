# 苔石储藏室 · S2 商栈密道

依据本聊天的苔石储藏室参考图制作，只做一个可进入的小房间，不扩成九房地牢。补充参考图与原聊天附件为同一场景；本次没有新增收费图片生成请求。

## 建筑

- NBT 尺寸 **X=11、Y=9、Z=15**，其中房内地面净空约 **9×13 格**；地面方块位于局部 Y=1，玩家脚部位于 Y=2。主体净高 5 格，木梁局部压低一格。
- **北入口 Z=0，X=4..6、Y=2..4 保持空气，三格宽、三格高，没有铁门、栅门、活板门或机关。** 入口脚部锚点 `[5,2,0]`，安全内点 `[5,2,7]`，朝向 `north`。
- 中央 X=4..6、Z=0..11 是连续三格宽的干道，不要求跳跃、游泳、开门或完成机关才能进入与返回。
- 普通石砖、苔石砖、裂纹石砖与少量圆石组成墙和地面；云杉原木立柱与横梁、原版木桶堆、暖灯、封蜡墙牌、蛛网、根须及少量藤蔓还原参考氛围。
- 后角保留红布桌台与一个旧物箱。木桶和箱子均为空，没有战利品表或奖励刷新；两块金质测重压力板只是原版装饰，不是金币模型。
- 9 格真实水源位于干道两侧，水坑底部与四周都有完整方块封挡。完整成品封顶；总览为了看清内部剖去屋顶和部分近侧墙梁，不是实际无顶建筑。

## 统一接入交付

接入文件位于：`D:/ft工程文件/FT地牢_Image25接入_20261101/incoming/S2/`。

- `room.nbt`：Minecraft Java 1.20.1 原版压缩结构模板，DataVersion 3465。
- `room.json`：`id,name,size,entrance,interior,facing,sha256,reference` 八字段接口。
- `preview.png`：从最终 NBT 读取的轴测软件剖视，不是游戏截图。
- `qa.json`：几何、干燥通行、水体围护、封顶、原版注册表和哈希验证记录。

**这里只交付统一北接口房间。没有修改 FT-Dungeon-Mobs 的 DungeonRooms 等核心源码，没有构建或替换正式地牢 JAR，没有另装数据包，也没有打开或写入玩家存档。** 原大厅中的具体位置、连接廊道和部署由统一接入工程负责，先前设想的东侧连接没有单独实施。

原参考图中的铁门不放在统一北入口，替换为敞开的石木门框。所有构件都是原版 1.20.1 方块，不需要建筑附属模组。参考图中的定制木箱、零散金币和写实反射不属于本次新增模型或着色器能力。

## 安全边界

结构包含整个 11×9×15 体积的显式空气记录，导入器必须在放置前完整检查声明范围，拒绝已有建筑、实体或液体冲突；不能把原生 `/place template` 当作有防覆盖保护的安装命令。

没有自然生成、波次、Boss、奖励发放、传送、定时任务、常驻区块、额外入口或返程逻辑；不会改动五档难度、个人返程与现有门的状态。原版注册表与 NBT 校验不等于已在完整整合包客户端完成实机验收，水体更新、照明和多人仍需由接入方在备份世界确认。

## 重建与验证

1. 使用现有 Python 与 Pillow 运行 `tools/build_room.py`，确定性生成 `out/room.nbt`、接口 JSON 与几何报告。
2. 用 FT 工程现有 Gradle wrapper、JDK 17 对本目录运行 `runData --offline`，只启动独立验证 Mod，不把验证 Mod 安装到玩家实例。
3. 运行 `tools/render_room.py`，从最终 NBT 与本机 1.20.1 客户端贴图生成预览。`preview/exterior.png` 保留完整屋顶，`preview/plan.png` 显示北接口和干道。
4. 运行 `tools/publish_room.py`。只有几何、原版格式和预览报告都匹配当前 NBT 哈希才交付四个文件；已有不同内容会拒绝覆盖。

构建器、渲染器和验证器都保留在本独立工程。`build.gradle` 仅用于离线注册表验证，不是替换 FT 核心的模组工程。
