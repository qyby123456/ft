# 小型群系地牢修复 0.28.0

适用 Minecraft 1.20.1 / Forge 47.4.10。此工程独立于原通用风格工程，保留月蚀、混沌和旧风格实例的注册 ID 与读取逻辑。

## 本次修复

- 小型古林、砂岩、霜原、紫晶分别使用原 S1、S2、S3、S8 的九间真实房间，36 间原始 NBT 保持原文件哈希。没有调用监狱网格或月蚀布局。
- 每个新实例固定九间房、八条连接；各房只出现一次。种子决定房间布局与朝向，连接仅通过房间声明的真实边界门洞。入口和宝藏室有独立角色。
- 各风格单独封闭房间池，不把四套造型降为同一套监狱房间的换色。标准连接适配限定在原门洞范围；窄入口保留窄通道，其余门洞采用三格宽、三格高的连接截面，剩余原开口封边。
- 每间房外围添加一层屏障，声明门洞保留通路；整个实例外围也有完整屏障壳层，覆盖底部、顶部和四周。原模板内的家具和装饰不被屏障替换。
- 地牢门首页显示混沌、月蚀与“小型群系地牢”分类。点击小型分类后再选择古林、砂岩、霜原或紫晶。返回分类不改变选项，不会触发生成。

## 操作

管理员或创造模式潜行右键完整入口门，点击“小型群系地牢”，选择风格，再点击生成。点亮门旁祭炉后，等待生成完成并从门进入。返程门返回各玩家自己的原入口位置。

新小型实例 ID 为 `ftsmall:forest`、`ftsmall:desert`、`ftsmall:frost`、`ftsmall:amethyst`，使用独立的 `ftsmall:small` 维度。旧紫晶实例仍使用原有九房后端；新门上的紫晶选项使用带逐房隔离的新小型后端。旧 `ftmossgen:*` 四层实例保持原始绑定和出入逻辑，不作为新的小型风格列出。

已生成的旧入口不会被自动重绑或清空。需要新放入口门选择九房版本。模组更新不重建已有存档中的大型布局，也不删除玩家建筑或战利品。

## 独立验证

`BUILD.ps1 -Task runGameTestServer -Offline -GradleOptions @('-PsmallOnly=true','-PgateTestDirectory=独立测试目录')`

测试覆盖四套九房池、不重复/不串池、不同种子和同种子复现、真实菜单分类/选择/返回、实际建造、完整外围屏障、家具方块实体、原生玩家碰撞路线、进出与保存数据回读。具体执行状态以 verification/small-20261109 下本轮日志和验收记录为准；编译成功不代表原生测试通过。

## 本轮验收结果

- Forge 原生三项必需测试全部通过：36 间原始房间、16 组种子布局、四种风格实际建造和九房可达、真实菜单操作、家具保留、个人进出返回、保存数据回读与区块票据释放。
- 最终 0.28.0 生产 JAR 已重混淆打包，入口/返程门模型与动作检查、房间资源检查通过；生产包不包含测试类和测试结构。
- 对照已安装 0.27.0：5584 个既有 data/assets 文件逐字节一致，新增资源使用 ftsmall 命名空间。
- 完整 build 仍在既有石棺模型共面重叠检查 verifyDungeonArchitecture 处失败。该模型与旧版逐字节一致，本次没有修改；不能把专项打包成功表述为全量构建检查通过。
- 本轮未在图形客户端逐房游玩验收。日志与哈希记录见 verification/small-20261109。
