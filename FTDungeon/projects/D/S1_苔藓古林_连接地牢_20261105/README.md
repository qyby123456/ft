# 苔藓古林·九域连通地牢

按第一组的苔石砖、古树、藤蔓、灯笼、水景与木构风格，将已验收的01—09九个实际NBT模块组装为一座新地牢。没有复制第10张总览冒充新拼装，也没有更改九份原始文件。

## 规模和布局

完整源`mossy-forest-connected.nbt`：145×24×173，602040个显式格，DataVersion3465。南入口局部脚底坐标[75,2,172]；主通路地面脚底Y4，入口模块保留其内部台阶。主入口向北进入中央仪式主厅，再分三条探索支线：

- 北线：藤蔓长廊 → 书房 → 古树大厅。
- 西线：水景小室 → 折角回廊。
- 东线：上层回廊庭院 → 双守卫宝藏室。

共九原模块、八新建带顶灯笼连接廊。新廊内宽5，主体四格净高；接口按原模块实际宽度收窄，最窄为入口原有双门口。房间、结构、植物、装饰及负载逐格保留，例外只有明确列出的未使用接口封墙和入口四个门半块open=false→true。现有03个宝箱、02个木桶均未新增战利品，04份旗实体原样保留。`layout.json`提供每个来源哈希、原点、链接、封口及门状态变化。

## 在独立测试世界导入

**本次未替用户导入任何世界。先备份；先在独立测试世界验证，不直接用于正式存档。**

1. 将ZIP作为数据包放入测试世界`datapacks`，执行`/reload`。
2. 选择空旷、完整范围已加载的地方。例：共同西北底角为世界[0,64,0]，占位范围X0..144、Y64..87、Z0..172。
3. 例中可先用`/forceload add 0 0 144 172`请求加载完整占位区，等待加载完成再放置。建议使用固定锚点函数：`/execute positioned 0 64 0 run function s1_connected:assemble`。它按`assembly.json`的次序放16片，每条命令均相对同一个锚点，不能边走边手放。测试完成后可用`/forceload remove 0 0 144 172`解除此次强制加载。
4. 支持大模板的命令/工具也可尝试完整源：`/place template s1_connected:full 0 64 0`。结构方块GUI有48格限制，不能用一个结构方块载入整个145×173源；用16分片。
5. 此锚点的入口脚底为[75,66,172]，进入后沿台阶向北。可在入口南侧测试站位[75.5,66,173.5]，不要传送到方块实体或墙内。

所有分片为密集体积，**空气会清除原有地形和建筑**，不能启用忽略空气后还声称与总源相同。需要同时考虑完整145×24×173盒和分片加载区；命令失败须停下核查，不能忽视部分放置。未测试世界旋转、镜像或逐片运行时邻居/流体更新，不提供这类稳定保证。不要单独旋转各片。可在导入成功后再关闭入口门，不必修改原模块文件。
