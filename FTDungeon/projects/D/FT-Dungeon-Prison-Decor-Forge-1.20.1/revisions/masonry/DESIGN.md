## 06 / prison_brick_slab / 雕边囚石台阶

- **保留原生行为：** `kind:slab`、`mount:any`、`light:0`、`base:prison_blue_bricks`。预览仅一个 `[0,0,0] → [16,8,16]` 的下台阶，不使用装饰立方体假装台阶。
- **真正重画：** 顶面为四块大幅错缝石板，外围有连续凿刻双边；不是旧砖纹截成半高。侧面为全新的半高双线雕边、凿刻菱形和少量矿物沁色；底面另画粗凿刀痕。
- **原生接入合同：** `native_tiles:{top:0,bottom:1,side:2}`；预览 `tile:2`，`faces.up:0`、`faces.down:1`。顶/底/侧不能再全部指向旧蓝砖。
- **上、下、双层：** 2 号侧纹的 0–15 行与 16–31 行逐像素相同。按块局部投影 UV，下台阶 y0..8 采下半，上台阶 y8..16 采上半；双层采整张形成有意的两层石板边缝。父工程负责原生三个状态、流体状态和实际 Java 模型接入，本目录不声称已完成这些运行资源。
- **成本：** 1 盒 / 6 个声明面；0 发光、0 透明、0 动画。

## 07 / prison_fluted_pillar / 四槽基冠囚石柱

- **全新轮廓：** 宽基座 y0..2、退进肩台 y2..3、竖槽柱身 y3..12、颈圈 y12..13、承托冠阶 y13..14、上盖板 y14..16。不是旧的九根直通柱段加颜色。
- **真实凹槽：** 柱身以四个角石、南北槽底和中央腹板组成，四面各有宽 2、深 2、高 9 的实体空槽；槽底是后退的石面，非黑线假凹槽。四槽空体积合计 144 单位立方。
- **严格分割：** 七个柱身体块互不穿插，以面接触。角石上可见的外立面用 5 号，凹槽及窄回口用 6 号；不把槽的暗色任意贴到基座。
- **堆叠：** y0 和 y16 接触轮廓都为 x1..15 / z1..15，14×14、196 平方单位，完全一致。连续堆叠会保留基冠节奏，不承诺自动连接或隐藏中间柱冠。
- **材质：** 基座 3、颈肩 4、角石 5、槽面 6、水平切面 7、上盖板侧面 8。窄冠边按实际 y 高度落在对应像素行，不在薄件上缩放整块花纹。
- **成本：** 12 盒 / 72 个声明面；上限 12。基座 2、柱身 7、柱冠 3；没有逐像素装饰体块。

## 08 / prison_cornice / 双牛腿阶叠石檐

- **全新轮廓：** 三层连续石檐，正面依次位于 z2、z4、z7，分别为 y14..16、y12..14、y10..12。与旧砖 T 形檐和四小齿不同，承托由两枚真实牛腿负责。
- **成对牛腿：** 位于 x2..5 和 x11..14；各用下段 z12、中段 z10、头段 z7 的三阶支撑，加一条 z14..16 贴墙后跟。各段共享面而无体积重叠，均有真实承托路径。
- **负空间：** x5..11 / y0..10 / z0..16 完全为空，宽 6、高 10，960 单位立方，贯穿至背面；没有用整片墙板堵住开口。实际贴墙时墙体本身当然可能位于后方，这不是透明或传送门机制。
- **安装与拼接：** 两个后跟及檐带背面均到 z16；全宽冠阶到 x0、x16，可水平并置。仅一格内装饰，不承诺跨格承重或支撑检测。
- **材质：** 冠盖 9、次阶 10、雕带 11、牛腿前面 12、水平面 13、贴墙后跟 14、牛腿侧回口 15。牛腿上的凿槽和少量矿物旧痕只用像素，不增加微小零件。
- **成本：** 11 盒 / 66 个声明面；三条冠阶、两条后跟、六段牛腿。0 齿饰小方块。

## 材质、UV 与预览约定

原生 RGBA **128×128** 图集，4×4 共 16 块 **32×32** tile，全部 alpha=255。冷蓝灰石色族采用 #253744 / #354c59 / #405965 / #4e6570 / #74858b，有限 #8d6b3c / #9b8260 矿物旧痕；未使用随机逐像素电视噪声、模糊、假透明或发光。石纹为有方向的大色簇、长刀痕和按结构布置的刻线。

所有面采用 **块局部投影 UV**、固定 2 texels / model unit。子盒裁取其在整格中的对应区间，禁止把整块 32px 纹理拉伸到细柱或两格高的檐边。具体六面公式与 atlas Java UV 换算在 `tilemap.json`。材质分工及绘制坐标均在可复现源中。

`contact-sheet.png` 为固定相机的正、右侧、背、前斜四视图；每件还有真实 64×64 像素图标和 64px 无纹理灰模图标。`work/renders/` 另存同尺寸单图、底斜视和 256px 灰模斜视，共 24 张。已查看总览、图集、牛腿灰模斜视及柱体底斜视：基冠/凹槽、双牛腿和开口在灰模和 64px 下仍可识别。

这些图由本目录 Pillow 软件正交三角光栅器离屏绘制，带深度缓冲、nearest 取样、固定六面亮度；不是共享编辑器截图，也不是游戏截图。精确相机、背景、光照系数在 `qa.json`，预览不可作为最终客户端材质/碰撞验收。

## 已做的真实检查

1. 读取实际写出的定义/PNG/映射：恰好三项，顺序和运行字段符合基线；几何端点全部整数 0..16、正体积、零旋转、各项 ≤12 盒。
2. 生成器按 1×1×1 占用格精确检查零体积相交、面接触连通、每盒有外表面贡献、无重复可见单位平面；独立脚本另以解析 AABB 和面接触图复核，检查实际文件而不只调用生成器函数。
3. 检查 06 原生材质三分配及两半侧纹一致、07 四个真实槽和上下接触面、08 中央贯穿空区和贴墙接口。
4. 六面投影 UV 不越 tile；RGBA 尺寸、16 个 tile 的布局及引用、全不透明、0 发光 tile、单帧均核验。检查输出视图的颜色仅来自图集色与固定面光照，没有插值色。
5. 生成器每次执行独立构建两遍，比较四个生成交付物和 24 张 PNG 的全部字节。`work/check_delivery.py` 还以不同 `PYTHONHASHSEED` 启动两次全新 Python 进程，比较四个生成交付物和 `qa.json`；证据为 `work/independent-validation.json`。
6. `work/independent-validation.json` 同时记录实际文件哈希、基线相关文件在复现前后的哈希不变，以及与旧像素/几何的不同。此检查不冒充父工程对其余十五件和最终 jar 的完整字节验收。

运行复现：使用已提供的 Pillow Python 执行本目录 `make_assets.py`；默认仅写本目录生成物及 `work/renders`。`--output` 只允许本 lane 内的目录，拒绝外写。独立复核可执行 `work/check_delivery.py`。无需网络、外部图片或旧几何输入；Pillow 版本和本机预览字体哈希在 QA 中。
