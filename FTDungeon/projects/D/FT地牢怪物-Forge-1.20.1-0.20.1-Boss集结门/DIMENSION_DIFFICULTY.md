# 火炬难度的维度作用域 · 0.19.1

## 直接结论

火炬 / 血棘祭炉的档位只控制 FT 地牢维度 `ftdungeonmobs:dungeon`，**不再对火炬附近的怪物施加半径加成**。主世界、下界、末地和其它模组维度的怪物不会因附近摆放或调节火盆改变属性，也不修改原版世界难度。

FT 地牢目前是一个共享维度，而非每个入口单独创建的副本。本次修改不会新增维度、复制房间或改变模型。若将来新增独立地牢维度，应明确为每个维度新增各自的控制来源，不能复用一个全服全局难度。

## 如何控制

| 场景 | 行为 |
| --- | --- |
| 在 FT 地牢内部，尚未开始一轮 | 点燃 / 切至 1～5 档，立即更新该维度中所有已加载、自动分级的 FT 骷髅，不受距离限制 |
| 地牢内部多个火盆 | 最后一次显式选择的有效档位生效；不会按怪物最近的火盆重新选档，也不叠加 |
| 门外控制本次入口的火盆 | 保留入口 6 格内最近火盆选取及开关门、门色联动；档位用于地牢维度，不作用于门外邻近怪物 |
| 与当前入口无关的外部火盆 | 仍可变色、调档，但不会给周边实体加成，也不改变已绑定地牢难度 |
| 第一位玩家成功进入后 | 按既有规则冻结本轮档位；地牢内部火盆和绑定入口的控制火盆都不能绕过锁定改档 |
| 熄灭、挖掉火盆或控制区块卸载 | 不存在零档怪物属性；保留地牢最近有效的 1～5 档，不因离开半径或控制器卸载而回落 |
| 新怪物或重新读入的怪物 | 自动分级者从当前地牢维度读取同一档位；不强制加载其它区块 |

地牢内部的显式选择会持久保存，入口的周期性复核不会偷偷改回旧档。下一次在已绑定入口火盆显式选择有效档位，或按入口规则开始新一轮时，重新采用该入口档位。原有五分钟入场窗口和全员离开后的解锁条件不变。

视觉仍按所点击火盆自己的 0～5 方块状态显示，不扫描整个维度去同步每个装饰火盆；本轮实际档位由维度 / 本轮状态决定。

## 哪些属性受影响

仅自动分级的本模组骷髅战士、弓手、法师和骷髅王；使用已有配置中的生命倍率、攻击倍率、物理护甲加值、铁魔法魔抗加值和法术倍率。

- 管理员命令 / API 手动固定的单体档位继续优先，不被火盆覆盖。
- 单体自定义加成、其它模组属性修饰符和剩余生命比例保留，不免费回满血。
- 已按本轮显式固定档位生成的地面符印怪物仍沿用该轮档位；本次不修改刷怪点的数量、位置或怪物组。
- 非 FT 地牢维度中的自动怪物恢复原版世界难度映射 / 默认档位；从旧版继承的周边自动加成会在原有实体刷新路径中消退，手动固定者不变。

## API 与存档

`ArenaDifficultyApi.setTier(ServerLevel, BlockPos, int)` 签名不变，0 只代表熄灭火盆，1～5 才是有效地牢难度。必须在所属服务器线程调用；活动轮次的火盆改档在修改方块之前拒绝。返回值为本次即时刷新的自动实体数量，不是全维度的总实体数；未加载实体之后自行更新。

`ArenaDifficultyApi.findTier(ServerLevel, Vec3)` 保留旧签名以兼容调用者，但位置不再参与难度选择。在 FT 地牢返回该维度档位，在其它维度返回空值；查询不会寻找最近火盆，也不会加载所传位置的区块。

`findSource(level, position, radius)` 继续作为已加载火盆的有限距离查询工具，供门与扩展获取控制位置；它不是怪物属性作用域。门口固定 6 格的控制器选择与旧怪物半径没有关系。

沿用主世界中的 `ftdungeonmobs_dungeon_gate` SavedData 保存地牢档位、入口与轮次。新增布尔字段 `DimensionTierSelected` 记录是否由地牢内显式选择；旧存档缺少字段时按 false 处理，不重置档位或轮次。旧 `ftdungeonmobs_arenas` 位置索引保留兼容，不能重新启用半径加成。

`config/ftdungeonmobs-common.toml` 的 `[arenaTorch] radius` 保留解析，避免升级破坏现有配置；**现已废弃，不参与属性计算**。无需编辑旧配置或删除存档文件。其它五档和单体配置格式不变。

## 构建与验收

执行 `.\BUILD.ps1 -Task build -Offline` 构建正式 JAR，执行 `.\BUILD.ps1 -Task runGameTestServer -Offline` 在独立测试世界运行 Forge GameTest。维度测试位于 `tools/DimensionDifficultyGameTests.java`，覆盖远超旧最大半径的怪物、五项属性、受伤比例、单体加成、手动锁档、其它维度隔离、入口联动、持久化、旧火炬和本轮锁定。

源码包不重新分发第三方开发依赖。首次重建时，将原工程 `libs/` 的六份既有 JAR 复制到源码根目录的 `libs/`，版本坐标见 `build.gradle`；然后使用本机已有 ForgeGradle 缓存或允许正常下载依赖。运行 JAR 的前置要求没有改变。

本轮未自动部署、未打开玩家存档、未启动 Minecraft 客户端。升级前仍需关闭游戏 / 服务器、备份世界并只保留一份相同 mod ID 的 JAR。完整测试结果和限制见 `VERIFICATION.md`。
