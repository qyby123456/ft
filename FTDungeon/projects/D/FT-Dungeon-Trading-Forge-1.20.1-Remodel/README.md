# FT 地牢交易 · 两格宽融蜡长桌 1.2.0

独立的 Minecraft **1.20.1 / Forge 47.4.10 / Java 17** 模组，无额外前置。不是 Fabric 模组，不修改现有 FT 难度/挑战模组，也不沿用已经放弃的火盆模型。

## 本轮外观

根据用户提供的 dungeon-trade-table-scenes 场景图，桌子做成 **两格宽 × 一格深** 的长桌；选择两格而非三格，便于放在地牢走廊或商人摊位。扩展桌板、横梁和置物板，四根桌腿仍在外角；药瓶、卷轴、颅骨、陶器和匕首只重新排布，保留原比例，不横向拉胖。

蜡烛下原金色托底改成 **米白融化蜡池和一处相连蜡溢**，仅两块薄实体，不用逐像素堆块。装饰金币、绿宝石、钥匙和桌面/置物板灰斑不恢复。保留粗像素木纹、破损桌板、铁包角、少量腿脚青苔与角落蛛网。参考图里出现的钱币等物件不是本次恢复指令。

完整可编辑模型/物品：**52 组件、270 声明面**；实际放置使用左右分区，整桌合计 **58 组件、294 声明面**。增加的六个组件仅为跨格长构件在格界的切分，内部接缝面删除。两侧共用一张 **128×128** 图集，桌面区域 64×32 保持原先的粗像素密度；没有整桌重复渲染、描边壳或几何动画副本。烛焰为静态装饰，不提供动态光源。模型不能当容器打开。

## 放置与购买

1. 创造栏「FT 地牢交易」获取桌子，或使用 /give @s ftdungeontrading:trading_table。
2. 放置点是主半边，相邻的一格沿桌子朝向的顺时针方向延伸；两格都必须可放置。遇到障碍时不放置、不扣物品，一张完整桌子只消耗一个物品。
3. 新桌默认无报价、库存为零。绑定后，右键 **任意一半** 先查看完整报价，再于至少 6 tick、最多 100 tick 内右键确认；可以先点一半再点另一半。
4. 台面前侧动态预览付款和商品，各最多三种，正面文字区分。静态药瓶等是装饰，不代表当前报价；以聊天里的完整报价、数量和库存为准。
5. 原料不足、背包放不下、售罄或扩展取消时，不扣款、不发半份奖励、不将奖励扔到地上。成功后下一次购买仍须重新核价。

原版长按可能重复发右键包。本模组限制同 tick、过快确认和副手重复结算，不声称能识别物理鼠标是否已经松开。正常 20 TPS 时确认窗口约 0.3—5 秒，服务器卡顿时以 tick 为准。

左右两半共用一个报价、库存与方块实体。拆除任意一半都会移除整桌：生存模式共掉一张桌子，创造模式不掉落；活塞不能推开其中一半。桌子没有真实卖家背包，不接漏斗：付款物品销毁、商品按配置生成至玩家主背包；有限库存表示可交易次数。拆掉重放不保留旧绑定或库存。

## 管理员与自定义

以下坐标替换为桌子任意一半的坐标，命令权限等级 2，区块必须已加载：

~~~mcfunction
/fttrade offers
/fttrade bind 100 64 100 ftdungeontrading:rations
/fttrade stock 100 64 100 32
/fttrade inspect 100 64 100
~~~

bind 设定报价并把库存设为不限；stock 的 -1 表示不限、0 停售、1..1000000 为有限次数。每次购买整份配方消耗一次库存，不按单件商品计数。两半均可用于绑定和查询，交易确认与事件会解析到存储数据的主半边。

内置报价：ftdungeontrading:rations 为 3 绿宝石换 6 面包和 2 金胡萝卜；bone_exchange 为 16 骨头换 1 绿宝石；iron_sword 为 5 绿宝石和 2 铁锭换命名铁剑。**移除装饰绿宝石不会禁止交易配方使用绿宝石。**

- 数据包格式与双方物品配置：[DATAPACK.md](docs/DATAPACK.md)，修改 costs / rewards 后执行 /reload。
- Java API、库存、购买前取消和购买后通知：[API.md](docs/API.md)。公开 API 签名保持不变；接入无需另写半桌结算。
- 安装示例数据包：交付目录中的「交易数据包示例.zip」，源码在 examples/datapack。
- 模型主文件：model_sources/地牢交易桌.bbmodel，内嵌贴图；运行资源在 src/main/resources/assets/ftdungeontrading。
- 设计、分区成本与来源：[REMODEL-DESIGN.md](docs/REMODEL-DESIGN.md)；验证范围：[VERIFICATION.md](docs/VERIFICATION.md)。

## 安装与升级注意

**先备份世界。** 客户端与服务器均安装本版 JAR，同一 mod ID 只能留一个版本。本轮仅交付，不自动复制进现有 mods，不启动游戏客户端。

1.2.0 从一格桌子改为真正两格结构，**不会自动占用旧桌旁边的方块**。旧世界的一格桌子可能没有相邻半边，视为未完成结构而无法交易；请提前记录报价和剩余库存，拆除后用新物品放置完整长桌，再绑定恢复。地图/结构作者直接写方块时必须同时放置同朝向的 left 与 right 两半；单个 /setblock 不会自动补全。详见 docs/API.md 的两格坐标约定。

## 构建与验证

Java 17、Node.js；模型工具另需 Python 和 Pillow。首次构建需要下载 Gradle/Forge 依赖，本机已有缓存可用 -Offline：

~~~powershell
.\BUILD.ps1 -Task build -Offline
.\BUILD.ps1 -Task runGameTestServer -Offline
python tools/verify-assembly.py
~~~

build 包含资源检查和重映射，结果在 build/libs。GameTest 使用独立 run/trading-verification 测试世界，不读取现有玩家存档；测试类、标签和测试结构不进入正式 JAR。模型生成器会覆盖生成文件，手工修改模型后不要直接重建覆盖。

Forge GameTest 通过 **206 项断言**，包含四朝向摆放、障碍拒绝、两半共享报价与库存、跨半确认、拆任意一半只掉一件和创造清理。Minecraft 1.20.1 实际模型解析、原生导出、分区表面/UV 连续性、八视角、七种 Display 与保存重开检查通过。11 个受保护核心文件（含付款匹配、数据包与公开 API）和旧版 SHA-256 一致；布局接入所需的方块、服务入口与访问解析有明确修改，不声称全部 Java 不变。

未启动 Minecraft 客户端，未测游戏 FPS、真实多人网络、着色器或第三方领地/经济系统。拆分装配与完整源模型在少数像素边缘有渲染差异，记录于 assembly-render-check.json，不宣称像素完全一致。保存重开同一工程的 RGBA 对照则严格相同。当前未接通 FT 难度锁商品、卖家库存或外部余额事务，保留事件扩展入口。
