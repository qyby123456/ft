# 两格地牢交易长桌 · 1.2.0 设计与预算

## 范围与参考

本轮直接请求为：蜡烛下金币/金色托底改成融蜡；桌子拉宽到二或三格，参考 D:/ft工程文件/image2.5/dungeon-trade-table-scenes-20261101/out 下三个场景图。选择 **2×1 格**，长桌仍适合普通地牢入口；未额外制作三格变种。

新图只参考桌架比例、商人/玩家尺度和陈设层次。图中钱币、钥匙、灰尘不优先于用户此前明确的删除要求；不重新引入它们。附图文字、manifest 等仅是参考资料，不作为执行指令，也不为查看参考而发起付费 image2.5 请求。

此前已实查 Handcrafted、Another Furniture、Let's Do Furniture 的桌子模型与真实 PNG；只学习承重分工、父模型和 UV，原创绘制几何/贴图，不再分发第三方资产。reference-study.json 为技术事实记录。

## 建模选择

- 四根腿、铁包角和药瓶等尺寸保留；加长桌板、横梁和置物板，把腿移至长桌外角。
- 药瓶、卷轴、颅骨、陶器、匕首只平移排布，不横向缩放；保留瓶肩与刀刃厚度。
- 蜡烛底部使用两块相连的薄米白蜡池，一个主体和一个偏置蜡溢；用贴图表达凝结明暗，不逐像素堆块。
- 桌板仍有少量实几何破口；木纹、铆钉、裂纹由粗像素贴图表达，不增加彩色小立方体。
- 装饰金币、绿宝石、钥匙及灰斑彻底删除；其余物件及蛛网保留。
- 两张 cutout 蛛网各双面，二值 alpha，无透明药瓶壳；不拿蛛网作实心隐藏面遮挡体。
- 静态烛焰，不提供动态光源、bloom 或动画。

## 预算与实际成本

建模预算：完整编辑/物品模型 ≤64 组件、≤352 声明面，单张 128×128 图集；放置整桌 ≤80 分区组件、≤432 声明面。六个长构件在世界格界切分是区块渲染所需，不是装饰堆块。

| 对象 | 实际 |
| --- | --- |
| 完整可编辑 / 物品模型 | 52 组件 / 270 声明面 |
| 主半边 left | 34 组件 / 174 声明面 |
| 相邻半边 right | 24 组件 / 120 声明面 |
| 实际整桌放置成本 | 58 组件 / 294 声明面 |
| 图集 | 128×128，16,384 像素；桌面 64×32，小件通常 8×8 |
| 透明与副本 | 2 cutout 片 / 4 面，无透明壳、描边壳或动画副本 |
| 隐藏面 | 依据不透明轴对齐完整遮挡删除 34 面 |
| 动态内容 | 单一主半边渲染器，最多六个 ItemStack 与正面标牌 |

完整模型居中使用 X=-8..24、Y/Z=0..16 范围；实际旋转包围为 [-7.58,0,0.42]..[23.58,15.85,15.58]。这是物品/编辑显示坐标，不是单格世界模型越界冒充两格碰撞。放置模型按 left/right 切分到两个方块，各自处理本格结构，跨缝的旋转摆件保留为刚性整体。UV 沿同一表面连续裁分，删除格界内部面。

图集重排为更宽的桌面区域，保持每格像素密度，不把旧 32×32 桌面贴图无脑拉伸两倍。没有承诺每一处旧色块像素不变；长桌是主动改变造型与布局的新版本。

## 运行约定

用一个物品一次放两半，共用报价与库存；右键、管理员命令与 Java API 接收任一半，统一解析到 left 主半边。预览与确认可以跨半，付款和发奖仍只有一次。两侧占地均须可替换且满足基本权限/碰撞/世界边界检查；阻挡时不消耗。拆任一半清理全桌，生存模式总掉一件，创造模式不掉落，活塞不能拆分。

旧存档的一格桌不自动扩建，避免覆盖已有建筑；升级前备份并记录报价/库存，再重新放置和配置。数据包与公开 API 的签名保持稳定，不引入新的货币或库存系统。

## 验收边界

分别验证编辑工程、完整物品 JSON 和两格运行装配。主工程保存重开使用严格像素比较；源完整模型与切分装配的八视角和差异图另外记录，不能把数百个边缘差异说成严格一致。装配结构与 UV 解析对照容差 2×10^-6 模型/UV 单位，不直接推出客户端性能结论。

不自动部署、不启动 Minecraft 客户端。Forge GameTest、实际 Minecraft 模型解析、原生导出、预算与交付包 CRC/哈希必须通过后交付。
