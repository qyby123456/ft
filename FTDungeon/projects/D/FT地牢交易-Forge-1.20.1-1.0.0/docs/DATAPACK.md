# 双方交易内容 · 数据包接口

## 文件位置与生效

一个文件定义一条交易，路径为 `data/<命名空间>/ft_trades/<名称>.json`，对应 ID `<命名空间>:<名称>`。文件也可位于子目录。放到服务器世界 `datapacks/` 后执行 `/reload`；客户端不必单独安装该交易数据包，因为桌面预览由服务端同步。

完整可用示例在 `examples/datapack/`。其根目录必须直接包含 `pack.mcmeta` 和 `data/`，不能多套一层文件夹。Minecraft 1.20.1 数据包 `pack_format` 为 15。

```json
{
  "title": { "text": "地牢远征补给" },
  "costs": [
    { "item": "minecraft:emerald", "count": 4 },
    { "tag": "forge:ingots/iron", "count": 2 }
  ],
  "rewards": [
    {
      "item": "minecraft:iron_sword",
      "count": 1,
      "nbt": "{display:{Name:'{\"text\":\"契约短剑\",\"italic\":false}'}}"
    },
    { "item": "minecraft:bread", "count": 6 }
  ]
}
```

示例 ID 为 `ft_trading_example:dungeon_supply`。加载后：

```mcfunction
/fttrade bind 100 64 100 ft_trading_example:dungeon_supply
/fttrade stock 100 64 100 12
```

## 字段约定

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `title` | 可选文本组件 | 标题，省略时使用交易 ID；可用 `text` 或 `translate` |
| `costs` | 1—8 项数组 | 玩家付出的全部材料，条目之间是「同时需要」 |
| `costs[].item` / `tag` | 二选一物品 ID / 物品标签 ID | 付款来源；标签无需 `#` 前缀 |
| `count` | 可选整数，默认 1 | 每项 1—4096，不接受小数、字符串或负数 |
| `costs[].nbt` | 可选 SNBT 字符串 | 付款物品完整 NBT 精确匹配，最长 16384 字符 |
| `costs[].allow_any_nbt` | 可选布尔值，默认 false | 明确允许消费任意 NBT 的匹配物品；不能和 `nbt` 同时使用 |
| `rewards` | 1—8 项数组 | 玩家获得的全部商品，条目之间是「全部发放」 |
| `rewards[].item` | 注册物品 ID | 必须具体到物品，不能用标签随机发奖 |
| `rewards[].nbt` | 可选 SNBT 字符串 | 原样附加到商品，最长 16384 字符 |

两侧方向固定：`costs = 玩家付款`，`rewards = 玩家获得`。想做回收店，把骨头写在 `costs`、绿宝石写在 `rewards`；不需要改变引擎。

物品须已注册且不是空气，支持其他已安装模组的 `modid:item`。标签可引用已有或数据包自己新增的物品标签；空标签无法满足付款，不会降级为免费交易。字段名严格检查，拼错或未知字段会拒绝整条交易并写入日志，避免静默按错价结算。

## NBT 注意事项

默认没有 `nbt` 时，只接受**无 NBT** 的相应物品，保护玩家命名、附魔或其他特殊材料。它不是“无视 NBT”。`nbt` 为完整精确相等，不是部分字段匹配；多一个字段也不相等。`{}` 与不存在 NBT 也不同。`count` 不属于匹配 NBT。

需要自定义代币可用 `"nbt": "{DungeonToken:1}"`；如需消费任何附魔/命名版本，明确设置 `"allow_any_nbt": true`，并告知玩家。物品标签和精确 NBT 可以同时用。无法仅凭 NBT 防止管理员 `/give` 伪造；管理员本就处于信任边界内。

## 库存与结算

- 库存属于世界里的每张桌子，由命令/API 设置，**不写进交易 JSON**。同一报价可绑定多张桌子，各自库存独立；当前没有共享卖家账户。
- 付款读取 36 格主背包和副手，不碰盔甲栏、末影箱、鼠标携带格或其他容器。
- 商品只放主背包，按物品自身最大堆叠数量拆分，支持多项商品和超过一组的数量。
- 先模拟完整扣款和完整发奖，任何一步失败均不提交；扣款腾出的背包格可用于奖励。
- 多个付款条件重叠时使用最大流匹配；同一件材料不会同时满足两个需要。创造模式也会正常支付。
- 桌面两侧各显示前三项的代表物，标签只展示其中一个样例，展示数量会限制在合法堆叠范围内。**实际完整名称与数量以第一次右键的服务端报价为准**。

## 覆盖与重载

相同资源 ID 遵循 Minecraft 数据包优先级；数据包报价优先于同 ID 的 Java 注册报价。可通过相同 ID 替换内置示例，或用不同命名空间新增报价。每次资源重载使旧确认失效；已加载的桌面显示最迟在下一次右键或 20 tick 周期刷新。

本模组一次最多加载 1024 条有效数据交易，按 ID 排序处理；超出和无效项写日志。加载失败的条目不会保留旧的数据包报价；若同 ID 有代码注册的报价，则回退代码报价。删除报价不会退还已成交材料，不会重置桌子库存；不存在的报价只会停用该桌，不能购买。

新增自定义 `translate` 标题时，其语言键仍需相应客户端资源；无需资源包的运营方案可使用 `text` 标题。
