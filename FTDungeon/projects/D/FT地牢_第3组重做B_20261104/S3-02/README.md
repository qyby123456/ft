## 坐标、连接与放置

原点[0,0,0]，+X东、+Y上、+Z南。北木框口[14,2,0]，西木框口[0,2,9]，均5宽、保守净高4；内部安全点[14,2,6]。坐标为玩家脚位方块格，身体中心使用x+0.5、z+0.5，见`route-targets.json`。无东/南出口，无楼层高差，只有完整地板Y1上主路。

`rotated-connectors.json`给出四旋转后非负包围盒尺寸和锚点；90/270度时X/Z交换为27×29，接入引擎必须补偿实际pivot平移。单件NBT无拆件顺序。原点应由相反朝向锚点相邻一格计算，不能把两个模板门平面直接重叠。未执行四旋转世界实际拼装。

显式空气覆盖整个13311格体积；未来接入器须先检查整个29×17×27体积占用/实体/世界边界及玩家建筑，占用拒绝，禁止先清空。不得把`preview-only/`放入生成池。两个木桶、两个熔炉只有对应id的空block entity，无Items/LootTable/燃料/自动奖励，不新增实体或刷怪笼。未写正式存档/mods/config或统一incoming。

## 路线与真实自检范围

`NativeQA.java`在独立临时目录读取候选快照，绑定170个真实原版block tags，遍历所有13311方块的canSurvive，检查注册表/状态与StructureTemplate读写。单独以0.6×1.8玩家体积、0.5格水平网格检查11个目标：两门、安全点、阅读凳、炉具、空桶、柜架、冻池接近点、两侧绕行点、骨骸观察点。目标含逐步身体中心坐标，非抽象“连通=true”。身体固定Y2，不模拟跳跃/上台/速度/战斗；冻池上台没有必须到达的奖励点。

`static-qa.json`含完整边界门洞、783列屋顶覆盖、完整坐标唯一与范围、原版ID、无危害/实体、四个空block entity、炉口朝室内未点燃、未点燃蜡烛等检查。`attachment-check.json`检查非空气方块面连接，不冒充重力/邻接更新。`snow-light-boundary.json`检查内部4个灵魂灯、光强10、开放空气曼哈顿衰减保守上界，不是世界光传播。

**世界放置/随机刻/光传播/区块重载/Forge游玩全NOT_RUN。**雪层在BLOCK光强>11可随机刻融化；内部灵魂灯最高10，熔炉和蜡烛均未点燃，但玩家点燃炉具/蜡烛或外界强光可改变结果。普通冰数量0，浮冰/蓝冰不依普通IceBlock光融化；外部模组/数据包改写无稳定保证。雪层支撑检验必须使用已绑定标签的原生结果，不能只看表面是否有方块。
