## 完成门槛

每组必须具备十个不同功能房间、可重现配方、完整NBT、真实Lodestone预览及看图记录、可核接口与内部路线、当前哈希绑定QA；还需整体连通的新合并源、布局和分片清单。第20号必须是密道藏宝，不能当总览省略。单元形似但功能、主要特征或比例明显不符参考，须退回逐图修正，不以通用房盒换皮通过。

验收阶段：

1. 读取ready-for-review.json，确认线程已停止改写本次候选并冻结交付。检查路径均位于对应组目录，哈希/大小/图号真实一致；缺失、歧义、仍改写一律待补。
2. 独立解码当前NBT：合法尺寸、注册/属性、显式空气、唯一坐标、实体载荷、容器状态；保存本验收目录源快照与精确SHA-256。核对配方、源和所有预览同一版本。
3. 逐张并排看实际参考和实际结构预览；必要时独立渲染。检查关键标志、功能、出入口、剖视仅显示不改源、房间间重复度；逐图记录观察而非批量凭文件存在判通过。
4. 独立原生静态注册、模板往返、canSurvive及碰撞路线；入口到每个重要目标/出口，特别上下层、窄门、箱前和角落。冻结检查亮度/工具限制明确标记，不升级为客户端世界刻认证。
5. 安全专项：水/熔岩完整围护、燃料距离、箱顶与功能物件、工作台兼容和动植物支撑。原生动态世界刻未测则列未测，不能以非空气邻接代替流体碰撞证明。
6. 新合并逐模块比较，所有修改坐标/属性/实体适配明确列出。独立重建连接图并核全节点可达；未用口、安全高差、门框补缝和外围联合屏障不能截断内部通路。不是照搬原第一轮固定坐标。
7. 完整源/分片逐格及实体载荷一致，无重叠缺失；数据包CRC/真实模板资源及共同原点检查。未做命令实际放置则保留限制，不擅自改世界测试。
8. 分别给出单房、组内合并、运行时安全和玩法范围的结论。至少独立单房与合并静态验收通过才登记当前源索引；对不支持项目不能用全组PASS掩盖。刷怪/精英/Boss/奖励不在本轮原建筑交付内，不因验收建筑而声称玩法完成。
