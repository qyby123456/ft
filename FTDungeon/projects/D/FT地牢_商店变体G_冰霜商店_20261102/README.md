# FT 地牢商店变体 G · 冰霜商店

本目录是只负责 G 的独立制作工程。最终状态以 `out/qa.json` 与 `qa/native.json` 为准。**不是已部署房间，不占用正式槽位，不直接修改统一接入工程。**

## 四件套与接口

- `out/room.nbt`：gzip 单调色板 Minecraft Java 1.20.1 / DataVersion 3465 模板，XYZ **17×10×15**，2550 个显式坐标记录（含空气），四周闭合，完整屋顶。
- `out/room.json`：暂定身份 `SHOP_G_FROST`、原图/结构完整 SHA-256、接口与设计适配记录。正式 ID 和槽位由统一接入负责人确定。
- `out/preview.png`：最终 NBT 回读后的实际方块材质剖视，1536×1200；不是设计图或游戏截图。
- `out/qa.json`：静态、原生、视觉、重建与范围边界的最终报告。
- 北入口脚位 `(8,1,0)`，安全内点 `(8,1,3)`；北侧开口 `X=7…9, Y=1…3, Z=0`，三格宽三格高，有完整地板，无门扇和突起阻挡。

## 冰霜主题与空间逻辑

- 冷灰石砖/石英砖、蓝冰、浮冰墙；原版没有“冰砖”方块，不伪造不存在的 ID。
- 独立冰柱落点 `(2,2)/(14,2)/(2,12)/(14,12)`（XZ），Y=1…8 直达完整屋顶；每根柱的八邻域全高保留一格空气，货架、冰锥、展柜和柜台均不碰柱。
- 深橡木柜台 X=5…11, Y=1, Z=9，所有四周与两端至少一格环通；空酿造台、蓝冰、晶体、无电路的金质测重板和花盆作陈列，无实际商品库存。
- 双侧 3×3 落地玻璃展柜：木底座、冰蓝玻璃壳、内部实体方块晶体与海晶灯、白色霜顶。内部展品不是掉落物或奖励；玻璃和晶体不穿插。
- 后墙木架下端落地、横板接墙，所有书与冰晶有顶面支撑。侧墙小架和蓝冰斧形浮雕有墙面支撑；桶为空，蓝冰堆连续落地。
- 两盏灵魂灯笼位于柜台上方 `(6,5,9)/(10,5,9)`，三节垂直锁链连续连接至 Y=9 的完整屋顶；不使用隐藏 light 方块。
- 7 组冰锥以天花板下蓝冰帽和冰蓝玻璃细柱表达，没有用会坠落的钟乳石伪装冰。完整屋顶在剖视图内被暂时隐藏，因此上部悬挂视觉以坐标和外壳图交叉检查。
- 冰洼是侧角地板内嵌蓝冰，没有水；入口、主路、柜台环路与四柱绕行点均为非滑冰实心地板。没有普通冰、霜冰、粉雪、火、真实液体、刷怪笼、命令方块、结构方块或拼图方块。

## 概念图适配（不可冒充一比一）

设计图：`reference/frost-shop-design.png`，原始文件路径和完整指纹位于 `reference/fingerprint.json`。原图为 AI 概念图 1536×1024，SHA-256 `defa7b24b65ee89ec5db3d7575826363f295da10b0b34a397c8a606888af2df1`。

为保证四根独立柱、墙角留空、真实双展柜和主通路，约 11×9 的概念比例扩大为 17×15。冻结药瓶、鱼盘、天平、无实体斧头等不是可直接放置的原版方块；采用空药水架、冰块、晶体、测重板、花盆和方块化蓝冰斧形浮雕代替。晶体使用原版紫水晶，带少量紫色，未制造蓝色自定义材质。没有真实商人、商品或交易行为。

- `qa/static.json`：20 项静态检测；从序列化 NBT 重新读取，完整封壳、四柱 256 格全高净空、主题结构互不穿插、支撑与空库存、入口/柜台环路/展柜/柱周可达。
- `qa/native.json`：独立 Forge **47.4.10 / Minecraft 1.20.1 / Java 17** GameTest。原生注册表、全部状态属性、方块实体类型、StructureTemplate 加载与回存、四个旋转放置、邻居通知、100 tick 稳定性、碰撞/支撑/空库存/雪的光照条件均校验。
- 四个方向共检查 10200 个放置后记录，每向做缺灯链与堵主路的真实反例探针；回采 90°/270° 方框为 15×10×17，0°/180° 为 17×10×15，逐坐标核对旋转后源状态。
- `qa/native-placed-*.nbt`：100 tick 后从隔离世界真实回采的四份 NBT；NONE 与源模板所有方块状态一致。
- `preview/four-views.png` / `preview/exterior.png` / `preview/plan.png` / `preview/native-world-capture.png`：四向剖视、完整屋顶、净空平面、原生世界回采数据的软件渲染。均不是实机截图。
- `qa/reproducibility.json`：重新构建后 NBT、room.json、blueprint.json、materials.json 字节级相同。
- `qa/package-verification.json`：交付包及四件套指纹；zip 回读核验。

第一轮原生 QA 的失败保留在 `qa/previous-*`：检验夹具沿用正方形模板的回采计数/边界断言，初步放置、支撑与通路通过，最后回采断言失败。随后修正为本房间长方形的旋转尺寸、完整计数和逐格对照。只改 QA 代码，房间 NBT 未因该问题变动。不把失败日志删掉或声称首轮成功。

第二轮新增积雪光照检查在放置完成的同一调用内执行，尚未等待异步光照引擎传播，得到过强光照的失败；将这项检查移到已有 100 tick 稳定期末。第三轮四向的真实稳定后光照均不超过 11、积雪未融化，全部通过；源模板始终保持相同 SHA-256。两次失败的日志与 JSON 均保留，报告中如实记录。

## 复现

本机 Python：`C:\Users\YOUR_USERNAME\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`，需要现有 Pillow。原版材质读取既有 Gradle 缓存 `client.jar`，不下载或新增材质包。

```powershell
$python = 'C:\Users\YOUR_USERNAME\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $python tools/build_room.py
& $python tools/qa_static.py
& $python tools/run_native.py
& $python tools/render_room.py
& $python tools/finalize_delivery.py
```

原生执行器只启动本目录 `qa/forge-run` 的无界面 GameTestServer，使用现有 Gradle 8.8、Java 17 和离线 Forge 缓存。`src/` 和 `build/` 里的验证 mod **绝不能部署到玩家整合包**。`tools/nbtio.py`、原版材质渲染底层和原生夹具模式复用自已完成的独立补给商店工程，已在本目录适配，不修改上游工具。
