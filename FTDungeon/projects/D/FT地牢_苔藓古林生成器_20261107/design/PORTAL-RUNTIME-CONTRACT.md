# Moss portal runtime contract (B)

Provider/mod/dimension: `ftmossgen:forest`, `@Mod("ftmossgen")`, commands `/moss`. SavedData is `ftmossgen_instances`, independent from Eclipse.

A owns `Plan.bossPortalPiece`, `Plan.bossPortal` (WORLD anchor, center bottom block, FT PART=1), `Plan.bossPortalFacing` (`Direction.from2DDataValue`); `plan.exit` is safe standing position immediately in front of this real gate. Select lowest main-layer graph-farthest room; no promenade proximity trigger. Keep `boss/eclipse_keeper` template key for runtime geometry unless this contract is explicitly updated.

Portal geometry: FT native 3 columns x 4 high, anchor center bottom, width along facing clockwise, all three supports full collision blocks. A reserves all twelve cells AIR and front/back three-wide, four-high clearance, plus standing support front/back. B includes the gate cells in Engine exact-cell AIR preflight/reservations before any writes. Boss return gate anchor local `[16,2,25]`, facing NORTH rotated with boss; preserve original 24 barrier cells until real-player victory. All portal parts and support/clearance must stay inside their owning piece. No terrain replacement or hidden teleport trigger.

B provides `public static boolean MossBossPortals.handleUse(ServerPlayer player, BlockPos anchor)` and `handleTravel(ServerPlayer player, BlockPos anchor)`: true means owned/consumed, including locked/failure. `public static boolean refreshControl(ServerLevel level, BlockPos anchor)` consumes native controller refresh for owned gates. Owned gate state is on the FT anchor BE persistent ForgeData (`ftmossgen.portal`) with instance, role, destination dimension/position and facing, backed by SavedData. Unknown/unbound gates return false; malformed owned gates fail closed. Runtime validates complete native geometry and authoritative COMPLETE job before travel. Outbound gate opens after initialization; return gate opens only after validated real-player Boss victory. Existing entry/leave origin tracking remains Engine/MossMod responsibility.

Host hooks (B does not modify FT core): in `DungeonGateBlock.use`, before shift/menu/torch logic, call handleUse and return SUCCESS when consumed; in `DungeonGateTravel.use` before generic generator/return routing call handleTravel and return when consumed; in `DungeonGateInteraction.refreshControl` before ordinary brazier controls call refreshControl and return when consumed. Add handleTravel at the TOP of `DungeonGateBlockEntity.tryTravel` before selector/automaticAllowed checks; handler itself checks OPEN, !MOVING and native passage intersection. Do not open generator selection UI for owned internal gates.

Gate initialization uses native registered FT entry/return blocks and BE bindGenerator; persist portal intent before placing parts, repeat missing owned parts idempotently after load, refuse foreign block/BE/metadata. All normal Engine checkpoints, 8192/tick block writes and restart cursor behavior retained. Coordinator performs integrated Gradle/server tests; B reports actual verification in ready-B.json.
