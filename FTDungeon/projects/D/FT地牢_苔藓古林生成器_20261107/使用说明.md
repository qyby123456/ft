# 苔藓古林生成器：接入与验证说明

本工程基于正式 0.24.2 副本并行实施，当前为开发验收工程，不代表可安装成品。不要将未验收 JAR 放进正式 mods，不要使用玩家存档测试。

苔藓古林预期接入 FT 地牢门的生成类型菜单，provider 为 `ftmossgen:forest`。原混沌、月蚀、紫晶三类型保留；使用新门选择新类型，已经绑定实例的门不得改类型或重抽种子。生成仍由门操作触发，不是自然世界区块生成。

预期流程：在地牢外搭好完整 12 格入口门并点亮旁边火盆，管理员或创造玩家选择苔藓古林、提交生成；待 COMPLETE 后普通玩家可进入。四层地牢最低主层通过实际门图距离选最远房放置 Boss 门；Boss 门服务当前实例，不应弹出入口选择菜单。击杀规则和返回以生产代码及原生测试日志为准。

## 本轮测试入口

- `src/mossTest/java/moss/generator/MossPlannerGameTests.java`：20 计划确定性、四层、独立端口图连通与原生碰撞块步距 BFS；从入口到各 eligible 非走廊门龛 trigger 的实际最短路径、最低层最远选择及冻结距离字段；无重叠、27 变体 SHA256 和苔藓材料、旧三 provider 加新 provider、旧月蚀 API 兼容。
- `src/mossTest/java/moss/generator/MossRuntimeGameTests.java`：真实异步 Engine 施工、完整 FT 门、三列支撑、双侧净空、原房非门材料严格保持；实际玩家点击不得打开选择菜单、实例与冷却、三个独立实例分别验证消失／非玩家致死／玩家击杀及正确返回。
- 空结构仅在 `src/mossTest/resources/data/ftmossgen/structures/empty.nbt`，注解使用 `template="empty"`，避免命名空间重复前缀。

宿主负责配置 `mossTest` sourceSet、Forge 测试命名空间和运行任务，再使用独立全新 workingDirectory 串行执行。C 不修改 build，不自行启动 Gradle。使用测试服务端并不代表获准访问或改写正式存档。

## 验收边界

A 的三个 Boss 门字段及距离字段、48×32 stride 与最终 27 变体已落盘；C 的磁盘检查确认 27 个 NBT SHA256 与当前 catalog 一致，11 个变体声明门龛。首轮原生通过与最终待验证范围见文末；不以文件检查代替原生验收。

Boss 门冻结坐标按 FT 原生底部中央 `PART=1` 解释，测试直接核对原生 anchor 与 BlockEntity，不按左下格补偿。B 的实际 API 中，点击只显示提示，完全开门后穿过门框才传送；测试通过原生 `entityInside` 验证这一流程及冷却、返回，不再把点击误当作传送。生产 provider 精确排除 test-only `ftgateintegration:isolated` 后仍要求四项。实际构建保留旧 gateTest 源码编译，因为旧 eclipse helper 引用了其中的类；原生本轮仅启用 `ftmossgen` 命名空间，不执行旧 gateTest 的过时断言。

保存/加载验证不等于进程断电、磁盘跨文件原子性验证。Boss 测试会在第一次完整施工后强加载测试实例并关闭生成敌人的 AI 以减少随机干扰；第一次施工没有测试强加载辅助。失败现场只属于隔离测试世界，下一轮应换目录。
