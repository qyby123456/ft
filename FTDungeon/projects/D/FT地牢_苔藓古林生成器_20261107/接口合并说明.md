# 苔藓古林接口合并说明

本目录是独立的 FT 0.25.0 苔藓古林候选工程，基于冻结的正式 0.24.2。后续其他线程已推进三生成器工程和正式安装；本候选不能直接覆盖那些新增修复。当前用户指令禁止部署与正式 saves、mods、config、KubeJS 改写，因此这里只交付隔离候选和证据。

## 接入点

新增 `ftmossgen` 内置模组命名空间，provider 和 dimension 均为 `ftmossgen:forest`。`MossDungeonGenerator` 通过原 `DungeonGenerator` 接口提供状态、规划、启动、进入、离开和维度所有权，菜单自动列举已注册 provider，不新增网络协议。既有三 provider 和月蚀注册 ID 保留。

新增 main Java 在 `moss/generator`，以及 `net/farmingtales/ftdungeonmobs/generator/MossDungeonGenerator.java`。新增资源在 `assets/ftmossgen` 与 `data/ftmossgen`。原 FT 核心只作五处修改：注册新 provider；`DungeonGateBlock.use`、`DungeonGateTravel.use`、`DungeonGateBlockEntity.tryTravel`、`DungeonGateInteraction.refreshControl` 优先交给内部 Boss 门桥接。桥接对不属于古林的未标记门返回 false，继续原逻辑。

后续合并到更高版本时，应复制新增命名空间和 provider，手工接入上述五处调用、模组元信息和维度资源。保留目标工程后续新增的重生、复用、IO 或菜单规则，不能用本候选完整旧类覆盖高版本同名类。合并后必须重新编译及重跑同一套隔离验收。

## 生成规则

保留参考 MineCells 四层递归的随机调用与分支规则；不额外加固定房间数上限。为容纳原始古林房体，世界网格横向间距为 48、楼层步距为 32，因此模板选择所用世界坐标和结果不会与原始 MineCells 或旧月蚀逐块一致。结构仍由服务器在存档内分批现场放置，不是预先导入整个固定地牢。

Catalog 含 27 结构变体，其中嵌入九份 S1 原房主体，并另建统一风格的连接廊、封口和门龛。原房来源、尺寸、哈希在 `design/templates-A.json`、`design/ready-A.json` 与 catalog 中记录。`design/build_forest.py` 是可重现的模板构造脚本。未使用付费图像生成。

最底主楼层不包括独立 Boss 场馆。在带门龛的非走廊房之间，以真实原生碰撞状态构建可行走方块图，从出生点做最短距离 BFS；先选最低 trigger 高度，再选距离最大者，并列按 piece index。计划冻结选择结果、各候选距离、图边和模板指纹。门采用 FT 原生三宽四高十二部分，底部中央 `PART=1` 为锚点，须保留完整地板与两侧净空。

进入门只通向本实例独立 Boss 房，内部点击不会弹出类型菜单。Boss 真玩家击杀胜利后才开该实例返程门，返回本地牢出生点；离开地牢维度可使用 `/moss leave`，恢复外部入场位置。怪物消失、非玩家致死不授予胜利或奖励。并行实例的状态、门和冷却相互隔离。

## 可重现检查

先设置 Java 17，由工程 `BUILD.ps1` 使用本机配置的运行时。所有运行目录均在本工程内，禁止指向玩家存档。

原生测试：`./BUILD.ps1 -Task runGameTestServer -Offline -GradleOptions @('-PmossOnly=true','-PgateTestMetadata=true','-PgateTestDirectory=moss-native-unique')`。每次使用全新测试目录；旧 gateTest 源码因 helper 引用仍参与编译，但只启用 `ftmossgen` 测试命名空间。

生产候选：`./BUILD.ps1 -Task jar -Offline -GradleOptions @('verifyDungeonGates','verifyDungeonRooms')`。生产构建不得带 `gateTestMetadata`，归档检查须确认没有测试类或测试模组。

归档比对：配置 Python 运行 `verification/verify_assembly.py build/libs/ft-dungeon-mobs-forge-1.20.1-0.25.0.jar`。冻结基线副本在 `verification/baseline`，哈希必须与 baseline.json 一致。活动的旧源工程已升级，不再用它充当基线；其差异只作漂移提示。

普通安装版验证：配置 Python（需 nbtlib）运行 `verification/installed_smoke.py`。它在本工程 verification 内新建三进程普通 Forge 服务端，验证四 provider 列举、暂停保存、重启恢复、完整生成、完工重启及真实门与持久元数据回读。首轮命令缺少区块加载等待的失败保留为 installed-result-r1.json；修正仅在测试脚本，未改候选 JAR。

## 验收边界

最终原生结果见 `verification/native-r2.log`；生产文件与旧版本保持情况见 `verification/assembly-result.json`；普通安装和跨进程结果见 `verification/installed-result.json`。应以结果文件中的精确 JAR 哈希对应证据，不把首轮或源代码自查当最终通过。

未做图形客户端实游、自然世界地形接入或断电/磁盘故障证明。测试玩家为原生 ServerPlayer 服务端夹具，没有真实客户端连接。已知基线石棺共面检查问题未在本轮修改；本轮执行指定任务，不声称完整 build/check 全套通过。Lodestone/实机截图尚未完成，design/template-contact-sheet.png 仅为方块色俯视示意。
