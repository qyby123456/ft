# 第三组：霜旗冰城·九域连通地牢

以第三组当前已验收的 01—09 九份真实房间源重新组装；不复制第 10 张总览，不修改冻结的原始文件。九个房间、八条新建连接通道，体积 **237×36×232**，完整源 **1,979,424 个显式格**。

## 布局与保留

南侧雪阶门庭进入霜旗双列长殿，再分三线：

- 北线：冰脊长廊 → 冰晶主厅。
- 西线：冻池休憩室 → 霜封骨藏小室；长殿另有灯角冰桥支路。
- 东线：雪杉冰池错层庭院 → 霜旗骨卫宝藏室。

入口低位脚底 Y4，通过原有雪阶抬升到主通路 Y10。各原模块只调整平移与底部高度，不旋转，不切掉内部楼梯、冰池、桥和上层庭院。主殿同一方向存在多个侧门，使用 north-axis、west-20、west-38 等真实门编号选择接口，不用“西门”一项覆盖另一扇门。入口宽 6 的非对称偏移 [-2,3] 原样保留。

新通道使用石砖、磨制安山岩地面、雪杉木顶、局部浮冰纹带和灯笼；内宽 7，接口按各原门洞收口。未使用的旧外门用石砖封闭，周边空隙补齐。只声明封口、补缝和开门状态变化，其余室内状态与方块实体负载逐格核对保留。

外围采用一层原版屏障，包住联合房间、走廊及入口平台，含侧墙、顶部和底部；不在内部连接上加屏障。共 71,020 格，不代表可限制旁观、传送或创造模式破坏。

- `frost-connected.nbt`：完整密集体积源，DataVersion 3465。空气会清除占位盒中的现有地形，不能直接覆盖正式建筑。
- `parts/`、`assembly.json`：25 片，各维 ≤48，共同原点、不独立旋转；逐格重组核对源状态和方块实体负载。
- `s3-connected-datapack.zip`：Java 1.20.1 数据包。装配函数为 `s3_connected:assemble`；必须先加载完整占位区，再在固定锚点调用，不应边走边逐片摆放。
- `layout.json`：源哈希、原点、门编号、路径、门框补缝及全部声明变化。

- `overview-complete.png`：完整实际源渲染；`overview-cutaway.png` 仅为显示剖视，原源保留屋顶和屏障。
