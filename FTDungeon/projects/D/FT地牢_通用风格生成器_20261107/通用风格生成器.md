# 通用风格生成器

这是独立工程的 0.26.0 候选版。没有部署到正式游戏实例，没有修改正式 saves、mods、config 或 KubeJS。

一个引擎读取风格数据，生成布局并现场放置方块。新增风格无需复制 Java 生成器，也无需重新烘焙一套相同房间 NBT。内置古林、砂岩太阳遗迹、冰霜档案馆。沙漠、冰霜同时改变材质与安全范围内的房间几何；装饰配方并非单纯改色。

## 直接制作新风格

1. 从 `src/main/resources/data/ftmossgen/styles/` 选择一种 JSON，复制到独立测试实例的 `config/ft-dungeon-styles/`，使用新的命名空间 ID，例如 `mydungeons:obsidian`。也可使用 `tools/style-author.py` 生成配置草稿，运行 `--help` 查看参数。
2. 修改名称、图标、材质映射、房间池权重、装饰几何和怪物/Boss 参数。图标是物品 ID；材质支持完整方块状态。配置目录只扫描顶层 `.json`，房间目录应放在 `assets/` 子目录。
3. 重启测试实例。风格自动注册到已有 FT 地牢门的生成器菜单。也可执行 `/moss styles`，再执行 `/moss generate mydungeons:obsidian 42`。生成任务沿用 `/moss status`、`/moss pause <实例>`、`/moss build <实例>`、`/moss enter <实例>`。
4. 验收完成后再决定部署。此工程没有自动部署功能，也不会主动写正式实例。

风格在启动时冻结。相同风格 ID 不允许重复；外部 JSON 不会静默覆盖内置风格。改变已有实例使用的配置/目录会使指纹不一致并拒绝续建，原存档不会被清空。迭代时使用新 ID 和独立测试存档；不能直接更换旧实例的材料来继续建造。

随交付提供 `output/水晶监狱设计输入.json` 与工具实际输出的 `output/风格配置示例/crystal_vault.json`。设计输入示例可用 `python tools/style-author.py --spec @output/水晶监狱设计输入.json --output 输出新路径.json` 直接转换。工具只做静态校验并拒绝覆盖；Minecraft 注册表、碰撞路线与真实战斗仍由游戏端检查。水晶示例未单独完成实机世界验收，不能当作第五种已验证实例。

## 数据接口

| 字段 | 用途 |
| --- | --- |
| schema | 当前为 1 |
| id / title / icon | 唯一风格 ID、菜单名称、物品图标 |
| catalog | 内置 `ftmossgen:catalog`，或 `file:assets/my-catalog.json` |
| palette | 来源方块 ID/完整状态 → 目标方块状态；精确状态优先，普通 ID 兜底；兼容的方向等属性继续保留 |
| pools | 按目录中相同池名覆盖加权列表，每项含 template、weight；权重 1–16 |
| decorations | 安全 AIR 位置内附着于现有结构的高处实体装饰配方 |
| capBlock / barrierBlock | 未连接端口封墙和 Boss 封锁材质，必须是完整实心、无方块实体和流体 |
| melee / ranged / bossType | 已注册且可创建的 Mob 类型；Boss 需要生命和攻击属性 |
| bossName / bossHealth / bossDamage | Boss 名称、生命和攻击数值 |
| roomCooldownTicks / instanceCap | 房间冷却 tick（20 tick/秒）与实例怪物上限 |

装饰示例：

```json
{"block":"minecraft:quartz_pillar[axis=x]","mode":"air","role":"room","from":[8,9,8],"to":[39,21,39],"spacing":6}
```

坐标在旋转前模板内部；from/to 含边界。spacing 为 Z 方向间距，X 连续，Y 从高至低处理。仅在原本 AIR、下方保有净空且能附着在实体结构处添加完整实心块。原墙面、楼板、方块实体、门洞、楼梯、符印支撑、出生与传送门保护区不被配方覆盖。role 支持 room、turn、terminal、promenade、boss、rooms、all 和 `prefix:terminal/` 等明确前缀；普通走廊、楼梯、出生及外围景观不参与这类高处装饰。区域必须落在匹配模板范围内，Boss 模板比主房间小，宜分别写配方。

这套配方适合顶部肋拱、冰晶、垂饰等安全增量。完全不同的房间造型可通过自定义目录接入；引擎不会从一个名称自动推导任意建筑，也不会凭空保证任意自定义模板的连通性。

## 接入已有房间或新房间

目录格式见 `src/main/resources/data/ftmossgen/catalog.json`：variants 定义房间尺寸、最低导入高度、端口、刷怪 sockets、传送门候选位置与 NBT SHA-256，pools 定义选择权重。可将目录放入配置目录的 assets 子目录，在风格中指定 `file:assets/my-catalog.json`。目录中的单个模板可用 resource 指定 `file:assets/rooms/example.nbt`；未指定时继续使用原有内置 NBT。

外部路径必须留在风格配置目录内，禁止绝对路径、越界及符号链接逃逸。目录/模板必须与当前网格契约兼容：四层递归布局、48 格水平单元、32 格层高，逻辑模板键、旋转、原生门洞/端口、独立 Boss 模板、符印安全地面和完整致密 NBT。单纯改尺寸或目录键不等于新的拓扑算法；需要另一类布局时仍应接入独立生成策略。

模板必须为 Minecraft 1.20.1 DataVersion 3465、单 palette、无结构 entities、无重复或缺失格点。房间原有方块实体保留；材质替换不能新增方块实体、改变原有方块实体类型、覆盖 AIR 或引入流体。先验证最终碰撞与端口可达性，再现场建造。未知材质、坏目录、未知风格不会退回古林或写入半套实例。

## 保留的游戏逻辑

布局沿用参考细胞式递归生成，房间数量由随机拓扑决定。预制房间通过原生端口和统一连接规则衔接；最终几何通过原版碰撞计算检查。最底层可达主房间中，按实际步行路径选择离出生点最远的房间，放置 FT 传送门进入独立 Boss 房。

符印使用安全支撑点，不替换房间原砖。房间敌人、Boss 与召唤物按风格参数创建，商店仍使用已有 FT 商人。返程解锁仍要求本实例匹配 Boss 被真实玩家击败；非玩家死亡不能解锁。实例按风格、种子、目录和配置指纹冻结，建造日志支持暂停、重启恢复，完成后释放生成用的区块票据。

## 验证边界

原生测试位于 `src/styleTest/`，与旧测试隔离；正式 JAR 不含测试类或第四风格夹具。执行 `BUILD.ps1 -Task runGameTestServer -Offline -GradleOptions @('-PstyleOnly=true','-PgateTestDirectory=独立目录名')`，使用新的测试目录避免复用旧世界。

`verification/style_installed_smoke.py` 在正式 JAR 生成以后才写入第四种黑曜石风格和外部目录，在独立服务器中验证自动发现、生成、暂停、重启续建和 FT 门回读。它不会写正式实例。最终结果见 verification 中的日志及交付清单；静态检查与真实服务器证据分别标注。

当前候选继承先前隔离古林工程的基线，并未合并另一线程之后的 0.24.3/0.24.4 变更；不能按版本号直接覆盖当前正式安装。旧 0.25 古林实例的目录指纹与此版本不同，尚无迁移器；混沌/月蚀等既有资源的保留由打包对比单独验证。
