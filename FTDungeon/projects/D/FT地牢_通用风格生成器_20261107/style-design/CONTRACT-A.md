# Shared style geometry

`StyleGeometry.process(Profiles.Style, Catalog.Template, List<Catalog.Cell>)` runs after the host's palette mapping, before Planner collision analysis and Engine placement. It uses only the agreed Profiles.Decoration fields. No extra fields, NBT copies, duplicated Java runtime, provider registration or deployment are required.

The shipped forest profile returns the original cell objects and order because its decorations are empty; there is no style-ID bypass. Users can add forest recipes using the same processing rules as other styles. Its shipped palette is also empty. New profiles use the existing ftmossgen:catalog; empty pools mean inherit catalog pools, never zero room choices.

Desert uses sandstone masonry and chiseled horizontal hanging bands with a sparse gold ceiling treatment in the promenade. Frost uses quartz ribs and denser blue/packed ice hanging bands. JSON controls role, local inclusive from/to box, solid block and spacing. Only air mode is supported. Spacing selects local Z rib planes starting at from[2]; X is continuous within the box, Y descends from to[1]. Existing full blocks above or to a horizontal side anchor each new cell; previously attached additions extend the same rib. This produces actual additional non-air geometry, not only palette substitution. Floating candidates are skipped.

Eligible roles: room = straight/room_*, turn = turn/*, terminal = terminal/*, promenade, boss = boss/*. The literal all means all these eligible roles. Ordinary corridors, stairs, spawn, scenery and standalone child layout templates are excluded. Current JSON bounds fit the frozen 48x30 rooms and 34x23x28 Boss; a custom catalog with smaller bounds must supply matching decorations and fails closed otherwise.

Additional selectors use the same role field: rooms selects all eligible non-Boss rooms (room, turn, terminal, promenade); prefix:terminal/ selects eligible keys starting with terminal/. Prefix selection is literal, case-sensitive, nonempty and limited to lowercase template-key characters. Prefix and all never opt excluded corridor/stair/spawn/scenery templates into decoration. Unknown selectors fail closed when processing eligible templates. No additional Profiles fields are needed.

Every addition must replace an explicit AIR cell with no NBT. Existing cells, block entities, fluids and their state/NBT payloads are retained. Decoration block strings are parsed by Profiles.state, including full property syntax such as minecraft:quartz_pillar[axis=x]. Full solid, fluid-free, non-BE materials only. Each addition requires three AIR blocks below. Native collision-derived preexisting walking feet/head/overhead cells are protected, along with explicit ports, sockets, spawn points, portal/trigger and Boss runtime spaces. This retains existing walk routes and keeps decorations above the walking layer. The Planner must run its final native collision BFS after this transformation.

Host integration requirements: empty pools inherit; palette mapping must retain compatible existing properties (e.g. log axis -> quartz pillar axis), and discard incompatible properties when replacing block type; never overwrite NBT blocks with arbitrary palette entries. Persist style identifier plus profile/content fingerprint with the frozen plan. This worker does not edit host-owned Profiles/Catalog/Planner/Engine/Store.

Validation distinction: local verification checks JSON contract, bounds, hashes and a conservative static geometry simulation. Native collision outcomes, actual final geometry deltas, route reachability, three provider lifecycle behavior and game-world tests are coordinator/C responsibilities. No deployment or player world writes are authorized.
